# 共工文档设计单元

偃师以独立 Agent 身份接入，登记标识 yanshi，入口为 agents/yanshi/AGENT.md。共工负责委托、权限、调度和跨模块协同，元衡控制体系管理其全部实例。需求澄清 skill 和兼容 CLI 都是偃师使用的能力，不替代其独立身份。

输入包括 feature 标识、目标与范围、真实授权、相关项目契约、原始资料和有效配置。输出包括需求简报、术语与决定、蓝本和调研、候选方向、策划稿、玩法和技术设计、确认记录、生产工单及证据引用。未知项保持可见，输出不自动成为已批准基线。

按 agents/yanshi/references/workflow.md 保留用户确认顺序；按需调用需求澄清能力。已有需求充分时直接整理，存在关键分歧时先查事实，再逐个询问决策并给建议。完成条件是相关需求、条款、验收和交接可追踪；功能整体完成还需适用实际生产、验证和复盘。

共工为每实例分配一个 feature 和唯一主要负责人。其他独立 Agent 通过委托和账本协作；偃师不获得修改共享规则、扩大权限或独立批准自身设计的权力。外发、派生和执行沿用真实授权。

定义接入以 reviews/yanshi-admission.json 为记录；接入许可只覆盖当前版本的本地框架定义，不覆盖任意业务生产。宿主必须核验有效通行证与权限后实例化；当前包未注册常驻服务。更新候选内容后重新核对指纹与准入，不更改冻结纲领。
