版本：0.2。性质：专项规范草案。加载条件：变更场景对象、共享资产或派生资源时。

按需参考依赖：specs/concurrency.md。仅加载与当前职责有关的部分；不要求每个执行任务读取全部依赖。

## 3D 场景与共享资产耦合协同

场景使用稳定对象 ID、明确实例与源资产关系，并按区域、对象、专业层和共享资源组织编辑范围。空间分区只解决部分冲突，跨区导航、光照和共享资产仍需检查。

| 操作 | 默认协作策略 | 合入后检查 |
| --- | --- | --- |
| 不同独立对象的属性修改 | 乐观并行，检查共同约束 | 碰撞、可见性及局部规则 |
| 同一对象同一属性修改 | 判定冲突，不静默覆盖 | 由负责人选择或重做 |
| 同一对象不同属性修改 | 根据规则尝试合并 | 属性间约束及实际表现 |
| 删除、重挂父节点或改层级 | 对受影响子树加强隔离 | 变换、引用、触发与脚本路径 |
| 修改预制体或共享源资源 | 与实例修改建立依赖协调 | 所有受影响实例及覆盖规则 |
| 地形、导航或全局光照变化 | 在对应影响域集成和重建 | 跨区连通、烘焙有效性及预算 |
| 二进制 DCC 源文件修改 | 独占编辑或生成独立变体 | 导入结果和资源替换范围 |

场景变更以语义操作记录目标 ID、基准版本、属性旧值与新值、坐标空间及预期结果。父变换改变时，子对象的位置修改可能冲突；不能仅因写入属性不同就合并。删除对象与更新其引用也属于冲突。

修改单个实例、修改预制体源、修改共享材质和替换资源版本必须有不同操作入口与授权范围。系统展示影响实例清单；超出原委托范围时升级相应范围决策。

锁只用于必要的非合并操作，采用租约、超时和失效凭证。普通生成任务不长期占住整个场景；先生成候选，短时完成集成。无法结构化合并的内容采用显式归属、分区或串行编辑，不能默认可用文本工具解决。

派生资源记录输入哈希和构建配置。导航、光照、LOD 等输入变化后，相应结果标为过期并重建，过期证据不继续显示有效。验证既检查局部区域，也检查受影响的跨区路径和全局预算。

例：任务 A 移门，任务 B 布置敌人，任务 C 烘焙导航。三者可在各自候选中工作，但门位置影响通行，敌人位置影响遭遇；最终导航必须基于已集成布局重建。旧布局的烘焙成功不能作为最终场景验收证据。
