# 共工回查与准入审查

仅适用于 Agent／skill 定义生成及其准入，包括新建、更新生成新版本和外部定义接入；不适用于每个普通需求。生成定义前回查冻结纲领、锁文件及共享元衡核心与模板，选择当前职责规范；同对象相同有效指纹可复用。定义提交、启用或合入前重验产物与基线，变更只重验受影响部分。

普通需求调用已有 Agent／skill、修复业务代码、设计内容或生产资产，不单独创建共工／元衡审查报告或通行证，沿原业务验证、验收及交付流程执行。混合需求只审查其中生成的 Agent／skill 定义，不将审查扩大到整张工单。宿主对已安装框架的完整性、既有准入和实际权限核验仍有效，这类环境核验不要求普通需求新建准入批准。

审查覆盖模块边界、治理链、真实授权、输入输出、依赖兼容、质量证据、恢复和职责分离。元衡评价逐项引用事实：实际目的与可修正理解；证据和未知；复用与整体收益；权责和独立性；适应范围与效果；承诺连续性。缺证为未知，文件格式通过不能替代行为或权限验证。

skill 和 Agent 入口只保留职责、触发、关键判断、必要约束和按需引用；移除通识、重复规则、固定编制及无效流程。记录长度和删改理由，不以任意字数代替判断，不把字符节省称作 token 节省。代表任务验证流程可执行，实际效果另行观察。

外部 Agent／skill 定义候选先隔离，检查入口、工具、派生、数据和状态行为，在同一审查记录中分别形成共工审查与元衡评价结论。在受限范围验证适用代表任务、失败恢复和接口；修复问题后重验受影响项。不能只接受候选自述，不把作者自评冒充独立审查。保留上游原件和来源，禁止覆盖纲领或绕过纳管。

共工审查与元衡六项评价是同一 Agent／skill 定义候选的不同判断维度，不是两轮串行全量审查。同一实际评价者具备相应委托且满足所需独立性时，可一次审查、共用证据并分别记录结论；需要不同专业或独立责任时按检查项分工，共用同一候选记录。独立性按真实身份、授权和参与行为判断，不能仅换角色名，也不能让作者自批；实际批准仍由有权负责人作出。

谛听的记录／分析不构成审查关卡；夸父仅在质量事件升级时介入，其处置复核不构成普遍前置审批。普通任务由原责任链完成适用检查与授权验收，不串行经过谛听、夸父、元衡各自重复测试或签发同一结论。治理评价引用原质量证据，仅对授权、治理边界和独立性等未覆盖项补充判断。证据缺失、矛盾、失效或独立性不足时定向补验，不能以去重为由接受未知。

使用 templates/review-pass.json 记录任务、事件与阶段、对象版本和完整文件指纹、纲领与规则基线、许可范围、框架审查、元衡六项、精简、验证、证据、评价者及独立性、未决项和真实批准。状态分为通过、需修改、拒绝、待验证；实际有权人员或被真实委托的治理 Agent 批准，自评不是批准。

入口通行证用于执行范围，交付通行证用于发布、启用或合入；同一任务不为每个原子动作重复审批。待审稿和隔离候选不是已启用能力。基线、对象版本、权限或范围改变后复核并更新批准；过期、撤销、被替代、未知或模板均无效。检查通过也不授予操作权限。

局部不满足只阻断受影响操作，继续无关清晰授权工作。通行证只批准其绑定对象；Agent 定义接入不批准未来 feature、游戏构建或运行工具。当前文件流程不等于部署了宿主自动拦截或独立审批服务。

组件创建、变更与合入同时核验谛听上报配置、组件／共享依赖指纹及必需事件。采用 tools/create-component.py 或等价契约；生产启用需实际宿主绑定和代表任务回执，按 specs/reporting.md 核验。
