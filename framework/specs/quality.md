# 共工过程与结果质量规范

版本：0.2。性质：专项规范草案。加载条件：配置或执行适用质量验证时。

按需参考依赖：specs/project-state.md。仅加载与当前职责有关的部分；不要求每个执行任务读取全部依赖。

## 过程质量与结果质量

过程质量检查生产方法是否受控，结果质量检查交付是否满足规格。两者均关联任务与版本，避免只在最后发现问题。

| 检查位置 | 检查内容 | 处理方式 |
| --- | --- | --- |
| 任务进入 | 输入、目标、假设、依赖、权限和预算 | 信息不足标记，阻止不满足前置条件的执行 |
| 生产过程中 | 来源、参数、版本、实际写入、消费与异常 | 记录履历，隔离越界或失效任务 |
| 产物提交 | 格式、引用、源文件、规格与基础运行 | 通过后进入集成候选 |
| 集成后 | 关联代码、资产、场景、性能和业务回归 | 绑定候选版本，失败回到对应责任人 |
| Feature 验收 | 目标达成、体验、剩余问题和承诺 | 由规则指定的验证者或负责人确认 |
| 交付构建 | 平台、资源完整性、构建和交付清单 | 对具体构建形成验收记录 |

判断区分硬性条件、评估信号和创作判断。无法启动、必然卡死、资源缺失等可以阻止交付；风格相似度、穿插检测和构图评分作为证据；乐趣、魅力和节奏结合设计负责人和目标玩家判断。AI 试玩验证部分行为，不能替代全部体验判断。

过程采用共享质量框架，具体门槛按客户、资产类型和任务风险配置。低影响可逆修改不强制全项目测试；公共接口或共享资源变化要扩大范围。独立审查只在适用规则要求时启用，但不能被生产者自行取消。

异常豁免由有权负责人记录原因、影响、有效期和后续责任，状态仍显示为带条件接受，不改写为无缺陷通过。上游规格或依赖变化后，已有验收按影响范围失效或待复核。

## 统一质量职责与领域配置

夸父作为既有质量体系内的阻塞处置及跨业务事件监察与协调单元，职责以 specs/quality-responsibilities.md 为准；既有 G0 至 G4、证据、缺陷和例外配置统一保存在 domains/quality/quality-policy.json。普通业务自检、指定验证和授权验收保留原责任归属，夸父不另设检查、批准或状态体系。记录模板由同一领域目录维护，跨角色引用同一证据。
