# 数据与反馈模块

谛听 diting 为独立数据 Agent，当前版本以 framework-manifest.json 及 agents/diting/agent.json 为准，五项 skill 按需加载。采集对象含授权外部反馈和需求执行事件，以实际 Agent／版本快照及关联工作分类。每个需求记录发起时间、对话消息／轮次、方向错误／纠正、质量问题／返工、步骤与 token／等价用量；缺失明确标注，不能补零。

入口 agents/diting/AGENT.md；记录契约 references/data-contract.md，采集及统计口径 references/telemetry.md，边界 references/optimization.md，接入与迁移 references/storage.md，均相对 Agent 目录。

共工和元衡内容只保留 reference。必须用户另行明确指令才进入原治理变更流程，谛听无框架和元衡修改权，冻结纲领不变。其他子 Agent 的优化候选按既有授权与审查执行，数据不产生权限。只有跨 Agent／关联通讯才可能涉及框架，不因一般反馈自动升级。

客户配置复用来源、权威数据服务、Agent 清单、分类、权限与保留策略。宿主按租户及来源分区，事务成功再确认游标，失败入待处理队列，重试幂等。源端账单／事件计数与落库结果对账；记录采集完整度，不承诺无数据丢失的虚假完整。

谛听拥有记录与分析，偃师拥有设计，业务方默认负责实现，验证者拥有质量结论，夸父负责阻塞分析、优先处置与升级监察，宿主拥有身份和状态。夸父直接修复按 quality-responsibilities.md 记录已有授权与唯一执行主责交接，并保留独立验证。问题／返工只引用原质量主记录，不建第二套质量关卡。

本地 SQLite 验证可用，企业连接器、身份隔离、删除／保留、备份恢复和容量仍需部署验收。主键、外键、字段约束、结构化索引、版本化标签、证据溯源及可重算统计是交付要求；“永远可用”落实为受权限和保留政策约束的可追溯性及恢复验证，不以文档承诺无限留存。
