# 共工交付与版本核验

适用：合入版本库、发布产物、交付可运行内容，以及影响已登记消费者的共享依赖变更。复用共工／元衡准入、原工单、源账本及谛听；不新增 Agent、审批层或周期任务。任务进入时加载本规范，其他任务不必加载。

## 在执行前明确交付对象

把用户目标落实为本次工单的验收条件：交付源码、可构建源码、可运行包还是已配置服务；列出必要的引擎、业务内容、运行时、安装／启动入口和模型验收范围。省略项及其原因写入需求文档，不用“完整”“全部完成”代替清单。新增用户要求更新范围版本和受影响验收条件，不将范围扩展倒算为此前缺陷。

源码与可运行资产进入任务选定的版本／交付来源；Git 接入才要求对应仓库提交或发布资产。其他来源须提供不可变版本、内容摘要及获取回执，不伪造 Git 字段。本机安装成功不表示接收方已经取得产物。产物清单记录相对路径及解析基准、摘要、分发位置及获取方式。模型未配置时可以继续无关工作；模拟验收与真实服务验收分别声明，仅用户明确修订范围才能改变承诺。

## 固定依赖，限定变更影响

开始执行前记录实际使用的来源版本、受影响文件摘要、接口与准入状态；这是本次候选依赖，不自动追随另一个聊天正在修改的主线。已批准发布与待审候选分别存放和引用；共享来源变更先在隔离候选完成审查，再切换发布入口。修改已登记消费者依赖时，记录 source.changed 事件及消费者、兼容结论和恢复点；司南在事件处理中更新阻塞与文档，不通过定时扫描发现漂移。

执行或合入前发现依赖摘要变化，应列明差异与受影响项，继续无关工作。不得自动改锁定值、重写旧批准或无限重建追逐最新来源。纯路径迁移同样先核对准入影响，不能把下游仍可运行当作未受影响的证据。

## 并行实现与同一候选验证

独立实现、来源核对和必要审查可并发，读写冲突及公共接口按现有并发规范处理。同一远程分支的发布由一个实际协调者串行执行，独立实现不等于多个聊天可以同时替换主分支；发布前核对期望父提交，出现变化进入重基／合并，不覆盖他人结果。

验证必须针对待交付候选：绑定来源、不可变候选版本、使用的依赖摘要、实际构建产物摘要和测试报告；Git 接入映射为仓库与 commit／tree。外部目录的编译成果只有在输入与候选版本对应关系已验证时才可作为证据；否则从候选重新验证。可运行交付覆盖从交付内容安装、启动和代表业务链路，并核对运行依赖；仅存在补丁包、面板文件或脚本不算接入完成。

保留一套当前候选证据。必要独立审查按边界并行，后续只复核新增差异及受影响链路；基线变化、失败或未决风险才扩大验证，不反复全量重读规则与重跑相同测试。缺陷修复留下失败、修复和验证关联，不把未知或用户接受风险记为测试通过。

## 发布后以事件完成对账

发布前通过选定来源的交付检查核对清单及证据。当前 `tools/check_delivery.py` 与 `templates/delivery.json` 是 Git 交付适配，具体字段见工具帮助；其他来源需提供相应检查与回读，不要求虚构仓库。它只校验本地对象与提供的证据一致性，不代替实际测试、远端读取、用户批准或宿主身份认证。发布完成后取得对应来源的版本／资产回读证据，触发 release.completed；没有回执时只记录已实际完成的本地步骤及发布待确认。

由司南在同次事件处理里刷新当前工单、相关上级／依赖工单、需求文档与交付视图。子项通过只使父项进入重新判断，不自动关闭父工单。外部 Issue 通过其权威连接器更新并回读；未执行、失败或需要权限的同步列为待处理，不能将本地文档变更当作远端已关闭。

采集的 configured、queued、delivered、consumed 分别保留证据：配置存在、持久排队、接收方回执和消费方确认不可互相替代。目录或索引存在不表示已消费；来源变化、落库或消费事件同步更新相关视图。缺失用量保持未知，不用零或估计数冒充实测。任何补偿与重试由真实事件或用户请求触发，不恢复时间调用。

最终交付明确已完成、待处理与适用范围，引用同一候选、测试和发布证据；状态同步失败时说明具体缺口，不重新运行整个生产流程。
