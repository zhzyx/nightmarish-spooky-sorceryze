# 司南｜共工统一工单管理规范

司南协调各类任务、跨业务依赖与交接。角色入口为 agents/sinan/AGENT.md。本规范定义权威来源、派工与同步的共同约束。

司南覆盖所有业务任务类型，包括独立事务；类型可扩展，开发类仅是其中一部分。Feature、代码与设计版本按业务适用，完成条件依据任务成果与真实委托确定。既有账本保留唯一工单事实。总协调管理来源登记、全局身份、协调关系和派工候选，不维护竞争的执行状态。全局身份为账本稳定 ID 与工单 ID 的组合；共享任务只建一次，流程 plan 不默认充当 Feature。

总协调处理跨项目依赖、优先安排、阻塞责任与交接；相应业务主责负责整体成果，偃师按适用职责负责设计交付，夸父负责阻塞、重复停滞及升级质量事件的分析和优先处置，验证者和交付负责人保留其原有判断权。新增职责按实际委托分配，不因此新增固定 Agent。

派工前检查硬依赖、源版本和证据有效性；环、缺失依赖及失效证据阻止受影响正向推进，无关分支继续。退回修复不应因前置质量失效而被阻断。优先级与计划不授予权限，委托记录不等于实际执行，子项完成不等于整体目标达成。

宿主选择具备所需能力的来源与过程适配器，能力声明见 skills/work-order-coordination/runtime-ref.json。写入、派发与验收须由获得授权的责任方执行，并重新检查跨来源约束。未登记或无法读取的来源保留覆盖缺口。

详细对象、生命周期、用户呈现及适配边界按需见工具模块中的《工单管理体系》。迁移时更新真实绑定，不把业务设计文档变成全部 Agent 的默认提示词。

司南标签分为类型、源进度、判断与业务分类：Bug 与处理中可并存；源进度自动派生，协调标签可维护且保留变更记录。待判断须列明责任人、事项及是否阻塞；普通判断留在授权主责，阻塞、重复停滞、关键问题及跨业务质量交夸父，用户保留取舍才提交用户。标签不能替代元衡判断或改变源验收。类型补标、标签筛选和本地协调记录写入按需查工具说明，不增加默认 Skill 指令。

## 事件触发与同步

### 新需求进入工单

宿主收到实际新需求时，保留原始诉求、来源事件 ID、宿主核验的工作者／执行实例、授权范围与稳定需求标识。先在适用的权威来源按稳定标识和目标查重：同一需求的澄清、范围变更与重试关联原工单并保留版本；只有独立交付目标才新建工单。需求整理可提出标题、类型、范围、验收和待判断项，但提案不是权威工单，Agent 判断也不授予写入权限。

若确认新需求且来源写入已获授权，由宿主调用该来源的原入口创建工单，回读稳定工单 ID、版本及实际状态，再提交 `request.created` 给司南刷新和协调。创建回执不明时先按需求标识对账，禁止盲目重建；来源不可用或权限不足时保存待关联记录、责任人、证据、可继续工作和恢复事件，仅挂起依赖该工单的执行。未取得权威工单回读前，不把提案、文档或聊天快照记为已建单，也不启动要求工单绑定的生产执行。

由来源适配器依据稳定需求标识查重、关联并回读工单。只读咨询按已选来源契约登记；咨询转为执行时重新核验工单及授权。

司南作为核心通用协调 Agent 保持按需可用。触发来自实际新需求、工单进度变化、依赖变化、用户或有权主体决策、执行完成／失败回执以及用户主动查询。时间流逝不构成触发：废止定时扫描、轮询、heartbeat、cron、延时唤醒和按时间重试。历史归档中的此类入口不可沿用。

事件由当前宿主或实际接入方在同一次工作中交给司南；没有全局事件监听器，不声称自动捕获其他聊天或外部系统。登记来源的执行者提交状态变化时必须同步交接司南；漏报在后续真实事件或用户主动对账时处理，不用定时兜底。

处理顺序：核对真实事件来源、工单全局 ID、当前源版本与权限；需要改变源状态时先通过已授权来源接口 持久化并取得回执，禁止根据消息直接覆盖源账本。随后读取最新来源，更新标签、进度文档、依赖／阻塞、责任人和下一步。任务专属文档只更新本次受影响且获授权的部分，保留来源引用与验收证据。候选、提交、完成执行、验收通过分别记录，文档是源状态的视图，不另建状态账本。

每次刷新核实触发事件、权威来源及修订，再更新许可范围内的派生视图。实际派发和来源写入需要单独回执。

任务就绪且已经授权时，先登记认领，再取得执行者接收回执。回执未知时对账。按实际执行容量、审查独立性与读写冲突约束安排独立任务。完成、失败、依赖解除等事件触发补位。

实际业务调用仍必须按 reporting.json 接入共享谛听，事件与真实源／执行快照关联，同一事件不重复计量；文档更新记录不能冒充谛听落库回执。采集失败保留待处理事实，在后续实际事件或用户请求时重试；未接通的数据源或用量保持未知。

## 关联文档与完成事件

交付核验及版本／采集状态依据 specs/delivery.md。scope.changed、release.completed、source.changed、report.delivered 同样触发一次刷新：范围变化更新验收约定，发布完成对账交付状态，上游变化列出受影响依赖，采集回执到达更新相应证据。来源事件不是新的任意任务授权。

文档适配器声明路径基准、可写范围、工单关联及受托更新区。保护用户正文、源账本和其他工作者内容，回读写入版本和失败项。

刷新从权威来源派生状态、标签、责任、依赖、阻塞、验收与下一步。分别记录已同步和待同步的文档、来源缺口、待办及写入失败。部分成功按实际结果报告，后续真实事件可重放修复。

父工单按权威来源核验验收与关闭。子项完成触发父项重新判断。负责外部工单与标签的连接器须回读已授权变更，未完成同步保留在待处理结果中。

需求和交付文档引用来源与修订，派生状态遵循文档适配器的更新协议。历史判断保留来源版本和时点；范围或批准变化时核对正文承诺，修正过时说明。采集索引逐来源维护配置、排队、交付与消费状态。

## 局部挂起与持续推进

对话缺信息、待判断、待决策、工具失败、采集/同步失败都不能使整个框架停止协调。每次真实事件先分离受影响操作与可继续工作；记录原意、证据、影响范围、责任方、下一步和恢复事件，在适用的本地权威来源查重并关联工单。需要外部工单的任务按已选择的适配器关联来源。独立交付才拆子单，同一问题沿用原单；父项尚有执行工作时保持处理中，局部待决策用问题记录表达。适用外部来源不可用时先持久保存待同步记录，后续真实事件补写并回读，不伪造 Issue 编号或重复派发。

普通判断由已有授权主责处理；技术问题交业务 Agent，阻塞、重复停滞、关键问题及跨业务质量交夸父，司南负责协调与回收。用户保留的决定异步提交，负责人继续准备事实、备选方案和其他任务，不能把沉默当批准。未认领问题由当前宿主协调者负责；登记 owner/proposed 不等于 Agent 已执行，真实 start/ack 才算派发。没有可用授权实例时保留适用的待派发工单并释放执行槽，不能无限等待或创建未经准入 Agent。

`pending_user` 仅表示待用户决定，不自动排除就绪或撤销验收。确实依赖该决定的操作须显式设置 `pending_user_blocking: true`；`assessment.blocking: true` 同样只限制该工单正向推进，仍生成问题处理候选。不得为绕过权限把真实限制改为 false；应拆分已授权调查、修复和独立交付。硬依赖、无效证据、源 blocked、授权/预算/数据边界与冲突锁只限制关联操作，不能以继续推进为由宣称通过或重复执行不明回执。

宿主交接后续动作时提供稳定问题键、来源工单、责任、恢复条件与验收。待处理项由责任方回读、派发和核验；来源仍为状态权威。

单项文档同步失败记录对应工单、诊断与实际结果，继续其他安全操作。越界、权限不足、目标冲突或来源不明时保留原件，按真实恢复事件重验。
