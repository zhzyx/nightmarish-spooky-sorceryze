# 共工质量职责与夸父接入规范

共同治理唯一来源为元衡与冻结纲领。specs/quality.md 是共工质量主规范；domains/quality/quality-policy.json 保存既有质量制度的领域配置，模板只表达记录。夸父是该体系内的阻塞处置与质量事件监察 Agent，不另建一套质量管理制度。原工作区的制度和已安装 skill 保留来源身份，不作为当前框架第二个权威入口。

## 单一职责归属

| 职责 | 唯一责任职能 | 其他参与者的边界 |
| --- | --- | --- |
| 公共规则和质量政策采纳 | 有权治理职能 | 夸父可提出有证据的改进建议，不自行发布新规则 |
| 授权数据采集、统计、归因假设与优化依据 | 谛听 | 引用已有质量结论，不签测试、事件关闭或交付批准；数据异常先回原责任链 |
| 设计条款、标准映射、Feature 交接 | Feature 主责，含偃师 | 不代替独立验证或最终验收 |
| 局部自检和修复 | 对应业务执行者 | 夸父不重复审批普通自修；阻塞修复可按下述委托由夸父承担执行角色 |
| 指定检查和集成回归结论 | 该检查的质量验证者 | 夸父读取结论，缺口退回原责任链，不另签测试结论 |
| 专业与体验验收 | 指定专业验收者 | 不由夸父用评分替代 |
| 阻塞与升级质量事件分析、优先处置、闭环跟踪 | 夸父 | 可在已有授权内直接清障或修复，不代签独立验证或交付验收 |
| 风险接受、承诺变更、最终交付批准 | 实际有权负责人 | 夸父只在有效委托内选处置方案，保留用户决定 |
| 身份、状态提交、版本和规则拦截 | 共工宿主 | 所有 Agent 只能在授权内提出或执行操作 |

每个具体责任槽只有一个主责。协作、咨询和共享证据不产生第二个主责。要求独立审查时核对真实身份、执行来源和参与行为；夸父可承担已授权阻塞的修复者，但参与修复或事件决策的实例不能兼任该事件的最终独立验证者。需要调整职责时先更新真实委托，不能用总管控名称吞并其他角色。

## 阻塞介入、优先处置与 bug 跟踪

开发执行受阻、用户明确报告阻塞、单个问题重复处理却没有新增证据或可验证进展，以及影响关键依赖、质量或交付的关键问题，均在当前事件内触发夸父介入，不以跨业务、等待次数或固定时限为前提。用户报告即登记，是否复现和根因确认另记；普通无阻塞自修不自动升级。

夸父拥有阻塞处置的优先协调权，并在当前宿主已授予的工具、数据和变更范围内自主调查、清障或直接修复，无需为同一已授权动作重复确认。直接接手时记录该次修复的唯一执行主责、原主责交接、影响范围、验证和恢复方式；实际夸父实例承担 business_executor 执行角色，不改变普通修复的默认归属。优先权不产生额外系统权限，不绕过元衡、准入、独立验证或用户保留的取舍；仅挂起缺权限的相关动作，继续其余工作，不代操作其他工作副本。

第一时间（同次触发事件、深入排查和修复完成之前）记录来源、时间、原任务、影响、现象、已尝试操作与结果、证据与未知、主责、授权边界、下一动作及解除阻塞验收条件，并通过已授权权威来源查重、创建或关联 bug 工单。同一阻塞复用原单并追加尝试与证据；已关闭问题复发时核对关闭依据，按权限重开或建立关联复发单。原父任务若不是 bug，保留其类别，另建关联 bug；阻塞类 Issue 统一为 bug，不能混成多个类别。

建单失败、权限不足或回执不明时保留可恢复的待关联记录、稳定标识、责任人、错误和下一恢复事件；先对账再重试，不能声称已创建或盲目重复建单。不得等待登记恢复而停止无关已授权工作；要求真实工单绑定的生产执行仍遵循宿主入口门禁。紧急止损若已在授权内，可与最小记录同步执行，随后同次事件补齐工单关联。

夸父汇总事实与假设、复现条件、既有尝试为何无效、权限/依赖/技术根因及影响，给出有验证目标的下一步；无新增证据时停止同法重复操作并调整方案。司南协调优先级、依赖与交接，谛听提供事实和重复轨迹，业务主责提供技术上下文，偃师处理需求及验收歧义，合契处理变更冲突；按需协作，不新增固定编制或竞争账本。

处置后请求原责任链定向复验；复用有效检查，区分临时绕行、根因修复和仍存风险。阻塞解除须有对应验收证据，由权威来源有权责任人更新状态；未解决时明确主责、下一动作和恢复事件。子 bug 关闭不自动关闭或验收父任务。跟进仅由进度、依赖、决策、失败/完成或用户请求等真实事件触发，不设置定时扫描。

## 检查与证据去重

检查按目标清单版本、标准 ID、方法与配置、环境、依赖快照和规则版本识别。相同检查条件只分配一个检查 ID 和主责；既有证据有效时，业务、Feature、谛听、夸父及治理评价均引用该记录，不为满足各自流程复制检查或重新跑全套测试。仅生成 Agent／skill 定义时需要共工审查与元衡评价，其合并记录与真实独立性遵循 specs/governance-review.md；普通质量任务不增加治理审查关卡。

谛听提供跨 Agent 关联、覆盖缺口与反例；夸父复用这些数据判断升级事件的业务影响和处置，不重做采集统计。数据相关性不直接成为质量裁决。普通无阻塞局部问题交业务主责；开发或用户报告阻塞、重复停滞、关键问题、已升级的跨业务影响、责任冲突或原链未处置问题交夸父，沿同一事件／缺陷 ID 跟踪。没有上述触发事件不例行调用夸父；没有数据分析需要不等待谛听另写审查报告。元衡治理不接管这两项业务产物，必要独立验证仍由指定验证者负责。

影响范围、版本、环境或规则变化，或证据矛盾、遗漏和独立性不足时，向原责任检查创建关联重验，记录原因及新版本；保留有效且不受影响的检查。重验不是第二套职责。夸父监察证据链、跨业务冲突和未处置问题，不重新实施已有例行检查。多个上报关联同一事件和缺陷，保留来源而不新建竞争账本。

## 关卡和批准唯一性

沿用既有 G0 至 G4，不增设夸父平行关卡。检查者签发具体检查结论，交付负责人作授权验收，宿主写入唯一状态。夸父的事件处置记录不能覆盖失败、未知、已失效结论，也不能把风险接受改成测试通过。事件关闭仅说明关联处置已复核，不代表 Feature 或交付已经验收。

偃师已有的方向、策划稿和设计定版确认继续有效，质量侧引用对应版本，不重复请求同一批准。共工 Agent 接入通行证与业务质量关卡针对不同对象：前者批准 Agent 定义接入，后者判断具体产物；任一都不能替代另一个。

## 统一入口与迁移

Agent 入口为 agents/kuafu/AGENT.md，方法为 skills/kuafu/SKILL.md，制度字段与记录模板位于 domains/quality。依赖全部相对当前框架解析，不再依赖另一个工作区的已安装 skill。原质量制度的检查、证据、缺陷、例外、风险档及 G0 至 G4 已迁入单一配置；原通用判断步骤移除，直接引用元衡与共工治理。历史来源通过 provenance.json 追溯。

本版交付规则、定义和文件级职责检查；真实项目的检查注册、去重调度、身份隔离和状态拦截仍需宿主实现。定义接入不代表已启动生产实例。

文件级计划校验使用 tools/check_quality_ownership.py。execute 项的 responsibility 区分 local_self_check_and_repair 与 check_and_regression_verdict（默认），分别绑定业务执行者与指定验证者；reference 项只引用现有检查。执行计划有既有检查时需提供 existing_checks 的完整身份字段，仅提供 ID 不足以判断重复。必要重验使用新 check_id、supersedes_check_id 和明确 revalidation_reason，沿用原责任链且保留旧结果；缺少关联或理由的同条件执行仍拒绝。该工具不验证真实身份、证据有效性或授权。
