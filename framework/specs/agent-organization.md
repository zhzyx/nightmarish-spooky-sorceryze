# 共工 Agent 动态组织规范

版本：0.2。性质：专项规范草案。加载条件：分配职责、调整分工或沉淀方法时。

按需参考依赖：GOVERNANCE.md。仅加载与当前职责有关的部分；不要求每个执行任务读取全部依赖。

## Agent 动态组织与生命周期

创建、修改或接入 Agent 时执行 specs/governance-review.md，记录共工框架审查、元衡标准评价与精简结果。已有有效能力优先复用；候选未通过不得作为共工生产 Agent 启用。外部候选先隔离评估，不能凭自身合规声明获得准入。

所有 Agent 及其派生实例必须始终受元衡控制体系管理，无角色、客户或部署例外。动态组织只改变分工，不改变治理根。创建、外部接入和恢复时由宿主核验登记、有效授权链、策略版本和冻结纲领基线；核验失败不得派发执行或接受结果。治理和审查 Agent 同样适用，不能自行声明豁免。退出或撤销后，凭证与结果提交资格一并失效。

组织遵循“先检查现有能力与在途工作，再决定直接执行、复用还是组建临时职能”。增加 Agent 需有专业化、并行收益或独立审查的具体理由。

任务委托至少定义结果、负责人、输入、权限、预算、依赖、读写范围、交接对象、完成条件、截止策略和异常处理。委托由宿主验证；子委托权限不得超过父委托。专业 Agent 可以提出扩展建议，不能自行获得工具、资金或更高权限。

生命周期为：识别缺口、检查复用、形成委托、实例化或分配执行者、执行与检查点、提交证据、验收交接、释放资源与复盘。被取消或失效的实例不能继续提交有效变更；其租约和提交资格由宿主撤销。

治理按企业、项目、Feature 和任务范围分配，权限来自实际委托。公共标准由有权治理职能决定，局部执行者不能自行改写通信制度、验收规则或共享接口。普通授权内工作自主推进；存在目标争议、费用或权限缺口时，只升级相应问题，其余独立任务继续。

动态调整的触发条件包括：任务类型改变、实际瓶颈、反复失败、依赖失效或独立审查要求。调整可以拆分、合并、替换或撤销职能。是否保留一种方法，应比较有效交付、返工、成本和协作负担，记录作用范围与可恢复版本。
