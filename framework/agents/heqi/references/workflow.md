# 通用协作与司南契约

路径以框架根为基准；任务文件以宿主明确绑定的 workspace_root 为基准，不跨工作者目录。合契与司南是共工核心 Agent，Git、Godot 等用户接入子模块提供工具与来源，不定义或替代这两个 Agent 的职责。

## 责任与输入

司南维护来源关联、目标、依赖、责任、派发交接与验收对账。合契承担当前授权工作副本中的多方差异比较、技术冲突解决、整合候选与证据。业务主责负责目标和成果验收，独立审查者保留评价权；配置不产生执行权限。

每次委托绑定 worker_ref、identity_receipt、execution_id、change_id、work_ref、workspace_root、read_paths、write_paths、authority_ref、预算、交接对象和验收条件。work_ref 指适用权威来源及稳定任务身份，可是本地工单。版本采用 source_revision 或内容摘要；base_ref、各 contribution_ref、target_ref 声明 available/unknown，未知不得冒充已验证基准。来源无法提供版本时，只开展可核验部分并登记补证。

接入契约须明确身份核验、来源读取、版本比较、候选保存、发布及接收回读。工具权限和任务权限分别核验。

## 生命周期

1. 读取实际任务、来源版本和既有贡献，记录当前工作副本的未保存内容与读写范围。每份贡献分别标识工作者、执行实例、变更集、来源版本及验收，不把同任务的不同贡献去重掉。
2. 比较声明范围与实际变化，识别重叠、改名、删除、二进制与语义依赖。能安全并行的工作继续；不可合并范围由有权主责协调单写者，未经确认不声称排他锁。
3. 按 concurrent-changes.md 在获授权的独立候选中整合。候选必须保留共同基准、输入快照及恢复方式，不覆盖其他工作者或当前未保存成果。没有共同基准时标记比较限制，不伪造三方结果。
4. 核对每份贡献和组合验收，记录纳入、延后或拒绝项及有权依据。技术冲突在授权内解决；目标、权限或验收取舍未定时只暂停相应操作。
5. 交接前回读目标版本，发生漂移则保留原候选并增量比较、重验。以适用接入保存或交付成果，分别记录保存回执、目标接收和验收；没有发布能力时提供可审阅候选，不能声称已提交到来源。

## 协调与采集

协调事件记录 event_id、worker_ref、execution_id、change_id、work_ref、版本、文件/对象范围、阶段、decision_owner 与 evidence_refs。使用来源支持的追加或版本保护；不覆盖别人的说明。回执不明先对账，不重复执行副作用。已有源账本保持权威，派生视图不另建完成状态。

实际事件通过共享谛听记录；配置、持久保存、落库与消费分别确认。没有事件时不轮询、不延时唤醒。工单和交接可在本地完成；只有接入要求才增加外部 Issue。
