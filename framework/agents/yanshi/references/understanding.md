# 偃师需求理解方法

以当前阶段足够可靠的共同理解为目标，逐步减少用户需要补充的信息、重复解释和无效步骤。每次收敛仍须满足元衡的目的、循证、整体收益、权责、适应范围及承诺连续性要求。

先查对话、现有设计、关联能力及实现证据，复用有效决定。区分原话、解释、未知和真实权限。资料已足够时直接整理；事实能查则先查，普通可逆选择在委托内决定。只有答案会改变当前目标体验、范围、验收、可行性或授权，且无法从现有证据解决时才询问。

按决策依赖处理最早的阻断点，每轮一个关键问题，给出建议和取舍，等待答案后再推进依赖决定；无关调研可继续。根据任务复杂度展开分支，不使用固定问卷、问题数量或置信分数。歧义术语只记录当前项目的必要含义；重要取舍才补充决策理由。

例如“闪避更爽”需要先查现有规则与反馈，再判断响应、表现或战术价值哪个问题仍未明确。建议必须有依据；没有输入延迟证据时不能声称已发现延迟，也不能自动加入反击机制。

停止条件是本阶段的目标与范围、相关关键约束和可观察的验收方向已足够清楚，改变关键选择的分歧已解决，且具备该阶段所需权限。非阻断未知保留来源、影响和后续验证方式，不为穷尽所有可能持续追问。方向阶段只需足以比较和确认方向，具体参数可在已授权的详细设计阶段解决。

每轮只复述新增理解、发生变化的假设和剩余关键决定，引用已有简报与确认；小幅修订不重开整轮访谈。简报按需保留原话来源、具体情境、目标验收、范围约束、有效决定与未知，不制造空章节或要求用户重复填写。

保留原流程的方向、策划稿和设计定版确认。停止澄清不等于获得确认，沉默不等于批准；用户纠正后只更新受影响解释、决定与依赖，保留历史。

在多轮实践中检查哪些问题实际改变决定、哪些步骤造成重复，以及理解偏差、遗漏和返工是否减少。有证据表明不再改变判断的步骤才合并或删除，方法保持项目与任务适用范围；出现遗漏则恢复必要追问。少问或入口更短本身不能证明优化，不凭一次反馈改写全局方法或冻结纲领。
