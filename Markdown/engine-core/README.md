# EngineCore 模块

本模块是引擎核心架构与迁移边界的顶层入口，承载核心公共契约、对象与资源语义、宿主适配及独立演进规则。

当前不预建空子模块。新增规范优先并入本文件对应章节；形成独立加载边界后再拆分，避免核心架构被拆成大量只有少量规则的目录。

## 架构边界

- 共工持有的意图、实体身份、资产来源、任务、依赖和证据保持引擎无关；适配器负责映射到具体引擎对象。
- 中间表示只覆盖经过真实流程验证的共同语义，同时允许显式声明引擎专属能力。
- 每项引擎能力声明版本、支持范围和失败语义；不支持时明确返回差异，不静默丢弃数据。
- 场景、资源、组件、动画和物理迁移不仅验证格式，还必须验证可比较的实际行为。
- 新核心不得通过改名、包装、传递包含或链接输入重新绑定 Godot 实现；具体检查由 Engine Next 构建契约承担。
- 独立 Cook 的图像解码声明支持的格式与布局，共用结构、校验和、解压及尺寸边界；跨平台路径用精确像素和派生包字节复验，完整成功后才发布输出。逻辑像素字节上限与分配器扩容造成的进程峰值分开记录。
- 独立 Executor 宿主使用显式模块入口与 Provider factory，不通过编辑器的聚合 factory 加载无关可选服务。干净源码导出需从隔离 Python 入口实测本地复制与实际原生桥，分别验证标准库依赖、资产字节、身份、恢复和失败语义。

## 独立可视运行时的帧状态

需求是让几何、纹理、光照与诊断在同一显式帧图内组合，保留 M3 原始身份，并使取消、异步完成和资源退休具有可验证的语义。GPU Cook 的格式、压缩和页面布局属于渲染派生物，不改变原资产包语义。

- 准备、资源发布、状态提交及队列提交由明确的 owner 串行控制。并行命令录制只读取稳定帧快照，使用各自的 allocator/list；allocator 和被引用资源必须等所属提交 fence 退休后才能复用。
- 射线场景的材质表绑定源资产顺序。粒子等光栅专用条目保留独立边界，窗口 resize 等资源重建仍使用相同的源材质序列，不能把派生条目并入射线身份。
- 已退休反馈和本帧提交分开确认。反馈转存后保留至成功提交，Prepare 失败或取消不能吞掉反馈；没有新反馈时沿用最后已提交需求，明确的空覆盖反馈则替换旧需求。
- 纹理流送按实际资源、IO、上传和退休版本分别计预算，保留可用的粗 mip。安装新材质内容时同步更新各帧描述符、二次射线消费者及相关时域和 MASK 阴影缓存。
- 帧级统计归属实际退休的帧槽，普通报告和完整流共用字段序列化。CPU QPC、GPU timestamp、Present API 返回和显示扫描分别标明范围；软件观测不冒称物理显示延迟。
- 原生渲染、backbuffer 和窗口呈现尺寸分别记录；空间放大输出不计作原生分辨率验收。诊断视图标明真实资源及数据图集的含义，不以统计代理冒称不存在的场景数据。

具体实现和验收溯源见 [M4 设计](../../design-docs/engine-next-visual-runtime-m4-20261115.md) 与 [全程测量设计](../../design-docs/engine-next-visual-runtime-m4-6-telemetry-20261118.md)。构建证据仍遵循现有构建契约，最终质量和持续性能单独验收。
