# 马良骨骼生成、蒙皮与角色发布

本细则是 Agent 将人物 Mesh 生成骨架、蒙皮并发布可追溯角色版本的执行约定。实现边界与参数细节以[人物标准化、自动绑骨与蒙皮设计](../../design-docs/ainative-art/05-rigging.md)及 [SkinTokens 本地自动绑骨管线](../../tools/ainative/SKINTOKENS.md)为准；其中的开发记录和历史数值只作为证据，不替代当前任务验收。若任务还包括生成源 Mesh，先按[生成图、mesh流程](生成图、mesh流程.md)完成对应阶段。

## 1. 路线与适用边界

- **标准人物 `standard`**：适用于 Y-up、+Z 朝前、近似直立对称、双臂展开的 T 参考姿态、双腿分离且头和四肢具有独立可见区域的人物。使用解剖模板拟合，初始骨架为 17 个解剖骨加独立 root；这是一套独立实现的模板、截面和距离权重方法，不得称为通用 AI 自动绑骨。
- **自由 Mesh `free`／人工标记 `marked`**：必须提供全部 17 个解剖关键点，root 可选覆盖。`marked` 表示人工标注源模型的真实姿态，可用于 A 姿等输入，不得宣称源模型已被转换成 T 姿。
- **SkinTokens 本地自动绑定**：属于独立配置的实验路线，使用本地开源模型生成骨架和蒙皮，不使用云端服务、Blender 或 Python ML 环境。其输出默认是 `quality=learned_auto_rig_not_reviewed`，必须经过骨骼与变形预览审核；该路线没有模板路线的内置 ROM 检查动画，动画接入与变形验收需在 Godot 动画系统中另行完成。

普通非人物 Mesh 不套用人物契约。模板路线不支持任意怪物、额外肢体、手指或脸部骨；学习式路线也不能超出训练分布和质量证据宣称普遍适用。所有路线均不得覆盖原 GLB，清理、拟合和绑定结果必须另存为新产物。

## 2. 标准执行闭环

1. **固定输入身份**：记录源 GLB 和 SHA-256，确认当前操作针对该源文件；生成或导入成功本身不代表可以绑骨。需要改身高、头身比、臂长、腿长或胖瘦时，先使用 `human_shape_adjust` 在静态 Mesh 上完成体态调整。常规流程只填五项参数，由 AINative 自动渲染、估计姿态与 15 个关键点、写入源哈希并做网格校验，无需手工 landmarks 或额外确认；低置信度或几何不匹配必须停止。最终骨架和蒙皮不得先于该形变生成。
2. **执行人物头脸门禁**：标准、自由和 SkinTokens 人物路线都必须先检查绑定源文件的 `asset.extras.maliang_head_review`，确认完整嘴／下巴、头颈衔接及 `head_front`、`head_three_quarter`、`head_side` 三个近景结论。换头衍生模型还需 `maliang_head_landmarks`，下巴和颈根必须绑定对应头／身源 SHA-256，且颈根低于下巴。缺记录、来源变化、任一视图失败或头颈接缝不通过时，拒绝进入绑骨。体态调整会使旧记录失效，必须在调整后模型上重新完成本门禁。
3. **选择路线并设置参数**：按输入人物和姿态选择 `standard`、`free` 或 SkinTokens；设置米制目标身高、显式源 Y 裁底阈值及可选重复／退化面清理。SkinTokens 还需本机有效配置、CLI 和权重，缺失时明确失败，不静默切换其他路线。
4. **拟合并检查清理预览**：重新显示派生模型及保留／移除面数、开放边和非流形边。清理只删除选定面，不自动补洞，不得宣称修复全部拓扑；坏拓扑诊断和警告必须保留。
5. **检查姿态、骨点和朝向**：先 Fit 得到预览，再检查骨架、关键点和实际姿态。标准路线自动朝向只校正明显的水平臂展轴，不推断人体前后；非零手动 yaw 优先。自由路线先载入实际拟合标记再修正，未完整标记或未检查确认时只允许诊断与预览，拒绝发布。
6. **生成并检查蒙皮**：使用最终派生几何计算或校验权重，逐顶点骨索引必须有效，权重有限、非负、归一且至多四个。关节和人工权重修正绑定源 SHA-256、裁切、清理、身高、朝向和算法版本；任一输入变化后不得把旧修正或旧权重静默套用到新几何，改变清理后必须清空权重、重新拟合并重新标记。
7. **执行实际变形检查**：模板路线播放 `raise_arms`、`squat`、`turn` 并恢复 Rest，检查真实 CPU Skin 顶点变形、关节活动、足底接触和明显穿插，不能只确认动画或骨头存在。SkinTokens 路线在 Godot 中另行加载并播放验收动画，不得把静态绑定姿势写成 ROM 已通过。
8. **发布并重载验证**：通过 Save new character version 原子发布新 `.tscn`，拒绝覆盖已有目标；随后用 Reopen version + corrections 重载 Skeleton3D、Skin、AnimationPlayer 和修正参数，核对源身份及静止／变形结果。预览、暂存或保存成功都不能替代重载检查。

## 3. 结果声明与失败边界

- 角色清单中的来源绑定必须指向真实源文件和版本；当前角色仅声明 `semantic_mapped`，不得据此宣称已是 `SkeletonProfileHumanoid` 或已兼容 UE／Mixamo。
- 开放边、非流形边、未修复拓扑或人工标记依赖必须如实保留；能保存角色不代表几何、蒙皮和动画质量全部通过。
- Fit 失败不得提交新参数；配置、权重、源哈希、骨点或权重校验失败时停止当前步骤，不自动重试、不改写源文件、不回退到未授权路线。
- 合成单元测试和脚本契约检查只证明适配器行为。最终业务通过必须看到真实人物派生版本、实际变形与 ROM／动画检查、有效权重、发布回执和重载证据；不得以合成立方体、静态 GLB 或“未报错”替代真实角色验收。
- SkinTokens 的构建、权重下载、配置、命令和独立回退步骤直接遵循 [SkinTokens 管线说明](../../tools/ainative/SKINTOKENS.md)；未完成真实推理和变形验收时，必须明确保留该状态。
