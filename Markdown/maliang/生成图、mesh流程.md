# 马良图像、Mesh 生成与视觉审核

本细则是 Agent 处理马良图像／网格生成、视觉 review、原模型增量修复和实际运行包验收的执行约定。实现契约与参数细节以 [AINative 工具说明](../../tools/ainative/README.md) 为准；单次日志、调试脚本和历史验收记录只作为证据，不替代本细则。

网格通过本细则的视觉验收后，如需继续生成骨架、蒙皮和角色版本，按[生成骨骼流程](生成骨骼流程.md)执行；视觉几何就绪不等同于骨骼或动画验收通过。

## 1. 标准生成与修复闭环

1. 逐张理解全部原始参考图，识别真实视角、主体、结构、比例、材质和预期细节；文件名、标签和数组顺序不是视觉证据。
2. 生成第一版 GLB。GLB 返回成功只代表生成阶段完成，不代表资产通过验收。
3. 对当前 GLB 渲染规定的全身、细节和头部视图，再进行视觉 review。渲染证据必须绑定当前模型 SHA。
4. Review 完全通过后，才发布当前 GLB 并结束流程。
5. Review 不通过时，先区分证据问题和模型问题，再进入对应分支：
   - 相机朝向、视图标签或必备证据缺失：在同一 GLB 上校正渲染并重新 review，不调用模型修复，不消耗一次生成。
   - 材质、颜色、外观和表面细节问题：以上一版 GLB 为源执行 `model_adjust`，保留父模型哈希和修复意见，再次渲染、review。
   - 已有明确、经确认且受支持的局部几何参数：执行对应局部几何修复，保留源模型，使旧 review 失效，并重新渲染全部视图、重新 review。
   - 需要显式调整人形身高、头身比、臂长、腿长或胖瘦：在最终绑骨前使用 `human_shape_adjust`。常规流程只提供五项参数，由 AINative 自动渲染和估计 T／A 姿态及 15 个源绑定 landmarks，再执行解剖与网格距离校验；不设置手工 landmarks 或额外人工确认步骤。低置信度、正面不明或几何不匹配不得变形，输出必须重新进入完整视觉审核。
   - 缺肢体、主体错误、整体比例错误、真实缺脸或其他当前能力无法继续修复的阻断级结构问题：停止修复 loop，保留最后已审核模型，按“能力受限、带未解决问题”成功交付并弹窗提示；不得伪装成完整 review 通过，也不得偷偷降级为文字全量重生成。
6. 每次修复后的模型都回到第 3 步，形成“当前模型 → review → 原模型增量修复 → 再 review”的闭环。

不得为了提高通过率而跳过 review、伪造 `passed=true`，或在仍可增量修复时提前按能力受限交付。完全审核通过与能力受限交付是两种不同的成功结果；后者必须明确保留 `visual_review_passed=false` 和未解决问题。网络、无效 GLB、渲染失败及其他非能力边界错误仍按失败处理。

### 独立衣服正背面图片门禁

- 提示词只负责引导，不作为视角正确的证据。正面必须是正对、左右肩部与袖管呈现一致的全正面，斜侧面不得标为正面；背面必须展示旋转 180° 后的真实背部，不得复制、镜像或换标签冒充背面。
- 背面默认只展示平整袖子外侧，不得出现袖口开口、内衬、翻折袖口或突出的宽袖口边；背面默认是连续闭合的套头式结构，不得出现纵向开口、门襟、拉链、纽扣、系带或分开的前片。后腰和腰带保持平顺并隐藏闭合结构，不得复制正面的带扣、结饰、卡扣或大型装饰。只有用户明确要求背面采用这些特殊结构时才例外。
- 背面设计以大面积平面衣片和明确横向元素为主，至少检查横向肩育克、横向腰带或横向衣片接缝；横向结构应压过纵向中轴装饰，不得把正面的长纵向构图直接复制到背面。
- Kimi Work 图片路线在发布独立衣服正背面图片集合前，必须将实际返回图片一起送入视觉审核，分别检查袖口外观、闭合背面、平顺后腰和横向背部布局，四项均为硬门禁；同时检查标签方向、同一件衣服和无人体／模特。任何一项失败都不得通过，整体 `passed=true` 不能抵消单项失败。审核结论必须绑定每张输出图片 SHA-256。
- 视角不符、设计不一致、审核不可用、超时或回执无效时，父任务失败且不发布看似成功的图片集合；子任务生成结果和审核证据保留，不自动重试或静默降级为未审核成功。

## 2. Review 证据与通过规则

### 必备视图与动态计划

每次任务先理解全部输入图和用户命令，生成 `review_plan`。完整审核至少需要：

- 三维产物的基础证据：`front`、`right`、`back`、`left`、`top`；
- 由输入参考和用户目标决定的细节证据，例如头部、手部、盔甲区域或普通物体细节；
- 只有计划明确要求完整头部验收时，才需要 `head_front`、`head_three_quarter`、`head_side` 并启用头部门禁，不得仅因主体是人类就默认追加。

输入对照只使用真实存在的参考方向和细节；输入没有俯视图不妨碍从当前 GLB 渲染俯视证据。细节区域和机位必须属于渲染器已经实现的能力，计划、渲染回执、Review 提示和报告校验必须绑定同一份计划及当前模型 SHA。

视图必须展示其标签声明的真实方向。发现错位时先修正证据，不得把侧面或后脑勺当成正面审核依据，也不得直接据此断言模型缺少真实几何结构。

### 总体通过条件

只有同时满足以下条件才允许 `passed=true`：

- `subject_match=true`；
- `proportions_pass=true`；
- `details_pass=true`；
- 每个必备视图都存在、无重复，且对应比较通过；
- 计划要求时的完整头部门禁通过；
- `issues` 为空。

仅有 GLB、外观大致相似或部分视图通过，都不足以发布。

### 人类／类人头部门禁

仅当当前 `review_plan` 明确启用头部门禁时，三个头部视图共同确认：

- 嘴、下巴和下面部完整，没有横向裁切穿过面部；
- 头部连接完整颈部并进入衣领，没有明显缝隙或面具式接缝；
- 身份可辨认，但不要求与参考图做 1:1 摄影测量复制；
- 面部特征位置与比例正常；
- 可见眼睛、嘴、下颌和颈部没有明显阻碍后续变形的几何问题。

这里的动画判断仅是几何就绪性检查，不代表已经验证骨架、蒙皮权重或实际动画播放。

### 明确允许的容差

- 顶视图只需方向和整体布局一致；适度俯仰角差异及被遮挡的细节不单独构成失败。
- 面部要求可辨认身份和正常比例，不要求逐像素复刻。
- 真正的缺失解剖结构、矛盾布局、错误主体和明显变形阻断不因上述容差而放行。

## 3. 失败分类与恢复边界

- **证据／协议问题**：缺必备视图、重复视图、相机方向错误、响应不完整。优先在同一模型、同一渲染或已保存响应上恢复；报告缺项时只补审缺失视图，再将互补证据合并为完整报告，冲突结论不得选择性取通过。
- **外观问题**：只把可处理的外观反馈送入 `model_adjust`；局部几何诉求不得伪装成材质修复。
- **延期几何问题**：无法由当前受支持操作安全处理时，不得宣称已经修复；若没有可独立处理的外观问题，停止修复并按能力受限结果交付。
- **阻断几何问题**：使用结构化字段和明确缺陷判断。整体比例由 `proportions_pass` 等字段把关，不得仅因自由文本出现 `proportion` 等通用词就覆盖已通过的结构化结论。确认无法继续修复时，保留最后模型并弹窗提示未解决问题。
- **视觉/API 不确定**：停止并保留证据，不盲目重试、不猜测通过，也不得按能力受限成功交付。

完全通过的 review 使用正常成功交付，并可附带头部／动画几何就绪标记。能力受限结果也允许作为成功任务交付最后一版 GLB，但必须携带 `capability_limited=true`、`visual_review_passed=false`、完整 review 和未解决问题，工作台必须弹窗一次；不得附加完整头部审核通过标记。任何恢复操作都不得改变原 GLB 几何来伪造证据一致性。

能力受限弹窗的标题、按钮、正文、状态和问题摘要必须全部使用中文，不直接展示英文 review 原文或内部字段名。原始英文审核意见只作为证据完整保留在任务记录和生成物元数据中；界面按问题类型给出中文摘要，并明确提示审核未完全通过，不宣称已经完整验收。

## 4. 节点产物缓存与重跑

- 自动完整衣服重建以静态或已绑骨角色 GLB 为输入，先识别独立衣服清单，再逐视角取得可见表面遮罩；本地用同机位双 12 位三角面 ID 图确定源面归属，并在同一遮罩内按可见面深度和朝向补回高密度网格的漏采样三角面，不得以连通体泛洪代替表面证据；基础衣服的遮罩必须包含附属刺绣和装饰。随后去除人体并重建内侧厚度和边界。只有 `complete_visible` 且位置焊接后封闭的项才可标为 `wearable_shell`；局部覆盖、归属冲突、缺视角或封闭失败保持未解决，不得把碎片加厚冒充完整衣服。已绑骨输入保留原骨架、Inverse Bind、关节索引和蒙皮权重，新增内侧与封口顶点继承蒙皮，并逐文件校验；视觉、目标骨架适配、动画与碰撞仍是后续独立验收。
- 完整衣服生成后必须执行五视角质量门禁：使用同机位的源模型／拆出衣服图像对，逐件检查漏面、破洞、碎片及人体、头发、手部、鞋靴等误选。门禁回执绑定源模型和集合 SHA；任一视角缺陷都保持 `visual_review_passed=false` 并写入未解决清单，不得以正面正常或 GLB 生成成功抵消背面、侧面和俯视缺陷。失败后最多执行一次通用遮罩回修并再次门禁：缺面合并合法轮廓，误选替换对应轮廓；拒绝候选、回修次数和历史必须保留，第二次失败继续按能力受限交付，不得无限重试。
- 开发者显式衣服清单仍走源表面提取：本地盘点源 GLB，AI 只能选择有图像证据的组件，再交给本地提取器；普通界面不要求用户填写 `component_id` 或审核三角面。候选渲染有数量上限，不能宣称覆盖所有小型或融合衣服；没有证据绑定结果时应失败并保留源模型，不得猜测三角面。该路径产物必须标为表面片段，不是完整换装衣服。
- 节点“运行并预览”始终重新执行当前节点；上游已有有效结果快照时，直接把快照作为只读产物输入，不再重跑上游。当前节点还必须绕过执行器的同参数调用缓存，避免仅返回旧回执。
- 全局“运行”只调度没有结果缓存或缓存已失效的节点；所有节点均命中时直接完成，不创建后台进程。其他分支失败不妨碍已经成功节点保存结果，后续运行继续使用这些成功产物。
- 缓存复用绑定节点定义及全部传递依赖的指纹，输入文件按内容 SHA256 参与计算。参数、源文件、连接或任一上游失效时，下游缓存一并失效，不得把旧产物当作新输入。节点位置等纯展示信息不参与失效。
- 图片、Mesh 与有序图片队列均从不可变字节快照重建执行输入；重建前校验内容摘要，队列必须保留成员顺序、标签和索引。缺文件或校验失败时回退为正常执行，不伪造成功结果。
- 旧工作流没有指纹时，在打开并恢复产物的当次绑定当前定义；之后的编辑仍须正常失效。清理界面历史不删除原始输入或已发布文件。
- “全部重跑”必须先弹出中文确认，明确告知会清空所有现有缓存结果；取消不得清空或启动任务。确认后清空所有节点结果历史，并绕过全部节点的调用缓存重新运行，新成功结果刷新后续可复用缓存。
- 马良底部必须提供“查看具体过程”入口和可最小化面板，按时间展示实际收到的模型输出、工具调用、节点状态、命令请求与返回及错误；完整日志同时保留原始运行事件和本机诊断。最小化只隐藏面板，不得取消任务或停止记录。
- 过程视图复用控制器的运行事件、完成和失败信号，并由控制器在命令成功启动后发出携带冻结请求快照的开始信号；界面只消费这些可观察记录，不在视图层另造任务状态或推断未返回的模型过程。

## 5. 自定义流程模板

- 自定义流程模板用于复用一组节点，具有独立编辑页签和稳定模板 ID；改名只改变显示名称，不得破坏主流程中的既有引用。模板不得引用自身或形成循环嵌套。
- 新模板固定包含“流程输入”和“流程输出”节点，分别提供唯一输出和唯一输入，不能删除或复制。固定输出必须连接一个内部处理结果，不允许把固定输入直接连接到固定输出而形成没有执行目标的直通图。
- 主流程通过模板节点复用定义。运行前将每个实例展开为带实例前缀的内部节点，外部输入接到固定输入的内部目标，外部输出来自固定输出的内部来源；预览和重试仍归属于用户看到的模板实例。模板编辑页可以独立运行内部普通节点。
- 工作流序列化同时保存主流程、全部模板定义及其输入快照，旧版单页工作流保持兼容。缓存指纹递归包含模板内部定义，但排除节点坐标和显示名，确保逻辑修改使实例缓存失效而纯展示修改不触发重算。

## 6. 实际运行环境与验收

- 内置马良工具由 `editor/ainative/builders.py` 嵌入引擎，启动时安装到编辑器数据目录的版本化 `ainative/bundles/<hash>`；仓库源码修改不会自动同步到正在运行的 bundle。
- 修改 `tools/ainative` 或内置 GDScript 后，必须重新构建引擎候选，让新 bundle 安装到实际编辑器数据目录，并重启相关引擎／服务。不得用手改安装目录副本代替可重复构建。
- Python、受信宿主脚本等机器级运行环境在保存时同时写入 `ainative/shared-host.cfg`，供所有工程共享；任务状态和服务方案仍按工程隔离。不得在新工程中仅因本地 `local.cfg` 不存在就静默恢复成另一套 Python。历史本地 host 配置作为兼容备份保留。保存生成服务时不得顺带覆盖 host Python；只有 Codex／本机网格模式管理对应运行库时才可临时采用其 Python，Kimi Native 等其他模式不得修改该字段。
- 验收前回读实际 worker 日志、bundle 路径和文件哈希，证明运行的是本次候选，而不是旧 bundle。
- 单元测试、合成 HTTP、真实渲染、真实视觉 API 和真实生成是不同证据等级。排查实际失败时，优先使用本次同一 GLB、实际 bundle、实际渲染脚本和实际审查接口复现。
- 最终业务通过必须看到实际任务的终态、模型哈希和完整 review 证据；不得仅凭源码测试通过或引擎成功启动就宣称可验收。
