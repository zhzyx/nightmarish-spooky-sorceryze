# 父子 Issue、提交与尾项结转

适用本仓库所有工作者，路径以仓库根解析。偃师设计、阎罗交付与司南协调在本宿主使用本规则；不修改共享 Agent 定义、元衡准入或业务验收责任。来源为 [需求](../../../design-docs/issue-granularity-20261105.md)。这是执行契约，文档存在不表示 GitHub 关系同步或自动关闭服务已接通。

## 偃师在设计定版时拆分

父 Issue 管完整目标、设计版本及整体验收；设计内列出多个可独立提交、验证、接收的 sub-issue。拆分先于生产派发，避免把整项设计、实现和收尾长期塞入一个 Issue。以最小可交付行为或模块为粒度，不按文件数、行数或任意工时拆分；同一不可分割验收链不得为了关单拆碎。没有两个独立单元的小修复可保留单 Issue，设计中说明原因。

使用 [设计拆分模板](../../../design-docs/templates/issue-breakdown.md)，覆盖每条需求和父级集成验收。每个子项有独立稳定需求 ID、真实 Issue URL、设计条款锚点、范围/非目标、验收、依赖、实际责任人、交付目标和所需检查；子项只保留自己的 gonggong-request 标记，父 ID 用普通链接表达，避免入口 ID 歧义。共享验收指定唯一主责子项及依赖，不遗漏也不重复完成计数。

经授权创建/复用真实 Issue 并建立 GitHub 原生 parent/sub-issue 关系，回读父子两侧；正文任务列表只是展示，不能冒充原生关系。无权限或失败时记录 relationship_pending，保留已创建 URL，恢复先查重，不重复建单。设计审批、实现授权和准入仍按原边界执行；生产前对实际执行子项运行 intake-only。

## 按子项提交和关闭

默认一个提交/PR 对应一个子项及其文档、测试和事件，使用该子项的 GongGong-Issue/GongGong-Request。父项写在普通关联链接中，不添加第二组关联字段，不使用自动关闭父项的关键词。不可分割的跨子项贡献在设计中说明，主关联仍只有一个，各受影响子项分别取得验收和交付证据；一个 PR 不代表所有关联项完成。

阎罗沿有效职责核对精确候选、完整贡献、适用独立审查、正式门禁和目标分支接收。仅本地 commit 或 PR 创建不算交付完成。目标提交/树远端回读、适用验收及证据持久记录完成后，即可把对应子项设为 status:done、以 completed 关闭并回读，不等同级子项。关闭失败只恢复状态步骤，已发布内容不重复提交。

子项关闭或重开事件交司南核对父项：分页回读全部原生子项与设计清单，检查没有漏建、未完成、未知、结转未接收或新增范围。全部子项已关闭且每条原始验收均已完成（或有真实范围变更决定）、父级集成验收通过，才由阎罗按完整证据关闭父项。closed 不等于 completed；cancelled/not_planned 子项不能计入完成。完成数只表示验收项数，不表示工作量百分比。子项重开后重新判断父项，必要时恢复开放并记录原因。

## 阎罗在合入事件中结转尾项

复用 #79 的当前宿主判断：已完成验收项超过总数一半，或已有模块完成且仅剩至多两个未支持模块时，触发拆单审查。这里的“少量”依完整设计清单判断；模块不可比、范围不明或证据未知时保留 unknown，不据此关单。原清单及统计分母不可为达到阈值而删改。只在实际合入、交付或明确恢复事件执行，无定时扫描。

满足阈值后，阎罗核对剩余子项能独立承接、已交付部分可验收、没有未解决的父级集成失败或权限/安全必要条件。满足这些条件且尾项在原授权范围内，执行本次用户要求的结转；若涉及承诺、权限或验收实质变化，先取得对应范围决定。仅少量、仅多数通过或仅新建 Issue 均不足以关闭旧单。

1. 固定旧父单修订、设计版本/摘要、原子项全集、已合入提交及完成/剩余/未知项。生成稳定结转键（旧父 ID + 设计范围版本），先查所有开放/关闭单；唯一开放承接单可复用，已关闭匹配或重复匹配须对账。
2. 建立新承接父 Issue，逐项复制剩余验收、依赖、责任与来源锚点。已有开放子 Issue 优先保留编号、迁移原生父关系；确需新建替代子项时逐条映射，原子项以结转原因关闭，不能标 done。旧父正文保留历史子项清单及迁移去向，不能因原生关系移动丢失追溯。
3. 更新同一设计档案的结转记录；新旧父单双向链接，旧子项→新父/替代子项映射，记录原设计版本、保留验收、已交付证据、实际操作者和回执。新单覆盖全部剩余与待验证范围，不能悄悄缩小承诺。
4. 回读新单、全部关系、文档与旧单修订。确认承接范围完整、没有并发新增工作，再将旧单设为 status:cancelled、以 not_planned 关闭，正文明确“已结转，未完成范围由新单承接”，不能声称取消用户目标或全部完成。若旧单全部验收实际完成，走正常 done/completed 关闭，无须结转。
5. 最终回读关闭结果，追加 Diting/采集证据；司南更新依赖和父级视图，继续跟踪承接单。结转不是完成事件的替代品，祖先不能因旧单关闭自动通过验收。

建单、关系迁移、文档更新或回读失败时旧父单保持开放。部分迁移保留操作回执和待恢复映射；下一真实事件从实际状态恢复，不盲目新建、关闭或回滚。关闭前发现修订漂移则重读差异并复核受影响项。旧单已经关闭但回执未知时先回读，禁止重复发布。

## 文档是跨 Issue 的溯源主线

设计档案长期保存需求→设计条款→父/子 Issue→提交/PR→检查与接收证据→关闭/结转链。状态权威仍为远端 Issue；本地表格注明最后回读及待同步项。文档改版保留 Git 历史、范围决定和前后版本，不复制成互相竞争的需求账本。每次子项交付与结转均同步档案，证据随交付进入 Git；归档旧单不删除原始设计、批准和事件。

现有单在下一次设计、合入或交接事件渐进拆分，不批量关闭存量单。本规则要求宿主执行者遵循；自动适配器尚未支持的动作保留待处理，由实际有权执行者按本契约完成并回读，不能声称已由程序自动强制。
