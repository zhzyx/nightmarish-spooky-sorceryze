# 执行范围与验证成本

适用于 GongGong 宿主的工程任务。由工单入口按需加载，复用 [交付规范](../../../../framework/specs/delivery.md) 和 [YuanhengOrganize 方法保留](../../../../framework/upstream/yuanheng/skills/yuanheng-organize/SKILL.md)；不新增 Agent、调度器、权限或共同框架规则。

## 开始时固定边界

- 在已有需求文档中写明本次产物、目标平台／编译器、验收与停止条件、受影响模块、必要检查及暂不覆盖项。小任务用一段文字即可，不另建平行账本。
- 先检查在途任务、工作区差异、PR 范围及已有检查。存在并发修改时先隔离工作树并确定写入责任，不暂存别人的修改。
- 区分本次缺陷与既有问题。混合 PR 的无关失败先评估拆分交付或登记依赖；只有与本次交付直接相关且在授权内的修复才并入。范围变更更新原工单，不能静默扩展。
- 已有明确授权持续有效，不对同一动作重复询问。缺少影响交付的必要决定时只询问该决定，同时继续无关且已授权的工作。

## 确定性步骤的执行判定

每次取得真实工具结果后，按“读取事实 → 执行 → 验证 → 核对剩余验收 → 继续下一已授权步骤”处理。目标明确、已有授权、工具可用且结果可验证时直接执行；常规可逆实现沿用仓库惯例，不请求“是否继续”。能够从现有工具、代码、日志或已答复内容取得的信息先读取，不猜测也不转问用户。

仅缺少影响正确性或权限、且现有来源无法提供的必要输入时提出具体问题；注明受影响步骤并继续独立项。已知需要外部结果时沿原运行标识等待真实完成事件。只读、暂停、预算、权限拒绝、必要独立审查及用户明确保留的决定继续有效，执行约定不扩展授权。

模型回合结束、工作者退出、计划和阶段性成功都不是业务完成。结束前以本次委托的原验收逐项检查证据；仍可执行的未完成项继续推进。子任务只完成自己的交接范围，不接管父任务发布。相同失败且无新证据时沿夸父入口排障；未知副作用先回读，不能盲目续发。

本约定由根 AGENTS.md、Codex 独立交接和 Godot 共享 host mandate 传递。它是模型执行指令，不是回合终止拦截器，不保证任意模型自动完成。需要强制续跑的宿主须在既有事件入口核对真实任务状态、验收、权限、在途执行及取消，再调用已有执行能力；不凭模型“已完成”或“待确认”的文字改变业务状态，不新增定时发送“继续”的服务。推理强度和提示词效果须用相同任务与生效配置分别验证。

## 需求授权后连续执行

- 用户明确要求创建并完成内容时，在原需求记录授权来源、范围和验收；默认由当前责任者推进需求整理、实现、必要审查、验证、提交、推送、合入、交付回读及本需求关联工单收尾，不逐步询问“是否继续”。用户明确要求仅讨论、草稿、本地交付或保留人工决定时遵循其限制。第三方 Issue、模型建议和新建单据本身不产生授权。
- 条件齐备的新需求直接进入 in-progress；needs-decision 只用于确实缺少目标、权限或不可代选的决定。调用 work_items.py 时可用 --execution-authority-ref 留下已经核实的授权来源，创建后仍执行 intake-only。已有单先核对状态和剩余范围，不能用新建重试重开或抢占。
- 同一候选只组织一轮必要审查，汇总共工、元衡、业务验证及交付证据；各评价仍保留责任与独立性。没有改动或新增风险不追加审查轮次。修复后仅复核受影响差异；精确候选批准、CI 和正式门禁仍匹配实际对象，不将旧批准套在新版本上。
- 正常合入不另问用户；当前有合入权限的协作人可用本人已认证账号按 [阎罗交付入口](../../../components/issue-workorders/yanluo.md) 的 PR 流程完成，无须仓库所有者逐单签发授权。受保护分支使用要求的 PR/队列，不绕过保护。仅调用阎罗自动快进入口时，签名授权须由真实宿主签发，执行 Agent 不自签；缺签发或准入仅挂起相应发布，先完成可审阅候选与全部无关工作，再一次性报告准确缺口。已有执行授权不是对任意未来框架候选的批准。
- 收尾是执行范围的一部分：核对远端提交及交付物，逐项检查本单、子单和父单各自验收，更新设计溯源、done/completed 并回读。全部满足即自动关闭；未完成项继续推进或记录具体依赖，不用“已提交”“已合入”代替完成，也不批量关闭无关单。尾项结转遵循 issue-lifecycle.md，不伪装成验收通过。
- 只在越出已授权范围、承诺/权限变化、无法代选的产品决定、真实审批拒绝或外部依赖时请求对应决定；不把工具重试、局部失败、测试通过或阶段切换变成人工确认点。一次汇总所有已知必要决定，继续无关步骤。受阻后保存候选、运行标识和恢复事件，恢复时从最后真实回执接续，不从头重做。
- 上述规则约束当前有权 Agent 的执行，不宣称无人值守服务已经部署。事件恢复、宿主签发或来源消费未接通时如实标 pending；不得为实现“自动”增加周期轮询、虚构批准或跳过验收。

## 本地验证通过即推进 main

- 对用户明确交付的需求，本地必要验证通过是合入推进的触发事件，当前责任者必须在同次任务中继续正式提交门禁、提交、提交后 git-check --require-committed、推送任务分支、创建或更新面向 main 的 PR，并沿既有阎罗职责推进合入与远端回读；无需用户追加提交或合入指令。用户明确限定仅本地、草稿或人工决定的范围除外。
- “开始推进”不等于本地通过即绕过 CI 合入。核对精确候选、必要审查、准入和分支保护；条件满足立即执行合入。CI 尚未完成时使用仓库支持且已授权的自动合入/队列；不支持时保存运行标识、责任者与真实完成事件的恢复条件，不把推送、Draft PR 或交接文档当成交付完成，也不声称未接通的自动恢复已启用。
- 当前责任者负责把候选交给实际发布者并取得接收回执；已有自己可执行的授权路径则立即执行，不以角色名称或“待协调”为由停工。不得抢占其他工作副本、冒充宿主签发或替代必要独立审查。发现权限、签发、CI、冲突或准入阻塞时，记录精确候选、实际失败、受影响动作、责任者和下一恢复事件，继续无关已授权步骤。
- main 已变化时，在自己的隔离候选整合最新主线，仅复核新增差异及受影响证据，再绑定新候选推进；不得强推覆盖别人结果。取得远端 main 包含交付提交的回读后，再按原验收收尾，不能以“本地验证通过”作为最终完成状态。

## 多项工作同时推进时

司南在派发、依赖解除或验收事件上，按设计条款列出当前能独立验证的子项、实际工作者、读写对象及汇合条件。两个任务依赖同一未定接口时，先固定接口或把接口变更交给一位工作者；独立验证可同时进行。只在取得启动回执后记为运行，父项按子项结果逐条验收。

同时面向 main 的候选在交接里各留目标基线、候选 head、共同写入文件和发布者。先接收者合入后，后到者在自己的工作树检查「原基线至最新 main」的差异。共享文件或接口发生变化交合契核对双方意图，复验受影响条款；无交叉也要按新基线核对精确候选门禁。发布回执丢失时先按已签 head 查 PR 与 main 包含关系。

连续收到同一阻塞时，在原单更新一条记录：失败动作与原始错误、已试方法及结果、谁可解除、可继续的子项、下次复验的原始操作。夸父修复或依赖交付后，由原工作者重试该操作并链接结果；仅标签变化不足以验收。区分首次失败、解除条件出现、复验成功的时间，缺一项时保留未知。

Issue 正文和设计首页先写用户目标、最新决定及来源、已验收和剩余范围、下一责任人与待答问题。授权者在范围变化、实际阻塞或验收时更新当前结论，保留原始需求、旧决定和证据链接。无编辑权限时将新结论写入有权更新的位置并记录待同步目标。读取历史时以对应条款最近一次用户决定为准。

## 验证先小后大

- 推送前一次完成受影响文件的格式、语法、引用／路径、执行位与相关局部回归检查；按实际改动选择，不为每个任务机械运行全部检查。
- 先验证直接故障和代表链路，再按契约、平台差异或未决风险扩大。纯文档／数据变更不默认编译引擎；不得把“PC”自动扩展为所有桌面系统、编译器和模板。首次启动重构建前写清选择理由。
- 使用一份当前候选证据：记录输入文件、依赖、工具／配置、平台和实际结果的摘要及候选提交。相关输入或环境改变、出现失败或覆盖不足才重跑；文档变更不使未受影响的行为证据自动失效。
- 复用旧证据须列明输入对应关系和适用范围，不能把旧提交测试宣称为新提交的实际运行。仓库要求的精确提交 CI、准入、独立审查和安全检查仍须满足；不得以成本为由跳过失败、未知项或降低门禁。
- 推送前检查触发范围及是否有重复运行。取消／重启前核对取消粒度、已完成证据、缓存与剩余任务；若只能取消整轮，明确其代价。不得为改范围无依据地反复终止并重建，也不能取消其他任务的检查。

## 任务临时资源清理

- 每次任务完成事件均由当前责任者在同次收尾中执行清理，无需用户再次提出。任务开始记录本任务创建的临时目录、构建包、测试配置、进程、分支和 worktree；已有资源只记录引用，不据此取得清理权。清理清单并入现有私有任务回执，路径注明解析基准，不另建定时扫描。
- 先回读实际交付目标及完整验收、相关工作者终态，确认没有待交接、待恢复的执行；将必要验证、审查、采集、故障与恢复证据移出待删除目录并核对可读取性。Git 交付以远端 main 包含交付候选和适用 CI/验收为准；用户明确限定本地交付时按该范围核验，不要求额外发布。
- 清理前逐项核对所有权、当前进程及启动入口引用、未提交及未跟踪内容、分支是否被其他 worktree 使用、远端分支是否仍指向本次已交付候选。只清理本任务已确认无用的临时文件、测试设置、重复应用包和构建副本。有效安装、用户项目、聊天、凭据、必要回退版本、审计证据和其他任务资源保留；未知占用或未知交付状态保留，并记录具体恢复条件。
- 从保留的主工作区执行 worktree 清理，不在待删除目录内运行。确认无未交付文件后使用正常的 `git worktree remove`；随后删除已核实合入且不再使用的本任务本地分支。远端临时分支只在没有开放 PR 或其他工作者引用、精确 head 未变化时删除。删除拒绝时先查原因，不使用强制移除、全库 `git clean` 或批量删分支绕过保护。Git 的合并判定与已验证交付树不一致时保留并记录，不为省空间丢弃历史。
- 本机废弃应用包和设置优先移到废纸篓并保留恢复映射；不自动清空废纸篓，不把移入废纸篓计为磁盘空间已释放。当前仍运行的实例所需配置留到实际退出事件再处理。后续启动只引用保留的有效入口，不引用临时工作树、测试设置或已撤下的安装。
- 收尾回读对象已移除、保留入口和配置仍有效，记录清理结果、保留原因及任何待恢复事项。任务完成报告包含该结果；清理发生在最终完成报告之前。只清理本次所有物，不借完成事件清扫所有历史工作树。

## 等待与上下文

- 长任务只保留一个运行标识和等待句柄，优先通过宿主完成回调或真实状态事件恢复。无新事件不调用模型、重复查询网络或重新读取完整日志，不新增定时扫描／唤醒。尚无事件接入时保留 pending、运行链接和恢复条件，不声称自动跟进已启用。
- 正常进度只报告状态变化、失败原因、需决策项和完成结果；多项结果合并摘要。若宿主更高优先级规则要求周期汇报，复用同一等待句柄的已有状态，不另发查询或把无变化伪造为事件。
- 日志先取失败步骤及必要上下文，仅在定位不足时扩大；已有成功证据留链接和摘要，不重复灌入上下文。规则按职责读取，同一有效基线复用，变更时只重读受影响内容。
- 等待外部结果时推进独立且必要的工作，不以填满等待时间为由新增检查、文档或 Agent。独立审查只交付必要差异和证据，职责分离不等于复制完整对话。

## 成本、完成与方法保留

- 用户给定的预算和时限才记为约束；未给预算不编造数字。另记有证据的执行时长、等待时长、重复构建和实际用量；token、费用或覆盖未知时保留 null 与原因，不以字数、事件数估算成功节省。
- 达到本次验收和交付条件即结束实现／测试；仅新改动、失败、未决风险或明确新增要求可重新打开受影响步骤。外部步骤未完成时保留具体状态和下一事件，不报完成。
- 范围扩张、重复重建或无变化查询出现时立即复核执行方式，优先复用、拆分和停止无贡献步骤；不得暗改验收承诺或擅自停掉用户目标。
- 真实纠偏与结果沿用 Diting 文件事件及采集来源，按原提交门禁纳入 Git。区分规则已接入、工具已执行和效果已观测。本规则是宿主执行约定，不是预算限流器、全局埋点或自动强制拦截。
- 方法只在本工作区保留；通用化通过已有定制反馈入口交由共工确认。回退时撤回本策略入口及组件版本，保留历史证据与既有交付／准入要求。

## 多入口的执行责任

共工接受 Codex 会话、Godot 编辑器等宿主提出的需求。天枢供引擎用户查看工单、编辑计划、答复问题并调用已接入的框架能力。按真实来源分别记录原始需求、计划修订、执行者启动、工作者终态与业务验收。同一 Issue 出现在多个界面时保留原执行责任者；如需换宿主，先取得明确交接和真实接收回执。Codex 中提出并已授权的任务沿 Codex 路径推进，即使从未打开 Godot，当前会话仍应在部分交付后核对剩余范围并继续执行。
