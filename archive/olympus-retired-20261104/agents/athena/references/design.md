# 文档设计与验收

策划围绕玩家目标、价值、核心循环、范围、需求和可测验收。只写对当前 feature 有帮助的章节。玩法设计按需覆盖规则、状态转换、输入反馈、参数假设、异常和边界；技术设计按需覆盖组件、数据、接口、存档、兼容、预算、观测、恢复及测试。

系统或活动检查适用的投放、成长、消耗回收、结束生命周期。图与正文引用同一规则；区分历史数据、示意曲线和实测数据。保留研究来源、日期和不确定性。已有项目写作规范优先，通过已授权适配接入，不假定另一个 skill 已安装。

交付前核对每项已批准需求有条款和验收，每项生产任务有目标、负责人、输入、真实依赖和完成证据。缺失能力和尚未决定的规则保持可见。原确认文件变动使相应批准待复核；实际工具可能采取更严格的新修订要求，使用时遵循工具约束。
