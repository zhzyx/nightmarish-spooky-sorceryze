# 奥林匹斯客户评估与方案配置规范

版本：0.2。性质：专项规范草案。加载条件：客户接入、试产或调整方案时。

按需参考依赖：specs/module-system.md。仅加载与当前职责有关的部分；不要求每个执行任务读取全部依赖。

## 客户需求评估与方案配置

评估先理解目标，再检查已有能力与生产约束，最后配置模块、组织和资源。团队人数仅是其中一个维度。

| 评估维度 | 关键输入 | 影响的决策 |
| --- | --- | --- |
| 业务目标 | 原型、扩产、质量、周期与交付承诺 | 优先能力与成功指标 |
| 生产对象 | 类型、复杂度、可编辑要求、风格一致性 | 模块、配方与加工流程 |
| 团队构成 | 岗位、人数、技术能力、负责人、供应商 | 人机分工、工作台与接管点 |
| 规模与时效 | 日常量、峰值到达率、批量大小、截止时间 | 队列、优先级和容量 |
| 工程耦合 | 共享代码、场景、资产和跨组依赖 | 隔离、集成及回归范围 |
| 现有系统 | 引擎、DCC、版本库、资产库、工单与构建 | 连接器、替代能力与实施成本 |
| 质量要求 | 平台、性能、内容规范和验收责任 | 门槛、证据与审查方式 |
| 数据与部署 | 网络、数据边界、模型限制、保留期限 | 云端、私有化或混合部署 |
| 预算与运维 | 成本范围、服务需求、运维能力 | 资源策略、支持与服务范围 |

接入分为快速访谈、经授权的项目体检、代表任务试产、方案定版四步。访谈产生初步方案；项目体检识别真实依赖与工具差异；试产测量通过率、人工返工、处理时长、等待和有效成本；有权负责人确定费用、数据和交付承诺。未经试产不承诺通用吞吐量。

风险可按“低、有限、显著、关键”分别记录耦合、数据、规模、质量和能力缺口，并附证据与置信程度。不能用单一总分掩盖关键限制，也不根据人数直接划分能力等级。信息不足时保留待验证项，并用小范围试产解决。

客户方案至少包含：目标与范围、生产对象、模块及版本、客户提供能力、连接器、岗位权限、工作流、组织规则、质量门槛、并发资源配置、成本策略、数据边界、实施步骤、基线指标及退出交付方式。

| 生产场景 | 典型组合 | 优先解决的问题 |
| --- | --- | --- |
| 小型原型团队 | 玩法设计、逻辑、灰盒、已有资产检索、运行验证 | 快速形成可试玩改动 |
| 资产批量供应商 | 规格接入、批量生产、加工、质量检查、交付 | 一致性、吞吐与来源追溯 |
| 多团队研发项目 | 代码、玩法、关卡、工程知识、集成验证 | 共享依赖与跨组可靠合入 |
| 外包交付团队 | 客户需求、规范适配、审阅与交付 | 不同客户隔离、验收和版本对齐 |

上线后按证据调整配置。低采用率不必然意味着模块无用，需区分低需求、能力不足和流程阻碍。授权预算内的任务路由可自动调整；新增费用、扩大权限、改变验收或交付承诺须走现有治理程序，不重复索取已有授权。
