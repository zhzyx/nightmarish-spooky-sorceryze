需求 ID：`game-config-platform-20261120`。路径以本仓库根为基准。

用户于 2026-11-20 要求基于共工当前在线文档与共同编辑搭建游戏配置管理平台：游戏生产中需调试的参数、配置内容和 ID 按 feature 聚合，改动即时生效。当前 Codex 会话负责需求、实现、验证、独立审查与 main 交付。复用天璇身份、文曲文档、权限、版本和实时同步；不新建框架 Agent 或修改冻结定义。既有工作树与部署保留。原生产平台在途工作只读核对，不抢占发布。

## 设计与验收

1. Web 导航提供游戏配置入口，按项目及 feature 汇总可调参数、内容与稳定 ID，可搜索、创建与编辑；feature 关联文曲说明文档。
2. 配置定义支持数值、布尔、文本、枚举、结构化 JSON 和 ID 引用，包含默认/当前值、说明及约束；服务端拒绝类型、范围、重复 ID 与无效引用，不允许错误值进入有效快照。
3. 配置权限沿用天璇租户与文曲 ACL。保存带版本条件；并发冲突可见并保留本地输入，其他协作者看到已保存版本，不静默覆盖。
4. 保存后实时推送完整有效快照，重连从权威快照恢复。游戏在运行中应用，不要求重启或重新打包；只有实际消费者确认才显示已应用，未连接、失败与待应用独立显示。
5. 版本历史与恢复可用；恢复追加新版本并重新校验，不覆盖历史。配置说明可从现有在线文档共同编辑入口访问。
6. 提供 Godot 运行时客户端与独立示例，通过稳定 feature/config ID 读取与订阅变化，保护最后有效值；测试正常热更新、非法输入、并发、重连、权限隔离与恢复。
7. 完成受影响 Python 测试、Web 类型/构建与实际 HTTP/WebSocket 及 Godot headless 热更新验证；独立审查、工单门禁、CI 与 main 回读分别留证。

即时生效指已经接入且在线的运行实例消费已验证配置。任意游戏已有硬编码、代码和需重建资源不能仅靠配置 UI 自动热替换；本任务提供通用参数/内容注册接口及 Godot 应用示例。未连接消费者不显示成功。按照用户最新范围，不要求实际游戏项目；源码 main 交付与既有站点的生产部署分别记录，不宣称站点已升级。

优先复用文曲持久化、事务和版本条件，配置新增独立接口与 UI 文件，减少对现有协作和生产执行模块的交叉修改。必要后端/前端工作按固定接口隔离派发，独立核查不写实现文件。测试数据库、进程、输出、分支及 worktree 归本任务，完成后核对交付与工作者终态再清理；未交付候选及必要证据保留。
