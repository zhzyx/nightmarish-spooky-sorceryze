# R02 编辑器关闭时的最后一个工作步骤

天枢工作区收到退出事件时先停止接收新的需求判断、预览、执行和工作者步骤，并将当前账号和项目的任务检查点随原有个人缓存原子写入。运行中的步骤记录运行号、绑定工单、来源请求、序号和状态。已经返回的最近一步保留终态。重新挂载同一个面板后才能重新接收操作。

原生聊天停靠面板退出时停止并行派发入口，标记该批次并结束其调度进程。调度器从队列领取下一单以及准备回执返回后，均检查当前批次是否在关闭。运行过的工作者保留各自的登记和产物回执。运行中工作者的系统进程树处理由 R03 和 R04 接续。

macOS 候选编辑器在真实退出事件上接收原工作者回执，同时提交下一步。重新打开磁盘缓存取得原运行号，关闭后的新增派发数为零。另验终态先到时检查点保存其序号与成功状态，以及独立 Node 调度器在第一项结束的同一回调进入关闭时第二项的进程启动数为零。[原工单](https://github.com/zhzyx/nightmarish-spooky-sorceryze/issues/1802) · [回执及复验命令](../data-collection/gonggong-ai-workbench-plan1-r02.json)
