# 引擎内置 Terrain3D 与虚拟纹理地形

<!-- gonggong-request:terrain3d-native-vt-20261127 -->

## 需求与范围

任何使用本引擎的新 3D 项目都应能直接创建、编辑和导出 Terrain3D。已有地形项目需要保留场景类型、资源属性、笔刷结果和区域数据。Windows 桌面 Vulkan Forward+ 是本次验收平台，迁移输入来自 Terrain3D v1.1.0-stable 及工作区的四叉树扩展。

## 引擎边界

- 场景模块注册原有 12 个地形类型。地形数据、碰撞、网格和实例由模块持有，四叉树、虚拟高度页、RVT 和 SVT 通过 RenderingServer 与 RD 后端对接。保留直接材质和原生高度作为可切换的画面对照。
- 编辑器自动加载随可执行文件分发的工具、图标和笔刷，支持初始化首个区域、雕刻、撤销重做和保存重开。导出模板只包含运行时依赖。
- 离线 SVT 校验布局、世界边界和来源签名。材质纹理变化时回退到实时页。预览工具分别展示实际来源，打包工具收集选中场景引用的高度、材质流和 Region。
- 原项目通过复制迁移；保留自定义运行资源、脚本 UID 和项目数据。编辑器与调试、发行模板按同版本分发，使用默认 Windows 导出预设。

## 验收与复验

1. 无插件空项目创建并雕刻首个区域，交替执行保存、撤销、重做，关闭编辑器后重开检查高度和第二个地形的独立性。
2. 从新缓存导入旧山谷，核对类型签名、源纹理、区域以及碰撞。将原生高度与 VT 在移动、远眺和越区时对照，检查稀疏区域映射、可见范围和边界。
3. 同一光照、相机和分辨率拍摄直接材质、缓存材质和页来源。检查静止帧、近景纹理梯度、冷启动磁盘页、材质编辑后失效和正确来源重新烘焙。
4. 从多个独立项目导出 Debug 和 Release 包，回读继承场景、嵌套材质及 Region，执行排除过滤；普通项目的导出应避免额外构造不相关的场景资源。

## 愚公地形工作台

编辑器内置布局编辑和地形场景生成。作者可用中文描述生成本地布局，或载入样例后拖动河流、道路与台地控制点。生成场景时保留可重开的布局记录，连同原生地形、材质与试玩所需对象一并保存。覆盖已有地形时沿用原场景的材质与其他对象。

构建、迁移、烘焙、愚公操作和验收命令见[模块说明](../modules/terrain_3d/README.md)。
