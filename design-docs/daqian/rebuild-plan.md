## 当前现场

workspace.gd 在基线包含 142 个函数，负责导航、刷新、发布、审批和聊天。#427 记录 macOS 创建人缩放选错后测试缺键并超时，触发时序待核。43.5 秒为旧版刷新现场。#195 是工单接续的业务样本，入口动效由原单追踪；#347 有 Windows 真实路由回执。模型自动刷新存在并行候选 #439，集成前回读其实际接收状态。

## 实施顺序及验收

1. 建立版本与场景基线。复验 #427、#83 待办、#347 路由及旧草稿，分开记录冷启动到可操作、后台刷新及提交到反馈时间。保存平台、引擎修订、操作路径与失败步骤。
2. 完成建单到验收的纵向改造。每步显示同一工单的当前环节、责任者、下一步和恢复入口。回放断网、未知回执、重连、重启、切换账号及过期审批，核对无重复建单和误执行。
3. 完成总览到详情再返回。复用 #427 作为导航回归，建立唯一的范围、创建人、选中目标及视角恢复规则。核对 55 单、未知创建人、键盘、鼠标、窄幅和刷新中的切换。
4. 按两条真实路径逐步拆出导航、建单与回执、详情与审批、聊天绑定。每次迁移跑对应原生用例。验证老数据、并发取消、个人布局及相同来源重放，候选可单独回退。
5. 同一候选在两端接续一个真实工单，核对图、图片、模型和分支、明确待答、审批、验收、main 与关闭回执。按实际执行身份记录回环与真实调用，未实测项单独追踪。

首次交付以正确进入和返回原工单、网络或模型失败后可原位继续为验收。整体验收按以上五项逐项回读。
