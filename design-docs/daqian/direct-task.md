# 大千按共工流程直接建单与按需澄清

用户在当前 Codex 聊天明确要求大千与共工框架一致，偃师分析按需。默认允许明确任务直接从 Godot 建立真实工单，不调用模型；选择偃师时保留模型选择和原分析链路。直接建单使用原始需求、稳定标识、仓库原入口、同账号回读及真实创建事件，区分建单与执行授权。图按实际路径呈现，重试不重复创建。以 macOS arm64 的原生编辑器和定向宿主回归验收。路径相对仓库根。

默认直接建单，从仓库类别中选择类型，标题取原文第一个非空行。确认创建与开始推进分开：先向权威来源建单或核对原标识，然后传递 request.created；用户点击开始推进才以该单的稳定绑定进入司南对话，可在创建时指定推进模型，也可沿用当前执行模型。直接建单登记为 planned；点击开始才通过 issue-start 切换为 in-progress，随后核验宿主准入和权限。选择“请偃师分析后建单”时可另选澄清模型。工单与授权来源 https://github.com/zhzyx/nightmarish-spooky-sorceryze/issues/174 。
