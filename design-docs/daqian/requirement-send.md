# 大千创建需求时选模、确认发送并启动偃师分析

用户在当前 Codex 聊天反馈，大千发布需求后找不到确认发送及推进按钮，并要求创建需求时可以选择模型。当前会话负责该需求。范围包括大千草稿、确认发送入口和 AI Chat 的偃师需求接入。验收覆盖输入、选模、取消、确认后使用所选模型进入分析、重复点击及失败反馈。以 macOS arm64 编辑器和定向回归验证。路径相对本工作树根。

用户追加要求按共工框架自动生成和更新节点。创建草稿显示需求与偃师分析的关系，准备运行时按实际设计、待确认项和就绪回执呈现司南协调、任务及验收。区分计划、真实运行和终态，覆盖旧草稿、重复回读及个人编辑。工单 https://github.com/zhzyx/nightmarish-spooky-sorceryze/issues/172 。

## 流程节点的依据

以 CURRENT_FRAMEWORK.json 指向的 0.9.2 及仓库的 Git 交付接入为准。创建和重开草稿时呈现需求 → 偃师分析。窗口确认由框架启动需求分析；本机环境待配、分析进行、待答、就绪、失败与停止均以实际回执更新。范围、问题和验收条件来自最近一次偃师设计或关联工单。运行准备显示司南、真实前置工单和预期任务；开发类工单按接入显示合契候选整合、结果验证及阎罗交付步骤；工单明确阻塞时显示夸父处置。谛听记录来自实际事件；元衡治理和共工审查按各自适用边界触发。节点连线表示计划，执行状态须有独立回执。展示层与可编辑、可调试的图分开，以免重开时重复派发。
