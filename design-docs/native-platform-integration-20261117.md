# 天璇原生模式：文档、工单、模型与需求版本接线

需求 ID：native-platform-integration-20261117。父目标 #1382；依赖已验收 #1413，main 4b1ca40e3f48c0b766bd9768865412be0ee2d5d0。沿用用户开始执行与继续授权；当前服务、数据库和既有生产部署不在本切片直接替换。

原生候选 API 已不依赖 Git，但原生入口提前返回，文曲文档、偃师需求、司南工单及模型接口未挂载，尚不能形成日常工作链路。本项恢复这些既有能力并接到多宝精确版本；不新建平行协调器，不把候选接收当作完成验收。

验收范围：

1. 原生模式下，真实 HTTP 注册独立组织、登录、创建和编辑文档、创建需求并拆分工单、状态及需求进度回写、评论/历史/机器视图可用；不同组织仍隔离。所有既有非 Git 文档与工单能力应保留，不用一个功能更少的平行平台替代现有实现。
2. GitService、MergeQueue、Gitea 和 Git 专用环境均不是原生启动或上述操作的前提；原生模式不暴露可执行的 Git 仓库、合并、导入、webhook 和 Git commit 路径。既有 Git 模式可回退。能力接口明确报告实际模式及可用能力，天枢桥 status 不再强制调用 Gitea。
3. 在原生模式挂载既有模型网关时，actor 与 tenant 必须来自有效会话或生产已核验身份。不能凭 X-Tenant、X-Actor 或 usage 查询读取/记账其他组织；角色/撤销及生产严格 Key 准入不弱化。复用现有网关、用量和预算，不改司南模型选择职责，不通过本项发生未授权实际模型费用。真实上游调用的边界测试使用确定性本地模拟并明确其性质。
4. 增加需求到原生版本的入口：保存一致的需求文档及其关联工单快照，返回精确模块修订/组合和来源版本。基线条件及稳定操作键明确，原生存储为该快照权威；不创建 Git 仓库。源变化不能被伪装成旧来源，历史回执重试返回原事实，异内容同键拒绝；范围未知沿用保守读取检查。快照不自动批准、发布或把工单标成 done。
5. 真实 HTTP 端到端验证注册→文档/需求→拆单→原生快照→读取/重启→进度，包含跨组织、撤销、输入错误、源版本变化、幂等和 Git 构造器不可用。复验相关既有 API/模型/核心/天枢桥测试。通过独立审查和当前服务器隔离测试。
