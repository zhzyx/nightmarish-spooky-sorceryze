# V10 从失效回执复验已保存的对象

工作台读取 `GET /api/v1/native/workflow/tasks/{key}/validation/{module}/{path}`。修改并保存场景后，如果某项已有检查的登记输入已变，响应的 `recheck` 给出当前模块修订和受影响的检查名。客户端向同一地址发送 `POST`，正文为 `{"revision":"<刚读取的模块修订>"}`。服务从任务回执确定工具、读集与执行身份。调用者可以在同一地址重新读取结果。[原工单 #1774](https://github.com/zhzyx/nightmarish-spooky-sorceryze/issues/1774)

复验沿用当前有效的原任务授权、可见性、对象范围和已安装检查。工作台把已保存的可写模块修订与原先准入的只读模块组成候选，再按旧回执的读集选择要执行的检查。每个完成的检查保留候选、模块修订、对象摘要、工具、结论和日志摘要。未变资产继续引用原回执，原阶段结论保留在原候选上。重复请求使用同一任务、候选和检查对应的执行记录。

如果保存与复验交错，客户端会收到修订冲突，可以重新读取对象回执取得最新动作。保存过程中被后续修订取代的检查结果留在原执行记录中。撤销任务授权后，服务拒绝接收正在返回的复验结果。

Windows 实测通过本机 HTTP 服务保存带有 `AnimationPlayer` 的场景，再由 headless Godot 读取动画时长。12 秒改为 17 秒后仅启动 `motion`，原 SVG 造型检查回执保持有效。25 秒样例超过夹具设定的 20 秒上限，失败回执挂在该修订。复跑命令、实测候选及对应结果见[验证记录](../data-collection/gonggong-ai-workbench-plan1-v10.json)。
