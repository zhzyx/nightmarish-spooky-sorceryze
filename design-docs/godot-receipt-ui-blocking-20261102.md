# Godot 聊天回执异步化：消除模型与工具边界的 UI 同步等待

工单：https://github.com/zhzyx/nightmarish-spooky-sorceryze/issues/8

已确认来源：Issue #2 的交付限制指出普通模型/工具边界同步回执可能阻塞 UI 最长约 15 秒；停止和结束投递已异步。这是现有引擎的明确优化项，不重开已完成的模拟验收。

状态：计划中。依赖：先复现当前精确提交；设计与实现可在不同文件责任范围并行，审查保留独立槽。

目标：UI 不被回执等待阻塞，同时保留先持久化、成功回执前不发送模型/工具请求的边界。

验收：
- [ ] 复现等待并记录 UI 响应与时序，禁止把未测延迟填零。
- [ ] 使用异步回执状态机；失败/未知保持明确阻塞，不绕过采集准入。
- [ ] 覆盖等待中取消、迟到回执、重启恢复、连续工具轮、并发去重及失败恢复；真实事件重试只依赖实际业务事件，不增加定时调度。
- [ ] 受影响原生与桥接测试、模拟场景和独立并发审查通过，绑定交付候选。

本单不包含真实供应商账号/付费调用或扩大模型验收范围。

## 已完成的定位

`editor/docks/ai_chat_olympus.cpp` 的 `_record_olympus` 在108行附近仍同步 `OS::execute`；默认 p_flush=true 的模型/工具边界调用会等待。118–172行已有异步flush，不能描述为完全没有异步。下一实现应复用现有异步路径/回执状态机，先记录请求代次与匹配回执，再放行模型/工具；取消、迟到和恢复均需回归。当前只完成代码定位和验收拆解，未修改引擎或声称延迟已改善。
