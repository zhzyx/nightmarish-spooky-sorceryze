# Godot 聊天回执异步化：消除模型与工具边界的 UI 同步等待

工单：https://github.com/zhzyx/nightmarish-spooky-sorceryze/issues/8

已确认来源：Issue #2 的交付限制指出普通模型/工具边界同步回执可能阻塞 UI 最长约 15 秒；停止和结束投递已异步。这是现有引擎的明确优化项，不重开已完成的模拟验收。

状态：计划中。依赖：先复现当前精确提交；设计与实现可在不同文件责任范围并行，审查保留独立槽。

目标：UI 不被回执等待阻塞，同时保留先持久化、成功回执前不发送模型/工具请求的边界。

验收：
- [ ] 复现等待并记录 UI 响应与时序，禁止把未测延迟填零。
- [ ] 使用异步回执状态机；失败/未知保持明确阻塞，不绕过采集准入。
- [ ] 覆盖等待中取消、迟到回执、重启恢复、连续工具轮、并发去重及失败恢复；真实事件重试只依赖实际业务事件，不增加定时调度。
- [ ] 受影响原生与桥接测试、模拟场景和独立并发审查通过，绑定交付候选。

本单不包含真实供应商账号/付费调用或扩大模型验收范围。

## 已完成的定位

`editor/docks/ai_chat_olympus.cpp` 的 `_record_olympus` 在108行附近仍同步 `OS::execute`；默认 p_flush=true 的模型/工具边界调用会等待。118–172行已有异步flush，不能描述为完全没有异步。下一实现应复用现有异步路径/回执状态机，先记录请求代次与匹配回执，再放行模型/工具；取消、迟到和恢复均需回归。当前只完成代码定位和验收拆解，未修改引擎或声称延迟已改善。

## 2026-11-03 实施及实际验证

执行责任：`/root/async_receipts`；本次用户推进当前工作区工单的授权范围，未扩大模型服务范围。状态：实现及本地编译/场景验证完成，等待独立审查与合入门禁。

在每次 flush 注入 0.4 秒延迟的隔离本机模型夹具中，原安装的成功聊天最大 UI 帧间隔为 1.687262 秒。改动后实际编译引擎，同场景为 0.014123 秒；这是当前主机实测，非跨设备性能保证。快速拒绝若不足两个帧采样，延迟标记未知而不填零。

事件先写入持久 outbox，随后启动异步 flush 子进程。模型发送、模型响应处理、工具执行、工具结果处理分别在匹配当前会话代次的成功文件回执后继续。等待期间取消会丢弃续体；迟到回执不能恢复旧请求。上一 flush 开始后新入队的终态或下一轮事件需要新的 flush，不复用旧回执。计时器仅观察已启动业务子进程的完成，不安排业务定时重试。恢复日志在工具结果回执成功后清理。

增量编译成功；12 项原生 AIChat 测试（107 断言）通过。12 个编辑器场景通过：成功、回执等待取消、回执失败保留队列、失败后用户显式重试、连续工具轮、恢复、恢复取消后新请求、恢复拒绝、上下文取消、拒绝、真实已批准框架准入，以及独立审查要求补验的恢复首个回执失败。模型传输始终使用本机模拟服务。回执取消和失败均为零模型请求；显式重试最终只有一次模型请求。既有安装未替换，编译产物尚未发布。

精确代码、编译产物和日志摘要由本轮验收记录保存；独立复核与远程 CI 尚未据此宣称完成。编译源 8,266 项核对中，仅 custom.py 一行注释与仓库不同，有效 Python AST 一致。已保留原安装和三个外部构建源原件。

独立审查补验：恢复流程首次 flush 注入失败，等待迟到终态回执后原 journal 仍存在，无 result_restored 事件、零模型请求，最大帧间隔 0.022336 秒；该故障夹具不改生产代码。
