# 需求沉淀与文档路由维护规范

## 需求

1. 需求类 Issue 的修改在 Git 提交并推送后，应充分压缩为可复用的「需求」和「做法」，写入最匹配的领域子模块；没有匹配子模块时新建子路由并登记父级索引。Bug 修复不执行此沉淀。
2. Bug 与需求的分类以关联 Issue 的类型或标签为首要依据，不仅凭提交信息或代码差异判断。
3. 文档任务开始时，若本地仓库落后于远端，先保留其他在途改动并拉取、回读最新版本；发现相同或相似需求时，明确告知用户现有事项的位置、状态和差异。
4. 最新文档已有同一事项时更新原事项及关联内容，不新增重复条目或平行文件，避免文档持续膨胀。

## 做法

- 在根 `AGENTS.md` 的任务路由中覆盖 Git 交付后的需求沉淀。
- 在工作流模块的子路由中指向文档维护细则。
- 在文档维护细则中统一承载 Issue 分类、提交推送后沉淀、同步查重和原文更新规则，不在父级重复正文。

## 验收

- 根路由能够逐级到达唯一规则正文。
- 非 Bug 需求的沉淀时机、内容压缩方式和无匹配子模块时的处理方法明确。
- Issue 分类依据、同步最新版本、相似需求告知和原事项更新要求明确。
- 变更仅包含本需求文档及上述三处规范文档，并通过文档格式与仓库交付检查。
