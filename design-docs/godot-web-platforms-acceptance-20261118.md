# Godot Web 工作台：双平台交互与生产站点验收

需求 ID：godot-web-platforms-acceptance-20261118。父 Issue：#1454。实际子 Issue：#1474。路径以仓库根解析。

此项保留原需求尚未取得真实回执的验收，不增加 Engine Next 范围，不以源码合入或隐藏窗口测试代替业务验收。macOS 实现由 PR #1459 交付；Windows 实现由 #1462 管理，依赖其精确候选 CI 和 main 接收。

## 原需求映射与验收责任

1. 原 #1454 验收 2：在有权访问的真实 HTTPS 天璇部署中，核对登录、退出、权限与站点支持的持久会话；访问文曲、需求、工单、多宝、搜索、账号与设置，并完成经授权的实际业务流程。macOS 本机完整站点导航和 Windows HTML 夹具不能替代此项。生产写操作仍受操作者实际业务权限和授权范围约束。
2. 原 #1454 验收 3：macOS 和 Windows 的实际显示器上检查中文输入法、键盘焦点、Escape、与场景之间切换，确认网页输入不驱动游戏摄像机；检查缩放、窗口调整、模态窗口及隐藏/恢复。
3. 原 #1454 验收 4、5：检查同源下载、上传选择器、脚本 alert/confirm/prompt 的可见交互；无效地址、加载失败、缺少 Windows WebView2 Runtime 时的诊断及显式恢复。保持旧安装和用户数据，不为测试卸载有效运行时。

业务验收责任人为拥有目标部署与测试账号权限的用户；当前 Codex 会话负责归档证据和修复已复现的范围内缺陷。需要的回执是各系统的实际构建版本、站点来源、逐项通过/失败结果和可复现步骤，不收集密码、令牌或私有业务正文。

## 当前限制与恢复条件

仓库 `customizations/components/godot-host/README.md#静默验证` 明确要求：“碰到只能由真实显示器复现的问题，记录具体缺口，留给用户自行检查。”因此本任务不驱动用户桌面。初始阶段未提供目标站点和有权测试会话；后续站点及现有安装配置已按下方更新，仍缺少可用的已认证测试会话。

已有自动验证覆盖后台编辑器入口、真实 WKWebView/WebView2、页面和存储、导航策略与生命周期。收到用户的实际显示器结果，或有权生产验收者的目标环境及结果后，沿本 Issue 继续复现、修复和复验。未知项不计通过；原父单在整体验收满足前保持开放。不新增定时扫描。

## 2026-11-18 个人 Key 登录失败接续

用户在入口恢复后反馈个人 Key 被拒绝。当前执行者负责 HTTP 与隐藏原生 WebKit 的技术对照，不要求用户自行切换浏览器验证，也不索取或读取个人 Key。HTTP 合成无效 Key 对照返回 401，服务健康检查正常；该结果不能证明用户 Key 已撤销或过期。成功登录与业务验收仍未完成，#1540、#1454、#1474 均保持开放。服务器账号/Key 状态需沿有权管理通道核查；当前 Mac 未具备该通道，不绕过权限或重置用户凭据。详见同一 server-entry 证据。

隐藏原生 WebKit 调用部署页面的实际登录处理器，合成无效 Key 得到 401 与对应错误文案，进程退出 0。该对照验证请求链路，未验证用户 Key、成功 Cookie 或登录后的业务。测试中误选搜索表单的夹具问题已修正并保留原日志，不作为产品缺陷。测试应用与隔离 profile/cache 已清理。
