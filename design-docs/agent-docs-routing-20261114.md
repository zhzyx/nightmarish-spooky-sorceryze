# 模块化 Agent 规范与文档路由

稳定需求 ID：`agent-docs-routing-20261114`。

关联 Issue：[Issue #1082](https://github.com/zhzyx/nightmarish-spooky-sorceryze/issues/1082)。

类别：`type:documentation`。

## 用户目标与授权

用户要求将根 `AGENTS.md` 保持为按需加载的路由入口，把工单、构建、测试、C++、UI 输入命令化等长期规范归入 `Markdown/` 模块，并预留 Gameplay 与 EngineCore 大模块。新增规范必须优先并入既有细则；模块过碎、重叠或总是共同加载时必须合并。用户随后明确确认将改动提交并推送到现有 GitHub 项目的 `main`。

## 范围

- 以最新 `origin/main` 为基线，在独立工作树修改根 `AGENTS.md` 与新增 `Markdown/` 文档。
- 将现有根 `AGENTS.md` 的工作区约束完整迁入工作流子模块，保留冻结框架、权限、门禁、交付和清理边界。
- 汇聚现有贡献指南、C++ 规范、编辑器控制协议、Gameplay 和引擎适配资料；权威正文保留原位置，模块页只提供执行摘要或路由。
- 记录文档与路由的新增、拆分、合并和废弃规则。
- 创建并关联真实 Issue，保存本需求实际事件、验证证据，执行纯文档检查、正式门禁、提交后核验、PR／CI、main 回读及工单收尾。

## 非目标

- 不修改引擎、编辑器、框架、工具或测试代码，不改变运行行为。
- 不批量移动第三方、上游、历史设计或依赖环境文档。
- 不把历史验收记录当作当前状态，不新增定时扫描或平行状态账本。

## 验收条件

- 根 `AGENTS.md` 只承担按需加载、任务路由和模块扩展约束。
- 原根工作区规则均可在 `Markdown/workflow/` 下找到，未因重构丢失。
- 构建、测试、代码规范、编辑器控制、Gameplay、EngineCore 和来源索引均有明确入口。
- 新增规范优先进入既有细则，过碎模块必须合并的规则明确且可执行。
- 所有新增相对 Markdown 链接有效，无旧工作区私有路径、失效路由、尾随空白或未闭合代码围栏。
- 纯文档改动不机械编译引擎；正式门禁、精确候选 CI、main 回读及 Issue 收尾按实际结果完成。

## 验证计划与停止条件

检查变更范围、原规则覆盖、Markdown 相对链接、根路由、代码围栏和尾随空白。候选变化后重跑受影响检查。达到上述文档验收并完成实际交付后停止，不扩展为源码或依赖清理。
