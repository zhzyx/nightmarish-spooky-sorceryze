# 天枢画布与创建需求文本输入性能

需求 ID 为 tianshu-input-memory，关联 [#511](https://github.com/zhzyx/nightmarish-spooky-sorceryze/issues/511)。用户报告天枢画布底部和创建需求正文在打字阶段即可引发卡死，独立 AI Chat 输入正常。

以同一安装的 Windows 图形编辑器、相同工作台的私有副本、原有画板和配置为对照，在独立桌面与有内存上限的进程树内，分别向 AI Chat、画布和需求对话框输入相同文本。另对长草稿反复输入退格、带大附件的历史草稿自动保存、恢复草稿以及画布发送上下文处理做定向回归。保留正常提交、撤销、换行和跨范围草稿语义。记录实际渲染驱动与资源观测，用户原会话未重现的现象保留待核验。

用户追加要求大幅降低刷新频次。自动整板读取间隔从 10 秒延长到 5 分钟，有变更时合并读取，界面隐藏时暂缓。5 分钟内切回已核验的画板不触发新的回读；进度管道读取从每 2 秒一次改为每 15 秒一次，手动刷新与提交操作仍即时执行。

## 已有图卡长段落的输入延迟

同一任务卡追加中文时，连续 11,000 字的一段在 215 像素宽的输入框里会产生数百个软折行。旧实现逐行读取高度及文本范围，每次都会检查整段所有折行是否需要重新排版。批量查询在同一次加锁范围内完成这项检查，再沿用原来的文本服务读取各行。正常输入、显式换行、双向文字、表情和滚动或展开全文均按原有排版处理。

复验使用独立 Windows 桌面上的图形编辑器和工作台副本。对已安装版、同一主线基线和修复版串行提供相同文本及按键，并核对折行文本摘要、尺寸、光标与输入内容；另测 35 秒内连续追加的完成数。输入延迟、帧间隔、静态内存变化与进程树私有提交分开记录。详细数据见 [图卡长段落输入实测](../data-collection/issue511-long-paragraph.json)。整机内存耗尽仍按原报告独立核验。
