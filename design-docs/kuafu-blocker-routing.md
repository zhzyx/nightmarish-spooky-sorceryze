# 夸父按真实阻塞事件接单与复验

用户要求所有阻塞均由夸父介入排查。以 #177/#187、#180/#200、#189 和 #207 为实案。主责为当前 Codex 宿主；当前有效框架的夸父职责和准入继续使用原定义。

验收：任何入口发现用户报告、依赖、权限、构建/提交/CI 或恢复失败时，将实际工单、候选、证据和受影响动作交给夸父；区分发现、接单、判断、上报、源头修复和原任务复验。活跃宿主按真实任务委托装载夸父并记录状态，不伪造消费。针对远端 CI 失败建立事件入口，避免无主事件、重复建单与错误归因。禁止定时扫描或接管他人已签发候选；旧 PR 的未知终态保持开放，按实际修复与发布者交接跟进。验证包含重复事件、非授权输入、失败路由与真实回执。
