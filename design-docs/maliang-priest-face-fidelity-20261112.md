用户实测“人脸细节处理得有点差，和输入相差太远。脸型都变了，且脸颊有明显的建模缺陷”。本次实际生成任务为 `782bf8af-c3a0-4ebd-9910-40a091408611`，仅经过首次三视图生成，没有执行后续模型调整。生成 GLB 的 SHA-256 为 `c6d14c4491540bf4a2d2239ff3a004e77eb05ff09b5989bf5b13c11a3febfe21`，大小 46,391,764 bytes。

原始人脸只保留在私有测试目录，不提交照片、签名 URL、API 原始响应或大模型。公开证据仅记录摘要、几何统计、操作 ID 和可公开的结论。

## 已核实事实

- 原始三视图提供全身正面／右侧／背面，但其有效面部像素无法等同于原始 1280×1280 高清人脸。生成服务对具体脸型和五官的保真度不足，不能仅靠“保留脸型”的文字承诺解决。
- 同一 GLB 已在真实 Godot 渲染器中加载，并拍摄正面、侧面和三分之四近景。脸型偏离参考且面部局部表面／明暗不自然，不能仅归为预览图缩放问题。
- 独立几何统计：1,471,105 triangles；头颈阈值区域 125,878 triangles。`cross(area)^2 == 0` 的严格零面积三角形为 **0**；法线缺失或为近零长度的计数为 **0**。早期 GDScript 阈值初筛只是微小三角形集合，不能据此宣称有 38,817 个破洞。
- 非零微小面积分布：78 个 `<1e-14`、39,039 个 `<1e-12`、其余更多 `<1e-10`。这些微小三角形可能来自高密度五官表面，不能自动等同于几何破洞。面部形态和表面连续性需要结合近景继续验证。
- `texture_3d_model` 的主要用途是材质／外观处理，不保证任意几何修改；用它修复脸型或局部几何缺陷是不合适的承诺。

## 修复策略与边界

1. 保留原始 GLB、原图和诊断证据，不覆盖旧结果，不重复提交相同三视图生成。
2. 使用用户原始高清人脸做一次独立的头部专项 `generate_3d_model` 验证，检查提高有效面部参考分辨率后，脸型与脸颊表面是否改善。新任务与旧任务分开记录，不把新任务称为“模型调整”。
3. 若头部专项结果仍不能保真，明确当前通用 image-to-3D 路线的限制，不把重新贴图包装成几何修复；后续需要可编辑的局部几何修复或专用头部重建路线。
4. 若头部结果改善，再评估头部／身体几何衔接、比例、材质边界和原生近景，未通过前不合并、不替换用户当前角色。
5. 代码或模板变更限于已证实的流程缺口。测试模板继续使用内嵌参考和显式手动运行，不自动消耗模型额度；所有真实结果保留独立文件。
