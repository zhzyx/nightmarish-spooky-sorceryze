# 外部并行工作者的明确修复续办

工单 [#792](https://github.com/zhzyx/nightmarish-spooky-sorceryze/issues/792)。父需求 #773，验收与原生消费者 #776 / #783；已交付来源 #785、PR #788。用户已授权编辑器持续游戏生产、自主迭代与验证，本子项负责已有授权候选上的明确修复执行。当前责任者为本 Codex 宿主，C++ 消费接线仍由 #783 实施者承担。

独立审查判为 fail 时，现 runner 只能回读原终态，不能在保留来源的前提下启动新的修复。新增宿主私有 repairOf 输入，绑定原 execution_id、不可变 terminal_receipt、独立失败审查的回执与宿主生成的续办 ID。修复使用独立持久票据和执行身份，保留原记录；同一失败审查至多创建一次后继执行，重放仅回读。原候选、设计、工单、工作副本或回执漂移，取消、未知运输、非失败审查及来源不足均拒绝。原容量和资源锁、intake、框架校验和报告保持生效，不删除原票据。

构建边界为既有 tools/godot_parallel 宿主工具，不增加原生模块或账号配置；输入为原生宿主匹配实际失败审查后构造的数据。runner 不能单凭磁盘 JSON 证明模型真实身份，原生独立来源由 #783 负责；runner 仍验证内容、摘要和执行来源。回退为恢复原 runner，保留新旧执行回执，旧版本不自动消费 repairOf。

验收：真实临时 Git 和子进程验证正常修复写入、原回执保留、同事件重放不重复启动；不接受漂移回执、未知/取消运输、错误工单/工作副本/身份或伪成功审查；竞争续办仍只一个实际执行且不绕过资源锁。#783 组合验证失败→新修复→新独立审查→下游只启动一次。当前范围不把未知运行自动重新派发，不宣称原业务验收完成。

方法召回 editor-dependency-handoff：bind-consumer-release 与 await-terminal-observers；适用条件是实际生产身份、候选与已落盘观察回执，反例为进程尚未终结、日志终写失败或过期字节。先验证定向行为，再独立复核、正式门禁、精确 CI 与 main 回读。
