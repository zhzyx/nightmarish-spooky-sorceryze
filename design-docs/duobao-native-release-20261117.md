# 多宝独立验收与精确组合发布清单

需求 ID：duobao-native-release-20261117。父目标 #1382 的 P0-C 第二步；依赖 #1386 原生存储和 #1406 输入定址证据，均已验收并合入 main。主责为当前 Codex 会话，现有合契、阎罗与司南分工不变。用户已于 2026-11-17 授权开始实施。

本项把候选接收、检查事实、独立审查、内容发布清单分开，提供无 Git 的可信宿主库。发布只表示原子选定可供消费者获取的精确内容组合；服务安装、消费者确认和线上身份接线由后续 P0-D 实现，不能把本地指针切换描述成线上部署成功。

可信宿主安装产品检查规范与工具链/环境/参数，至少要求一项完整组合检查，避免只有局部检查却宣称整个组合通过。沿用 EvidenceCache 校验精确输入、期限、执行者权限与撤回。检查规范不能由提交请求自行覆盖；未知配置拒绝。独立审查绑定精确候选、规范摘要、全部检查证据 ID、真实责任身份与审查记录。贡献者集合必须由可信宿主从实际来源核对，不能由候选提交者自行声明以绕过独立性；无法取得则拒绝批准。

新增库接口要求显式的宿主身份/操作授权器和贡献者来源解析器，不提供默认放行。批准者必须有权且不在贡献者集合中。批准、撤回、发布均幂等；不得把缓存的 passed 直接当批准。发布时在原子状态变更边界重新检查批准和证据仍有效；并发撤回、最新失败、过期、权限撤销或政策漂移不能留下新有效发布。

每组织、产品/发布通道分别维护选定清单，不建立所有生产者必须追赶的全局 main。清单固定完整模块修订与依赖闭包，跨模块一次切换；仅相同通道使用期望前版条件更新，其他通道及无关模块推进不冲突。回退沿同样授权和有效验收要求重新选择旧内容组合，不能借回退恢复已撤回批准或过期证据。发布记录与事件回执原子保存，消费者读取能核验完整性；记录事件不等于外部已消费。

验收：

1. 无 Git、网络或外部进程完成检查事实→独立审查→精确发布→读取→回退。
2. 未授权、自审、贡献来源未知、缺少完整组合检查或必需证据、失败/未知/过期/撤回/损坏证据均拒绝。
3. 发布重新验证批准/规范/证据；并发撤回与发布有确定的事务先后，撤回先提交时不能发布。
4. 多通道不相互追赶；同通道竞争一方成功、另一方明确冲突；多模块组合一次原子可见。
5. 稳定请求键幂等，重复事件无额外切换；异内容同键拒绝；故障回滚、重启回读和组织隔离留证。
6. 旧组合回退可运行，失效批准不能复活；原记录不被覆盖，始终区分内容选定与消费/部署回执。

placement=host_tool，复用明确绝对路径的原生 SQLite 存储；不改变 NativeStore 已交付语义。新接口放在现有多宝宿主组件，附真实正反例与独立审查；事务内无模型、编译或远程调用，授权回调仅限可信宿主本地判断。回退停用新发布入口并保留数据库。服务器隔离测试后再进行后续线上接线，不删除 Git 历史或切换有效安装。此子项不能关闭父目标，也不承担 AA 渲染验收。
