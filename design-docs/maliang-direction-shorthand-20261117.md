## 原始需求与目标

用户输入：“生成魔兽世界风格人类牧师图，用于生成人物模型，tpose，190身高，脸要我发你的图；要求前、后、左、右、俯视角，同时给出【多视角】脸部特写。”实际两次只得到正面和脸部特写两张。直接调用自动规划函数复现得到“俯视”和“面部细节”，确认方向简写列表没有被识别。

用户进一步明确：“【多视角】面部特写”不是一张，而是正面、左侧面、右侧面三张面部特写。因此原话应规划为 8 张：5 张全身视角加 3 张面部特写。

## 范围与非目标

- 识别由顿号、逗号或斜杠分隔的前、后、左、右、俯、仰方向简写，与已有完整方向词去重并保持需求顺序。
- 将紧邻的“多视角／多角度／多视图＋面部／脸部＋细节／特写”展开为正面、左侧、右侧三个 `detail` 输出。
- 保留单图默认、显式数量、8 张上限、三视图／四视图和同一主图派生契约。
- 主图提示词清理同步识别方向简写列表，避免视角枚举泄漏进主图描述。
- 对左右全身及左右面部特写使用明确的解剖学方向、90° 相机位置和鼻子画面朝向，减少模型把右视图生成成左视图的概率。
- 本单不改动 UI 控件，不恢复手工变体数量，也不声称真实供应商必然准确画出每个指定视角；真实模型视觉一致性不属于提示词单元测试的证明范围。

## 设计方案

在现有完整方向词匹配后补充简写列表扫描，将命中的字符映射为内部规范标签，并按原文位置稳定排序。面部多视角短语替换单个“面部细节”项，依次生成“面部正面特写”“面部左侧特写”“面部右侧特写”。既有执行链继续先成功生成主图，其余视角及特写均以主图为权威引用派生，不独立重新设计人物。

派生请求通过规范标签选择强化后的英文方向指令。左侧明确要求相机位于角色解剖学左侧、显示左脸／左身、鼻子朝画面左；右侧使用完全相反的约束。正面、背面、俯视、仰视和三视角面部特写也使用明确指令，不再只发送一个中文标签。

小修复无需拆分父子 Issue；代码、回归测试、来源事件与验证证据在同一候选交付。

## 依赖及风险

- 沿用现有 Python 解析与多图适配层，不增加第三方运行时依赖。
- 最大输出仍为 8 张，本需求恰好达到上限。
- 自动规划数量正确不等于真实模型视觉结果已验收；实际出图仍需重新构建并重启编辑器后执行。
- 实测旧候选时，左右标签分别正确进入独立子任务，但右视图与左视图均朝画面左；另一次俯视子任务遇到服务 HTTP 424。这两个真实运行观察分别用于提示词增强和故障边界记录，不冒充新提示词的真实视觉验收。
