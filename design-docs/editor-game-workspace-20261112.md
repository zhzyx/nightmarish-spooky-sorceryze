# Godot 普通游戏项目的正式生产工作区

稳定需求 ID：`editor-game-workspace-20261112`。父项 [#773](https://github.com/zhzyx/nightmarish-spooky-sorceryze/issues/773)，授权为用户要求 Godot 编辑器完整支持连接账号后的自主并行游戏生产，以及父项纠正评论。当前根宿主承担交付与父级验收，实际实现通过司南派发。

## 问题与范围

现有工作流偏向引擎仓库：普通外部游戏项目跳过引擎候选，但工单、准备和 runner 仍依赖该工作区内的宿主和框架路径；成果接入正确要求源和目标属于同一 Git 仓库，因此外部游戏项目不能仅靠改路径完成生产。

区分可信宿主安装根、用户游戏仓库根、实际项目子目录、独立生产副本。通过正常编辑器入口接入游戏仓库，工单、设计、候选、并行准备与验收均绑定该游戏仓库，宿主实现从可信安装加载。沿现有部署/数据适配能力实现，不能复制引擎源码进游戏项目、删除同仓库保护、绕过权限/独立验收或让候选脚本成为可信宿主。

普通 Git 项目为首个可独立交付范围；未初始化 Git 的项目须明确显示当前条件和可执行接入路径，不能静默把任务写回引擎仓库。涉及初始化或远端配置只使用正常真实用户授权，不创建无关远端仓库。保持引擎自迭代入口兼容。

## 验收与依赖

- 安装 A 与游戏仓库 B 分离，游戏位于 B 根或子目录均能从正常入口形成游戏工作区绑定、需求和可回读候选。
- 已有 GitHub 身份/权限和工单关联按 B 的真实来源核对；缺少条件给出明确恢复入口，不借用 A 的工单权限。
- 组合 #810 自动准备和 #811 成果接入，在 B 内完成两个独立任务、独立验收、整合、运行及回滚；A 的源码与用户设置不被当作生产目标。
- 路径漂移、不同项目/仓库、无权限、链接越界、旧候选、未知占用及未初始化项目有真实负例，保留用户修改。
- 独立审查、适用自动化与原生静默验证、构建边界证据、正式 main 交付。真实供应商和最终安装组合验收仍归 #773。

本项与任务级编辑操作授权可隔离实现。正常并行组合验收依赖 #810/#811；可先完成工作区绑定和宿主/数据边界。新增模块按现有构建边界记录实际输入、宿主接口和回退方式；冻结框架原件不修改。


## 实现契约与当前验证范围

可信宿主从实际编辑器安装定位。原生公开 `get_production_workspace()` 与 `get_installed_host_root()`，天枢的仓库、身份与缓存作用域采用前者，board/bridge/模型 CLI 适配器采用后者。外部项目沿项目目录向上寻找 `.git`，因此仓库根和子目录使用同一数据源；无 Git 时保留当前项目并明确报告恢复条件，不退回引擎仓库。已明确绑定的引擎候选与隔离子工作者保留原有绑定。

首次真实游戏仓库连接只创建 `work-items.json`、标签定义和谛听 dataset 清单。路径均相对游戏 Git 根；初始化前核对已提交 HEAD、GitHub origin、当前账号与目标仓库写权限，并预检文件与链接；不覆盖用户配置。不复制框架、引擎、工具或凭据。远程标签仅在用户确认的工单发布流程确保存在。后续 intake 仍实时核对该仓库来源、权限和精确 Issue。

普通 bridge、工作单适配器、框架与并行 runner 的 intake/框架核验均从安装加载；游戏候选不能提供验证代码或附带 Node/Git 可执行文件。候选、设计和回执继续绑定游戏工作树。#811 同一 Git common-dir、候选当前性和独立验收约束保持不变。

构建边界：`ai_chat_dock.*`、`ai_chat_engine_candidate.cpp`、`ai_chat_gonggong.cpp`、`ai_chat_host_runtime.h`、`ai_chat_sub_agents.cpp` 与 `gonggong_panel.cpp` 是原生输入；`editor/SCsub` 将 `daqian/workspace.gd` 编入 `daqian_scripts.gen.h`，board.py 编入旧版兼容 `daqian_board.gen.h`。桌面独立 UI 包只包含 graph_layout/issue_graph，本次未修改这些包。Python/Node 宿主工具由安装独立加载；更新与回退须带匹配的安装工具与原生生成输入，不能靠替换游戏数据升级宿主。

自动化使用真实独立 Git 游戏仓库，GitHub/model authority responses 明确为受控试验。47 项并行生命周期测试包含八项实际安装端候选门禁验证；框架文件、指针、锁文件及已提交/未提交删除均在工作者启动前拒绝，普通无框架游戏可运行。原生 root/subdirectory 探针验证绑定及进程结束。

组合 #810/#811 的普通游戏原生试验已从正常设置入口完成两个独立任务、两名独立审查者、成果 list/plan/apply、实际游戏运行和 rollback。游戏仓库不含框架或引擎源码，安装宿主单独提供工具。试验暴露并修复 Windows 预检误找游戏内工具、普通游戏审查误要求引擎标记的问题；游戏放宽只来自实时宿主审查上下文，默认引擎检查及冷启动拒绝仍保留。严格 Windows 构建、完整原生测试和实际 Git 分支/common-dir/基线漂移负例通过。

受控模型、GitHub 与 issue-agent/chat/flush 运输不能证明真实供应商或首次远端工单发布；普通游戏冷重启后的整合、真实账号组合与最终安装更新/回退仍须父项继续实测。正式 main 交付另核对精确候选 CI 与远端回执。

## 普通游戏冷启动实测补充

最终格式化测试通过真实正常准备、两个生产者／两个审查者、整合、实际运行后退出，再用同一私有编辑器重新启动。显式恢复请求前 journal 字节不变，两个恢复生产者均不具备 live acceptance，新的 plan/apply 被拒绝；明确 rollback 使用原 plan_sha256 并实际移除产物。独立核查及证据见 `data-collection/editor-game-workspace-821-cold.json`（本仓库根基准）。此前未测冷启动的限制由此限定范围实测替代；供应商、最终安装及父项仍未验收。
