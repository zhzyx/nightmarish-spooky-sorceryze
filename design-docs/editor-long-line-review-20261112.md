# 编辑器长行证据读取

父项 [#773](https://github.com/zhzyx/nightmarish-spooky-sorceryze/issues/773)，子项 [#886](https://github.com/zhzyx/nightmarish-spooky-sorceryze/issues/886)，需求 ID `editor-long-line-review-20261112`。当前责任者按原用户授权接续真实生产验收中发现的读取缺口。

独立只读审查需要读取原始执行 JSONL；现有完整文件和按行读取受 256 KiB 输出上限约束。单行超限时，减少行数仍无法得到必要证据。保留原件，增加既有 read_file/read_script 的明确分片参数，限制扫描与返回大小，报告真实片段范围、总长度、后续位置和节选状态。UTF-8 多字节不能被截断或伪造；不混合行范围与分片参数。

原生输入为 ai_chat_tools、工具声明和实际 dispatch/receipt 消费者。此为现有原生模块变更，须严格重编对应编辑器；无独立包或热替换模块。回退使用前一已验证二进制及对应宿主，保留所有原始日志和读取回执。

宿主仍在每次实际读取时计算完整原始字节摘要，记录分片模式及范围；候选/身份/父会话/辅助来源权限沿既有路径核对。片段不能被宣称为全文；辅助执行日志不能通过新参数变为候选业务证据。此单不改验收 unknown 分类、预算、依赖释放或历史回执。

验收包括超长单行 JSONL、分片拼接、中文/emoji、空文件与末尾、无效编码/NUL、范围冲突和超限、文件变化，以及原有完整/行范围兼容；实际原生独立审查分片读取与完整摘要绑定。由独立责任者审查，根会话整合后执行严格构建、适用原生回归、正式门禁、精确候选 CI/main 及父项真实流程复验。实际证据按完成事件追加。

实现使用 `char_offset/char_limit`，零基 Unicode 字符，默认 16384、最大 32768；返回 `has_more`、`next_char_offset`、实际长度和全文长度。`truncated` 表示非全文，只有 `has_more` 为真才继续读取，避免末段/EOF 循环。完整源摘要与原有候选/辅助回执路径不变。
