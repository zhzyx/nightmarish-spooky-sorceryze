# 本地模型来源与显式验证

<!-- gonggong-request:local-model-runtime-provenance-20261113 -->

关联 Issue #997，父需求 #978。路径以本仓库根为基准。

## 复盘与行为

个人模型库原先永久优先使用 `models_cache.json`，已登记 CLI 的 live 证明未绑定运行环境；切换 `CODEX_HOME` 或移除 CLI 后仍可能显示可用。显式“连接并验证”会复用旧证明，编辑器 API 密钥变化也可能仍验证第一次保存的副本。外层 Python 超时只停止桥接进程，可能遗留 CLI 子孙；HTTP 非对象 JSON 则可能逃逸可恢复错误边界。

修复将 Codex 目录读取交给编辑器已有 `models` 桥接，不读取外部目录缓存、不另行维护 `codex debug models` 路径。目录只提供候选，实际挑战回复才证明该请求的文本能力。[官方 app-server 文档](https://learn.chatgpt.com/docs/app-server)定义 `model/list` 的目录与推理参数；[官方认证接入说明](https://developers.openai.com/siwc/token-sharing-open-source/codex-app-server)也明确目录可能来自客户端缓存，不能当作授权验收。

CLI 配置增加不可逆来源摘要，绑定实际 Node/CLI/桥接文件元数据、有效运行环境及登录配置文件元数据。摘要不包含可读取的凭据内容；不读取认证文件正文。运行源改变或文件缺失时，历史配置仍保留，旧 live 证明退出可用候选；调用前和验证写入时再次核对来源，拒绝晚到的旧证明。每次发现同时维护目录活跃代次：移除候选立即撤销 live 证明，保留历史；候选重现产生新代次，旧调用和验证结果不能使其重新可用。

显式连接验证每次发送新的挑战，不跳过实测。当前编辑器 API 连接在同一明确动作下更新本机凭据，再验证当前密钥；没有当前密钥时不回退到旧副本。普通发现继续保留首次导入边界，不覆盖其他独立保存的供应商配置。沿用凭据 pending/ready 修订与比较写入保护，避免并发保存或迟到回复恢复旧证明。

Python 为每次桥接创建独占进程边界：POSIX 独立进程组，Windows 复用已存在的 `editor_provenance_process.WindowsJob`，进程在恢复执行前进入 Job。读取有大小上限的终态 JSON 行，成功、失败、超时和中断均清理自己的树。models 协议承接已合入的 #992；chat 同样发送换行终态并保持桥接进程身份至宿主清理。真实桥接离线 fixture 已覆盖两种 CLI 的 models/chat 成功、错误与超时共 12 个分支，不依赖账号或真实推理。

## 验证与边界

回归覆盖旧缓存、换 HOME/环境凭据/登录文件、CLI 缺失、验证过程中来源改变、失败重试撤销旧文本证明、当前 API 密钥变化、空密钥不回退、凭据并发修订和畸形 HTTP JSON。真实本机进程测试创建忽略 SIGTERM 的 CLI 与孙进程，验证终态、超时、错误、畸形及超量输出后的树清理，并保留无关进程。

元数据与环境变更检测不是账号授权证明；外部系统凭据库在原路径下变更且不更新文件时，不能声称自动检测。显式验证会重新实测；真实供应商账号、Windows Job 现场运行及 #971 的会话/节点选择仍需分别核对。未替换用户正在使用的编辑器或全局运行配置。最终证据、独立审查、CI 与主线回读待候选完成后追加。
