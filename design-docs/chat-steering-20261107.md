# 执行中的连续对话

用户要求引擎对话保持 Codex 的执行中追加指令体验，并兼容大千与共工。授权来源：2026-11-07 当前 Codex 用户对话「嗯那落地一下」。

产物：共享 AI Chat 会话支持在执行中接收补充消息，在下一安全边界应用到同一任务，不逐条另起任务；保持原快照、执行代际、工单身份及权限。大千复用该入口。引导、环境配置、操作确认与恢复有自己的路由，不把输入混入另一个任务。现有 API、Codex CLI、CodeBuddy 后端按其实际能力处理，不宣称已在执行的操作能撤销。停止/失败/重启后未应用输入保留且暂停，不自动重放。

目标平台：macOS arm64 当前编译器。必要验收：多条补充、旧动作失效、工具结果顺序、只咨询边界、大千绑定、引导及恢复、停止/失败/历史保存、后台候选构建与相关回归。源码实现与独立审查完成后按仓库正式门禁交付，不切换未经验证的引擎。

执行中补充采用 continuation-only 范围核对：已有工单绑定保持不变；若需求模型判断为独立任务，在任何远端发布前暂停，提示用户通过新任务入口办理。大千 direct 路径继续以原 Issue/request 与推进回执精确回读，不自动建单或换单。

## 实现与验收

关联工单：https://github.com/zhzyx/nightmarish-spooky-sorceryze/issues/381；稳定需求 ID：chat-steering-20261107。

默认执行中同模式输入补充当前任务，在模型响应、工具步骤或确认边界应用，保留原快照与执行代际。原目标与全部补充共同进入范围复核，大千直连工单同样适用。续办只允许保留原工单；模型判定独立需求时暂停，不发布或换单。模型调用期间收到的新要求不会执行旧工具提案。尚未执行的审批提案失效；已运行的操作不自动撤销。当前 Codex 使用 exec 桥接，在宿主边界恢复上下文，不宣称使用 app-server turn/steer。

CodeBuddy 使用同一桥接进程内的 reset 协议，在工具让出或完成边界清理旧命令和原生进程，取得真实关闭回执后恢复完整上下文；旧实例回调隔离。咨询模式切换仍为独立任务；停止、失败和重启保留未应用消息并暂停。
