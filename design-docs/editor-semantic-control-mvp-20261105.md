# Godot 编辑器 AI 语义控制与单目标引导 MVP

<!-- gonggong-request:editor-semantic-control-mvp-20261105 -->

## 原始需求与目标

用户希望在 Godot 编辑器内通过对话要求 AI“配置某项设置、打开某个界面、定位或高亮某个界面”，并确认按语义控制桥、编辑器状态读取和引导高亮层的方案实施；整体分两个阶段、两个独立 Issue 落地。

本阶段交付最小可用闭环：模型不依赖屏幕坐标，而是调用受宿主管理的结构化编辑器能力；宿主返回明确结果，并可在编辑器界面上高亮一个稳定语义目标。

## 范围

- 在现有 AI Chat 原生工具协议内增加只读编辑器状态查询，至少返回当前主界面、编辑场景、选中节点、当前脚本、运行状态、未保存状态及当前引导状态。
- 增加结构化编辑器动作工具，首批覆盖：
  - 打开 Project Settings 并定位类别或设置；
  - 打开 Editor Settings 并定位分区；
  - 切换 2D、3D、Script、AssetLib、AI Chat 主界面；
  - 打开场景；
  - 打开脚本并定位行列；
  - 选择当前编辑场景内节点并在 Inspector 中检查；
  - 设置或清除单个 Project Setting，并保存到 `project.godot`；修改必须走现有用户确认/自动执行授权边界，并提供可核对的旧值、新值和保存结果。
- 增加编辑器级鼠标穿透高亮层，支持单个目标的脉冲边框和简短提示；窗口缩放、Dock 布局变化和目标移动后继续跟随。
- 首批稳定语义目标至少包括 Scene Tree、Inspector、FileSystem、主界面切换栏、Project Settings、Editor Settings；无法解析的目标返回候选和错误，不退化为坐标点击。
- 为 HTTP/OpenAI 工具调用及原生 Codex host action 提供一致能力；工具权限关闭和“仅咨询”模式必须拒绝写操作，引导高亮可视为有界 UI 动作但仍要求本地工具权限。
- 增加原生单元/场景测试及 Windows 增量编辑器构建验证。

## 非目标

- 不实现多步骤教程、步骤持久化、用户点击完成检测或插件动态注册；这些进入第二阶段。
- 不使用操作系统级鼠标/键盘模拟，不控制编辑器外的原生文件对话框。
- 不允许模型执行任意 GDScript 来绕过能力白名单。
- 不修改共工共同框架、冻结纲领、工单门禁或权限规则。
- 不默认覆盖 Windows 之外平台，不发布安装包，不把模拟模型验证称为真实供应商验收。

## 安全与行为约束

- 只读状态查询不触发修改；写设置必须展示动作摘要并复用现有确认机制。用户拒绝后不得自动重试。
- 设置路径必须是当前 ProjectSettings 中已存在或明确允许创建的合法名称；保存失败时恢复内存旧值并返回失败，不宣称已配置。
- 场景、脚本和节点目标必须限制在当前项目及当前编辑场景语义范围内；路径失效、类型不匹配或目标不可见时明确失败。
- 高亮层 `mouse_filter=IGNORE`，不能截获点击；停止对话、切换会话、销毁 Dock 或显式清除后必须移除高亮。
- 工具结果是权威宿主元数据；模型只能根据成功结果陈述已完成动作。

## 验收标准

- [ ] “打开 Project Settings 的 Display/Window”能打开对应对话框并定位类别，返回稳定目标和可见状态。
- [ ] “把窗口 viewport width 配成测试值”弹出确认（或在用户已开启自动执行时直接执行），保存后回读新值；拒绝、保存失败和清除设置都有覆盖。
- [ ] 可切换主界面、打开脚本到指定行、打开场景、选择节点，错误路径不产生半完成状态。
- [ ] `get_editor_state` 返回有界 JSON，字段与编辑器实际状态一致；无场景/无脚本时使用空值而非伪造默认值。
- [ ] 对 Scene Tree、Inspector、FileSystem 及设置对话框显示鼠标穿透高亮，目标移动后跟随，清除后无残留。
- [ ] HTTP/OpenAI 和原生 Codex 两条通道均能发现和调用能力；权限关闭、仅咨询和未知动作按契约拒绝。
- [ ] 相关原生测试、编辑器场景测试、格式检查和 Windows 增量编辑器构建通过；未覆盖项按实际记录。

## 执行范围与停止条件

产物限定为 `editor/docks/` 下 AI Chat 编辑器控制实现、必要的编辑器公共只读访问点、对应 `tests/editor/` 场景/夹具及本需求文档和真实回执。目标平台为当前 Windows x86_64 MSVC 编辑器；优先单对象/增量构建，再运行受影响测试。达到上述验收并形成可安装候选即停止，不扩展到第二阶段能力。

## 实现与交付范围

本地源码候选新增 `AIChatEditorControl`，AI Chat 提供 `get_editor_state` 和 `editor_action`。HTTP 与原生 Codex 共用结构化 schema、宿主执行和确认；不向尚无相应原生终端适配的 CodeBuddy ACP 宣传这两项能力。六个固定目标为 `scene_tree`、`inspector`、`filesystem`、`main_screen_tabs`、`project_settings`、`editor_settings`。目标隐藏时返回错误与候选，不自动点击；同一高亮随布局/窗口变化更新，停止、切换会话/后端和 Dock 销毁清理。

设置写入先校验已存在名称与类型；JSON 数字需有限、整数且在明确范围内才转整数。确认预览包含旧值、新值与清除后的有效默认值；确认时再次检查旧值。磁盘内容从同一快照解析并复用已有写前比较、备份和回读实现，成功后更新内存；清除内建设置仅删除持久覆盖，内存恢复默认值。失败不删除内存设置容器，所以默认值、顺序和标志保持原状。

本次交付为源码与本机 Windows MSVC 构建/验证证据，供协调者串行推送和 PR 审查；不发布安装包，不切换有效安装。原生 Codex 验证限定工具发现、结构化提案转换及权限拒绝协议；无已证明可用的真实供应商入口，真实模型验收为未运行，不能标作通过。
