# 3D 编辑器内的天枢生产工作台

需求 ID：`tianshu-3d-workbench-20261112`。来源：当前用户明确要求在 3D 编辑器接入天枢缩略界面，能交互、借聊天布置 AI 任务，并在选择模型后显示正在工作的 Issue 和关联制作内容。当前 Codex 会话负责实现、验证和交付。路径以仓库根解析。

产物：3D 视图内可收起的紧凑天枢入口；复用现有天枢工单与聊天能力；选择模型后的资产上下文、显式工单关联和相关制作内容。项目资产按场景/资源路径识别，不按模型名称猜测关联。没有关联、离线、数据过期和多选应有明确状态；切换选择不得提交到旧模型。既有聊天权限和工单执行门禁继续生效。

验收：
1. 3D 编辑界面内可以展开/收起天枢面板，视口仍可使用，切换主屏幕无布局/会话丢失。
2. 面板使用天枢真实工单数据，可打开详情及聊天布置任务，携带明确选中模型上下文；无配置时说明实际缺口。
3. 单选模型显示资产标识、显式关联 Issue、真实状态和制作内容/产物引用；取消选择/多选/删除/换场景及时失效，不能显示成其他模型的数据。
4. 关联可持久化，重开可回读；未关联/无产物不伪造进行中内容；实际工具执行沿既有权限与门禁。
5. 候选后台原生验证、独立审查、正式工单门禁、PR/CI、main 回读及验收工单收尾。

平台：当前 macOS arm64 工作区，C++ 原生宿主与 GDScript 界面。复用已有模块，按实际消费者确定构建输入；workspace.gd 为内嵌脚本，不能用仅替换图布局运行包冒充新行为。召回 `godot-build-placement/trace-native-consumer` revision 9，适用原生/生成输入追踪，历史 Windows 结果不代替本机测试。

长期目标为支持 3A 游戏生产。本单交付编辑器生产协作入口，不将入口完成等同整款 3A 游戏产能、内容质量或全资产管线验收。未完成验收保持开放并记录实际依赖。

基线：`34cd08867`。隔离工作树，保留其他工作树与未跟踪文件。初始宿主问题：默认 PATH 未包含已安装 gh，沙箱阻止 Git 元数据写入和 GitHub 网络；已通过明确工具路径与授权提升回读最新主线和本人 WRITE 权限，未修改权限规则。

## 实现与已验证边界

工单 [#813](https://github.com/zhzyx/nightmarish-spooky-sorceryze/issues/813)。3D 菜单新增「天枢」，展开紧凑右侧面板；不移动既有天枢工作区。选中已保存场景内单个 Node3D 后，按导入场景/独立 mesh 路径或场景内节点路径确定资产；多选、删除、换场景和账号切换会撤销旧视图。关联与制作内容通过「关联与内容…」显式登记，项目文件 `res://.gonggong/asset-work.json` 按仓库和资产隔离；导入模型的多个实例共享源资产关联，内建节点重命名后需重新关联。文件锁与内容修订检查避免覆盖其他写入；失败保留原内容。

工单聊天复用原生聊天挂载；新任务把模型/场景/节点上下文放入草稿，由用户填写任务并发送，沿既有建单、权限与执行通道。已存在草稿、附件或队列时不会覆盖。建单回执绑定原资产，登记关注并刷新天枢；通过 Issue URL 可重开原会话。展开/收起不取消在途执行。手工登记的内容路径分别标记文件存在或待制作，不等同完成或验收。

实际后台回归、输入摘要与独立审查见 `data-collection/tianshu-3d-workbench-813.json`。测试使用隔离账号/工单数据及受控权限回读，不向真实模型服务发送需求、不创建测试生产工单。静态审查发现并修复来源别名、建单后关注刷新和并发保存提示；原生测试覆盖修复路径。初始化/退出诊断与未覆盖的像素、缩放、其他平台范围在证据中单列。

初次 intake 缺少 `--tenant` 的调用故障由夸父 #814 接收；加上 `--tenant gonggong-workspace` 后原工单回读成功，已记录处置与上报。该故障不修改产品权限或门禁。

最终本机候选启用 Metal 与 OpenGL，已通过同一原生业务回归及独立进程重开检查；二进制和测试摘要见证据。当前正在运行的旧编辑器不被覆盖或重启，新界面需要在新版编辑器启动后使用。验收采用 headless 几何与控件信号，不冒充像素视觉验收。生产聊天的真实模型执行、内容质量与完整 3A 管线继续按具体任务单验收。
