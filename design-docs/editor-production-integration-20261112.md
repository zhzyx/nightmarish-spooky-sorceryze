# Godot 编辑器接入已验收生产成果

稳定需求 ID：`editor-production-integration-20261112`。父项 [#773](https://github.com/zhzyx/nightmarish-spooky-sorceryze/issues/773)，设计条款为父设计“成果进入当前项目、导入、运行、诊断与修复”。授权为用户要求 Godot 编辑器完整支持游戏生产及父项纠正评论。当前 Codex 根宿主负责实现；父项负责最终组合与真实账号验收。

## 范围与行为

把独立副本中已通过当前独立验收的项目成果，沿编辑器正式工具/交互入口接入当前项目，返回逐文件结果及可回读整合状态，然后可使用现有导入、运行和诊断工具继续原需求。复用原生验收身份、实际候选与终态核对，运输结束或生产者自述不能授权整合。

只接入明确项目范围内的增删改，绑定共同基线、源候选摘要和目标当前值。拒绝路径越界、链接、未保存场景冲突、目标并发变化、来源漂移和未独立验收。已知冲突返回可处理清单；不能直接覆盖用户修改或整树复制。写入前保存恢复信息；失败中断保留准确状态和恢复入口，不能留下未知半写入并声称完成。保留来源、原始独立验收及整合回执，不更改上游副本。

## 独立验收

- 从正常编辑器会话获得已验收生产项，发现实际项目范围并计划/执行整合；成功后当前项目资源、导入及运行读取新产物。
- 不依赖根 Codex 会话手工复制文件、私有游戏脚本或测试猴子补丁。
- 无验收/过期验收、来源变化、目标变化、重复执行、取消、链接越界及未保存场景冲突均有真实负例；未知不记成功。
- 可复用于不同项目和后续生产批次，文件删除、二进制资产及已有用户修改保留正确行为。
- 独立审查、隔离测试及原生静默验证、严格编译、正式 main 交付；父项负责已连接账号的完整生产→整合→运行→修复实测。

## 构建与交付

原生宿主接线属于 native；验收与整合文件处理复用现有 host_tool 边界。记录真实调用接口、输入摘要和回退方式。保持其他工作树、生产编辑器及有效安装不变，直到新候选验证通过。与配置子项独立实现；共同调度接线由根宿主整合。不会替代 Git 发布门禁，也不自动宣称整个父目标完成。

原生 `integrate_production_result` 提供 list/plan/apply/rollback；模型只选生产项，宿主从实际独立验收上下文选源，按当前打开项目解析目标。来源与目标须属于同一 Git common directory。计划上限为 512 文件、前后原始内容合计 64 MiB；冲突不覆盖。Node 文件事务和 Python 当前身份/Issue 回读由已安装宿主执行；新计时器持续观察真实终态，不依赖 API 聊天的帧轮询。回滚绑定在写入前持久化到会话历史及不可变文件，冷启动只恢复显式回滚，不重启生产或重新授权 apply。

Windows helper 验证覆盖换行、固定未提交快照基线、取消、漂移、二进制、路径边界和进程崩溃；写入所有权用 Git ref CAS 避免过期锁竞争。原生隔离场景执行并行生产、独立验收、当前项目接入、退出/重启及显式回滚。受控 GitHub/模型响应不证明真实供应商能力；父项继续承担真实账号组合流程与最终安装验收。原始失败与复验见 `data-collection/editor-production-integration-811.json`，其路径以仓库根解析。
