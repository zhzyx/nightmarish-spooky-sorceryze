# 原生模型提案与真实用量观察

需求 ID：native-model-proposal-20261118，父 #1444；原始用户要求完整 AI 原生链路节约 token/时间，授权继续开发并实测。路径基准为仓库根。

当前 NativeWorker 只有普通命令执行，终态 usage/provider_model 为 null；已安装 subscription_session 通道能安全运行只读提案，但未持久采集实际用量。新增独立宿主组件复用现有 start/turn 与身份、上下文约束，不修改 #951 控制器或现有 transport。既有 Sinan 路由及原有角色继续负责生产选择与独立验收。

1. 在已有 sinan-workorders host_tool 内新增模型提案组件。可信宿主提供确切 CLI/Python/模型配置和固定任务、输入摘要、允许修改对象、验收与上下文。模型只接收有界文本并返回严格结构化提案，无原生工具、网络工具、MCP、直接写工作区或审批能力。请求数据不能选择 executable、环境、凭据或宿主路径。
2. 包装现有 subscription_session.start/turn 公共接口，保留全部原通知与上下文约束；不改现有实现。新 observer 按实际 threadId/turnId 绑定提前/重复/迟到通知，保存原始 last/total 和来源摘要。未证明的归属、缺失、异常、断线、模型名保持 unknown/null；不把文本字节当token、不累计重复通知、不自动补发模型调用。
3. 请求和回执分别绑定任务、输入、输出、配置与调用标识；记录请求模型和真实观察模型的区别、实际耗时、调用状态及有限的用量信息。凭据、账户身份、完整模型思维链不得写入公开回执；模型输出不是审批或可信物理终态。
4. 复用 installed owned_process 持有整个 node/app-server 子进程树，验证取消/超时/断线后没有遗留生产者；只调用 child.kill 不算完整进程关闭。生产信任边界、当前包装器能力评测与正式 live-profile/签名grant准入分开，不凭本地可调用宣布生产模型已准入。
5. 独立测试覆盖早到、重复、错thread/turn、迟到、缺失、负数/错误类型、关闭及上下文重建，用已有真实schema做契约参考；实际模型试验由根责任者在当前授权、已验证安装与明确输入/质量约束下执行并记录原始报告用量，不冒充全链路收益。
6. 当前交付只提供可信宿主调用的提案与独立用量回执，保持 NativeWorker 既有终态语义；其后接入固定输入生产和等任务 A/B。不得从包名、schema模拟或一次小任务声称250模型并发、完整远端执行、AA渲染或父目标完成。

新增实现为 host_tool，声明实际输入是固定任务/已安装CLI协议及宿主授权配置，输出是有界提案/观察回执；原生渲染不依赖本组件。完成实际SCons消费与缓存边界、独立审查、适用CI、main留底。回退停用新入口并保留已发生调用回执，不重发未知模型调用。
