## 设计定版确认

保护目标由已验证候选绑定的 request、tenant 与仓库根派生，不从 shell 命令拼写推断授权。活跃需求文档可以正常补充内容；活跃事件及待送回执保持不可篡改，来源文件及必要父目录不可被命令删除、改名或藏走。普通源码的 selective stash、stage、commit 与合并继续可用，系统上下文提供排除活跃来源的操作约束。

macOS 复用已有命令进程写策略，从文件和目录层阻止来源丢失，保留其他工作树写保护。命令执行前后核对活跃来源；跨平台后验检查仅从可信执行前副本恢复已证明丢失的文件，不覆盖未知内容冲突，发生恢复或冲突时返回准确失败。待送 outbox 合法消费不能误报：只有原 pending 保留，或同一完整事件已经规范化持久存储时才视为保留来源；不把返回字段或命令退出0当作事件存在的证明。

直接命令与原生 ACP terminal 使用同一保护约定；原生 approval 不算实际执行结果。停止或重启边界保留私有恢复记录，不能在未核对来源时继续框架回执。普通需求文档内容编辑与新证据创建仍可用。宿主自己的框架 flush 保留现有职责，不自动伪造记录或成功回执。

取消由宿主生成的独立标记交给保护进程，先清理其实际命令及子进程，再核对来源。POSIX 清理已归属进程组的非僵尸成员；Windows 在主线程仍挂起时归属私有 Job，成功后才恢复执行，Job 关闭即结束所属子孙，归属失败准确拒绝。已有活跃执行不能掩盖其他待恢复记录的冲突。直接文件写入先解析真实目标并核对路径，别名及大小写不能绕过来源或其他工作树保护。

命令结束不等于 pending 已消费。已知来源另存每工单私有检查点，直到完整事件通过真实存储适配器核验才删除待送副本；框架投递前重新检查，迟到删除或重启后来源缺失仍可按原始字节恢复。允许设计内容正常更新，检查点保留最近已核对内容，不覆盖未知冲突，也不重放命令。POSIX 显式脱离会话的守护进程不被误认作已清理，持续来源检查承担其后续保护；不宣称任意 shell 是安全隔离边界。

真实 Windows CI 在保护器集成用例中发现前置候选登记比较失败：Git 输出正斜杠路径，Windows Path 使用反斜杠；原逐行文本比较还会误读 Git 的非 ASCII 路径引用。沿用 #390 的身份与归属校验，登记与保护根改读 NUL 分隔原始路径并按平台规范 Path 比较；未登记、来源或归属不匹配仍拒绝。macOS 的即时保护根读取保留 UTF-8 并校验解码后的真实目录，中文／空格原生完整循环验证；此处不增加租户标识支持范围。
