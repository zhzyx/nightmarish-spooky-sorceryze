## 后续推进规则

每次接续选定一个里程碑或其中可独立交付的子项，开始前固定本轮产物、验收、依赖和退出条件。阶段通过即提交、推送、核验 CI/main 并汇报；不因阶段完成而宣布全平台完成，也不在收尾时扩展到未选定的新实现。

并行限于真实可用槽位和隔离写入范围。交接记录下一条可执行动作、实际运行句柄或具体阻塞；模型状态为运行中不代表已有测试或部署进程。中断后先回读宿主状态及外部副作用，使用恢复入口接续，普通消息不能替代启动。只在真实事件时协调，不新增定时扫描。

同一候选复用有效证据；只审查改动和关联风险。纯文档／证据归档沿现有 tier0 门禁，不额外组织代码独立审查。提交前一次核对完整候选的廉价静态检查、清单和证据字段，减少签发后的重复往返。浏览器测试保留可复用脚本和环境输入至父阶段接收，凭据不入库。

所有新增验收任务使用隔离数据。未结历史 Godot 工单不执行、不改变业务验收或关闭状态；不做双向同步，新任务仍可按项目选择是否进入天璇。

- UI：真实浏览器回退通过；未滚动复拍证明标题未被遮挡。版本历史长 ID 和控件样式待 M1 修正，当前没有已验证的视觉补丁。
- 资源：保留有效独立 Windows 安装、上一版 8 文件回退、生产原根盘树及必要镜像、未交付草稿和原始回执。本轮新增归档工作树与分支在 main 回读后清理。此前自动审批拒绝清理的临时对象仍保留，不绕过拒绝或宣称清理完成。

恢复时，仓库相对路径按所在工作树根解析；机器专用路径与私有回执在本机阶段交接中解析，不把它们当作可移植安装配置。未设置承诺日期或推测完成百分比。
