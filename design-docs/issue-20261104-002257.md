工单：https://github.com/zhzyx/nightmarish-spooky-sorceryze/issues/32

原始需求：发送左边增加默认关闭的“仅咨询”复选框；开启后仅阅读代码、回答问题，无修改代码/文件权限，不经过 Issue 监控。

本轮由 Codex 子任务实施，独立审查由另一实例执行。产物是原生 UI、消息队列模式、实际工具执行白名单和原生行为夹具。平台仅 Windows MSVC 单编辑器；不扩展模板或其他平台。本轮 API 后端支持咨询；原生 CLI/ACP 存在独立写入和终端通道，咨询模式明确拒绝启动该后端，用户可切换 API 后继续队列。未声称所有后端已支持。

每条消息发送时固定模式，改变下一条消息复选框不升级当前轮权限。咨询工具只开放 read_file/read_script/read_logs/list_scripts/list_directory，所有未列出工具在执行入口拒绝，包含写文件、脚本校验/运行、命令、构建、重启和回滚；旧自动授权不改变此限制。咨询不启动 Issue 引导、模型需求建单或 Hermes 业务记录。聊天历史、应用设置等宿主自身保存仍运行，不授予模型修改能力。咨询工具批次不保存成可恢复的开发日志，重启后历史可读但不自动重放；排队消息保留模式并需显式恢复。旧开发恢复结果存在时拒绝咨询发送并提示先停止。

进入咨询取消旧工单引导；返回开发重新进入原有门禁，不恢复已取消的旧引导消息。框架源码、Agent 定义和准入不变。

验收：默认关/发送左侧；无 Issue 与无宿主 Python 时咨询成功；强制非只读工具全部拒绝且目标文件字节不变；只读工具续轮成功；中途切换复选框不升级权限；CLI咨询被拒绝、切换API显式恢复队列；返回开发不能绕过门禁。新 C++ 输入须新单编辑器构建和原生夹具执行；旧二进制不作本次行为证据。提交前真实 Issue 门禁、提交后 require-committed、独立审查和远端精确候选 CI 均须通过后才可合并。当前为待验证候选。
