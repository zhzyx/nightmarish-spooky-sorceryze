# Godot 编辑器 AI 读取真实运行时调试错误

稳定需求 ID：`editor-runtime-diagnostics-20261112`。父项 [#773](https://github.com/zhzyx/nightmarish-spooky-sorceryze/issues/773) 要求编辑器内运行、诊断、修复和再次运行连续推进。来源为 #820 扩展验收中的已记录缺口；当前根会话负责实现与交付，独立审查另行派发。

## 现象与边界

当前 `read_logs` 只读取 `EditorLog` 的 Output 文本，运行时错误由 `ScriptEditorDebugger` 单独接收。#820 的修复测试使用游戏写出的错误文件，不能代替调试器诊断链路。先用私有 headless 游戏复现错误已到调试器而工具读取缺失，再修复已有只读入口。

不改变日志自动发送策略、工具权限、任务授权、断点行为或用户编辑器设置。模型仅在主动调用只读工具后取得有界快照，内容视为不可信数据并沿现有脱敏流程处理。不让错误消息成为工具指令，不读取变量值或任意进程内存。

## 验收

- 真实游戏产生运行时错误/警告后，`read_logs` 返回来源、调试会话、文件/行号及可用调用栈；保留原有 Output 字段兼容性。
- 多会话、无连接、停止、清空及再次运行的结果准确区分，不把历史错误当作新运行错误；有数量和字符上限，超限明确说明。
- 正常原生工具调用读取实际错误，修改受控故障脚本后再运行，验证新运行没有该错误；不以游戏额外写文件作为诊断来源。
- 本地工具关闭仍拒绝；只读咨询可主动读取；凭据样例不泄漏；日志不自动附加到普通消息。
- 独立审查发现短凭据 `true` 会使既有整段 JSON 脱敏破坏诊断回传和本轮前会话快照；按值脱敏并保留布尔类型及嵌套工具 JSON。实际读取持久快照验证上下文数组和工具结果可解析，保留修复前失败回执。
- 严格 Windows 构建、针对性单测/原生静默正负例、独立审查、正式门禁和 main 交付。真实供应商及最终安装组合归父项。

## 构建与回退

调试器和聊天原生源文件属于编辑器二进制输入，修改必须触发目标重编译。接口只从当前编辑器已经接收的调试数据形成快照，不新增外部服务或后台采集。恢复旧二进制可退回仅 Output 读取；不迁移或删除项目/用户日志。具体输入、摘要及消费者证据随实现追加。

## 当前候选证据

主线 c811 组合严格构建及全量 1560 项／435575 断言通过，三个既有跳过。正常原生工具验证两个实际游戏进程的错误、警告、调用栈、停止、清空、新代次和有界输出；短凭据 true 情形的实际快照信封、摘要、上下文数组及咨询布尔值回读通过。咨询结束按原契约去掉临时工具记录，嵌套工具 JSON 的快照递归只有静态审查。三位独立审查者的发现、修复及精确范围见 `data-collection/editor-runtime-diagnostics-845.json`（仓库根基准）。模型传输受控，故障脚本由驱动修改；不冒充真实供应商自主修复。
