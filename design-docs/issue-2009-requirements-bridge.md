# 需求桥接进程退出后的回执诊断

[工单 #2009](https://github.com/zhzyx/nightmarish-spooky-sorceryze/issues/2009) 承接 [#1709](https://github.com/zhzyx/nightmarish-spooky-sorceryze/issues/1709) 的 Windows 需求恢复故障。来源是 [运行 44959229481 的工件 14729710966](https://github.com/zhzyx/nightmarish-spooky-sorceryze/actions/runs/44959229481/artifacts/14729710966)。该工件显示需求桥接没有返回有效结果。当次桥接进程的退出码和回执状态均未知。用该次构建回放已有成功记录。

## 可复现的缺口

编辑器的发送入口通过私有标准输入启动需求桥接。旧的轮询函数在子进程退出时先解析结果，删除请求和结果文件，再检查返回值。它没有读取进程退出码，验收采集也只查普通聊天投递文件。在隔离编辑器内令需求进程退出且不写回执，或写入截断 JSON，两种运行的需求诊断条数均为零。

## 终态与隐私

原生宿主在当前代的子进程结束后取得退出码，通过已有回执读取器区分缺失、读取失败、无效 JSON、无效结构和有效回执。遇到暂时占用时只重读同一文件，沿用普通聊天回执的尝试次数和时间上限。成功需要布尔 `ok: true` 和退出码零。有效的 `ok: false` 继续进入既有业务拒绝分支，包括 GitHub 认证恢复。取消撤销本代，晚到的响应不能改变工单绑定或生成本代的失败记录。

失败时在编辑器私有缓存写入诊断副本，然后沿原流程清理请求和结果。诊断字段只含回执分类、退出码、读取次数、I/O 错误号、解析行号和临时文件是否存在。验收采集在自包含安装的缓存中只打开需求诊断副本，并限制最多 64 个。聊天正文、需求请求、临时结果和标准错误不进入这组诊断。

## 定向复验

在仓库根使用 `tests/editor/run_requirements_intake.py --godot <编辑器> --out <临时报告>`，分别带 `--bridge-fault missing`、`--bridge-fault parse_failed`、`--bridge-fault process_failed`。测试通过发送控件启动私有夹具的真实子进程，核对启动次数、结果清理、界面暂停、零模型请求、零建单和导出的退出码。无故障的原入口覆盖正常建单、业务拒绝与显式修复。取消用例先等服务收到请求，再等本地取消生效，随后放行服务端返回并核对取消状态。

本次变更属于已有 Godot 原生编辑器和验收脚本。回退时恢复先前编辑器和相应测试脚本，保留既有工单及诊断证据。历史相似故障 [#1357](https://github.com/zhzyx/nightmarish-spooky-sorceryze/issues/1357) 由原责任人处理。
