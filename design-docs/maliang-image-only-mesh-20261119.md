# 马良图生网格节点改为纯图片输入

<!-- gonggong-request:maliang-image-only-mesh-20261119 -->

日期：2026-11-19（Asia/Shanghai）。路径基准：仓库根。

## 目标与授权

用户确认当前 Kimi Native 直接三维接口不支持图片与额外文字约束一起提交后，明确要求“把生成Mesh节点的文字这栏先取消吧，就是图生Mesh”，并授权后续提交、推送及继续交付。本工单只收敛 `image_to_mesh` 节点的输入界面与工作流请求，不引入绕行图文生成链路。

## 范围

- 移除图生网格的提示词输入和不再使用的重绘图像模型入口，保留单图与图片列表输入。
- 在节点选中、参数应用、运行检查和工作流导出时清理旧 `parameters.prompt` 与 `text`，避免隐藏文字继续进入生成请求。
- 图生网格右键入口改为“编辑参数”，焦点只落到可见控件。
- `text_to_mesh`、`model_adjust` 和既有 Provider 契约不变，不实现图文混合生成。
- 增加参数表单、服务配置、旧工作流和内嵌编辑器回归；不把合成测试写成真实 Tripo 生成或视觉质量验收。

## 验收

- 图生网格不显示文字输入和重绘图像模型入口。
- 旧工作流中的提示词与文字说明在选中、保存和运行时被清空，保存重开后仍保持纯图片输入。
- 参数表单、多图输入、右键交互、服务配置及内嵌运行包受影响回归通过。
- 基于最新主线完成编辑器构建、提交和任务分支推送，回读 PR、CI、独立审查与远端 `main`；未通过的检查必须明确保留。

## 验证记录

- 代码候选 `68c68888349bf4bc21819e43a28b73442f11e2f6` 的 macOS arm64 内嵌编辑器与运行包验收通过，新增图生网格纯图片输入断言通过。
- 参数表单、多图输入和右键交互源码回归通过；未调用真实 Tripo 生成。
- 最终服务界面回归有一项上游报错弹窗路径的既有断言失败；另两项 CI 因测试环境缺少 NumPy 失败。上述问题均不伪装成本次验收通过项。
