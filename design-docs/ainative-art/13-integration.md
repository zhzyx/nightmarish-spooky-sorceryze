## 当前实现与验收边界

默认工作台的 `CharacterWorkbench` 使用唯一 `CharacterSession`。高级旧面板仍是独立模块诊断，不共享当前角色，也不作为端到端通过证据。会话保存不可变基体来源 SHA、编辑选择、generation 和播放时钟；体型、衣服、头发或动画改变时先从基体构造完整候选，验证真实求值后提交，失败保留旧实例。静态编辑重拟合衣服并重建布料缓存与头发绑定；表情帧仅更新映射 morph，不重新绑定头发。

每帧顺序为 body animation → layers/fingers/equipment IK → skeleton update → face expression → cloth → hair。原播放器和动态组件自动处理关闭，由会话唯一时钟采样。`frame_usec` 只记录该 CPU 流程，不能作为包含 GPU 的整帧性能。

在真实 i7-13700KF / RTX 4070 Ti 机器、隐藏父窗口且前台窗口保持不变的 GPU 工作台测量中，完整实时流程 p95 wall 为 42.981ms、CPU 为 41.759ms；烘焙回放 p95 wall 为 23.214ms、CPU 为 21.836ms。两者都超过 60fps 的 16.67ms 预算，当前不能宣称整角色稳定 60fps。可操作降级是选择烘焙回放、降低布料求解质量/毛发 LOD，或显式刚性布料预览；未另测的组合不声称达到 60fps。

表情使用捕获帧的真实 `timestamp_ms`，按观测时间保持上一帧；开始之前保持首帧，结束之后保持末帧，不假定固定帧率或自动循环。非有限/非单调时间戳和缺失检测会拒绝该来源。逐帧只更新姿态 revision，静态头皮 revision 保持。布料烘焙只允许一个在途操作，在隐藏隔离候选上运行，成功后检查 generation、取消 ticket 和缓存键再一次提交；重复点击、跳时、质量修改或角色版本变更不能让迟到结果覆盖当前有效缓存。

完整 `.tscn` 保存静态 DNA、来源元数据、当前衣服、动画/分层/武器、捕获表情帧、布料绑定和缓存、毛发绑定及展示状态。可重建运行网格不重复打包，绝对本机源路径不写入发布资产。编辑配方按发布文件实际 SHA 保存在机器 `user://character-recipes`；重开 A 不采用当前 B 的选择。无机器配方可自包含播放，重新编辑需要原始来源定位。旧文件拒绝覆盖。

兼容导出必须选择已经保存的完整版本，隔离重开该文件并采样最终骨姿，不能将原始 body clip 冒充 IK/分层后的动画。三目标为 UE4、Manny、Mixamo；Quinn 由 #202 待验收。兼容 GLB 包含绑定主骨架的可见身体/衣服蒙皮、当前静态体型和脸型、烘焙最终身体 TRS 动画。动态裙摆表面几何（仅保留主骨 Skin 腰带）、独立头发几何/头皮帽/辅助骨架、无 Skin 武器/帽子、脸部动画、运行求解器与编辑状态均在逐部件报告中明确排除；不只是丢失模拟配置。完整 Godot 角色包仍是全模块交付；GLB 不是等价替代品。

导出前后核对完整发布文件 SHA；兼容报告和 GLB 来自同一私有字节快照。报告先独占发布，GLB 最后独占发布，失败只回滚本次拥有的报告，不覆盖已有文件。若进程在两次发布之间中断，孤立报告不表示 GLB 已发布；重试另选新版本名，当前完整角色仍可重开。

开发验证已经实际覆盖同一生成机器人：改体型与脸宽、独立衣服换装、真实 MDM、人工持物分层、MediaPipe 表情、毛发、裙摆布料、保存重开后再次换装。错误 source SHA 保留旧实例。三目标开发产物已实际导出并在 Godot 回读到 68/161/67 骨及动画；这些开发记录不替代最终来源审查、Unreal Engine 外部回读、裙蹲实际三角检查、GPU 整帧测量与独立复核。最终冻结证据由主责汇总，不将当前开发通过写成 #154 已完成。

来源已升级为明确人工适配的 v14：角色源 SHA `163b2b76e5aaa3d550609ff217601a807578b593bb3d58049313846d8fb92dd4`，FaceBinding SHA `ad9997074180ec6d47d9833f5eb0ef7b1d34473661b9d22ecc73d80f5737a1d2`。同一原始生成身体保留 68 骨及 Skin；机械颈座是身体适配件，不能随换衣移除。v14 默认 UI 已重跑完整保存/重开链，视频蹲姿重新烘焙 425 帧且 cloth/hair 绑定实际同一主骨架实例。嘴型/视线不改变毛发 binding，改体型正确重绑并使布料缓存失效；帽子、LOD 和手动表情选择保留。

保留的失败与修复回归：长蹲姿全部 425 帧的实际腿带三角检测曾发现交叉，首次第 110 帧、最坏 131 条交叉边。定位到原低位固定腰线被深蹲大腿穿入后，为同一生成裙装新增明确的 `cloth_start_y=1.075m` 拟合分界与新绑定版本，保留 1.10m 上缘以下的主骨蒙皮腰带；没有靠增大碰撞半径掩盖问题。固定完整角色 SHA `52005908d1f3c6acfb16117ee781eab7f8cbd9c51e689ae261bf07f420abceeb` 的 7.067 秒/60Hz/425 帧 baked replay 已实际检测 7810 个声明腿带身体三角、9957750 条三角边，最坏交叉边为 0。该结论仅覆盖声明的腿/膝 rest-centroid 带和离散帧，不宣称连续碰撞或整身体积无穿插；实时同样的 425 帧独立检测也通过；GPU 多视图和性能由单独证据确认。新腰带的 6896 个保留三角索引、原顶点位置、骨索引/权重数组逐项等于从不可变基体与保存 DNA 重新拟合的非布料分区，Skin bind bone/name/pose 一致。所有旧失败版本保留。

## 本机复现入口

启动 `samples/ainative-workbench/main.tscn`，或启用项目中的 AINative EditorPlugin 底栏，在首个角色工作台选择本机配方。编辑器上下文曾因 `hair_runtime.gd` 缺少 `@tool` 无法初始化；已最小修复并在真实 EditorBottomPanel 中重开同一完整角色，验证毛发渲染、分层/布料、共享骨及真实表情时钟。配方以 `character.base`、`character.source_sha256`、`character.binding` 指定已验证不可变角色；`character.motion` 和可选 `layer_template`、`expression` 关联真实动作/作者分层/捕获表情。顶层 `wardrobe` 为独立装备 path/spec 数组，`hair` 为已验证来源 manifest，`cloth` 为绑定路径与 family，`animations` 为 label/path 数组，`target_profiles` 按 UE4、Manny、Mixamo 顺序。路径只存在本机配置，原始来源及权重不提交。

普通操作依次为选择角色、改体型/脸宽、换衣、启用毛发、切换动作、启用布料、选择完整/降低/刚性预览或烘焙回放、另存版本、重开、导出兼容副本。布料刚性模式是显式降级，不称为完整模拟；新体型/动作/衣服使旧烘焙失效。兼容导出前需另存完整角色。

无桌面控制的验证脚本使用默认入口真实控件：`integration_acceptance.gd` 验证共享角色与失败保留；`integration_squat.gd` 验证视频蹲姿、完整角色烘焙/重开及同主骨引用；`integration_controls.gd` 验证表情、体型、帽子/LOD 和缓存失效的衔接；`integration_export.gd` 从保存版本导出三目标并回读。均通过 Godot `--headless --path samples/ainative-workbench --script <脚本> -- <本机参数>` 启动；渲染图像与 GPU 性能由独立后台实例另验。

## 原始要求与上下文覆盖

| 原始要求 | 当前实现与实际边界 |
| --- | --- |
| 文字与图片上下文生成角色 | 复用已冻结真实生成体及推理回执；图节点保存上下文。image-to-mesh 加文字实际先 img2img；不能把元数据关联说成模型直接理解文字与所有参考。 |
| 目标骨架与 Unreal Engine/Mixamo | 从同一完整角色发布实例产生 UE4/Manny/Mixamo 兼容副本；最终外部回读独立记录，Quinn 未验收。 |
| 独立装备 | 独立生成来源及 SHA，按同一不可变基体和当前 DNA 拟合，换衣保留动作/脸/头发；布料必须与当前衣物源匹配。 |
| 文字/视频动画、上下身/持物/脸 | MDM 实际消费文字；视频提取消费实际视频，文字提示不改变提取算法。持物/手指层为明确作者夹具，脸流为真实 MediaPipe 捕获，人工嘴型/视线非音频生成。 |
| 布料与毛发 | 同角色、同主骨、同一时钟；静态修改重新绑定。实时、烘焙与刚性降级分别报告；穿插结论限定实际姿态/时间/网格抽样。 |
| 保存重开发布与错误恢复 | 单一完整版本、拒绝覆盖、SHA 来源校验、失败保留。兼容副本显式报告丢失通道。 |

| 上下文类型 | 框架保存/关联 | Provider 实际消费 | 仅来源元数据/不支持 |
| --- | --- | --- | --- |
| 文本提示 | 图节点与生成回执关联 | 图像模型、MDM；image-to-mesh 文字经 img2img 前处理 | 视频提取的文字提示不改算法 |
| 图片参考 | 可快照并绑定 hash | 图像生成/图像到网格流程按 Provider 能力消费 | 不代表 MDM 消费图片 |
| 视频参考 | 作为真实动作来源关联 | MediaPipe 身体/脸提取 | 不代表图像/网格模型理解视频 |
| 目标骨架/装备/脸映射 | 保存版本、绑定 revision 和 source SHA | 后处理适配与运行求值消费 | 不代表基础生成模型原生输出指定骨架/语义脸 |
| 音频与 Quinn | 可由通用数据结构引用 | 当前流程没有已验收消费 | 音频 AI 面部、Quinn 首版验收未支持 |

本机与云端部署可切换同一 Provider 接口配置，但凭据只留机器配置；更换模型、版本、艺术质量与骨架适配仍需重新验证。Rain 是授权作者参考头部及明确人工映射，不是 AI 生成面部。机器人源自身粗糙度/非流形孔洞与新增适配缺陷分开记录，失败的全 Rain 身体替换路线不作为通过证据。
