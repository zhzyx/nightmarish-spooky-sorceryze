## 问题与行为

#1195 的部分检查仍允许跨租户管理员改写文档，全局 request_id 查找误拒绝另一租户，同拆单重放新增事件，同标题但不同验收被静默复用。受控主线反例保留在私有来源回执，未触及生产数据。

现有变更入口统一核验 actor 租户、文档/空间及需求/父工单祖先；共享文档写入继续核验 ACL。六种已注册写工具 doc.create、doc.update、requirement.create、requirement.plan、issue.create、issue.transition 使用同一持久回执。回执以租户、actor、工具和调用键分区，绑定规范化完整输入；同键同内容返回第一次结果且不新增业务事件，同键异内容固定冲突。权限变动后重放重新核对当前对象和结果访问权。

回执、需求、完整父子工单树、进度和事件在同一 SQLite 事务中落库；独立连接取得写锁后再查回执，失败不留下成功回执。外层已有事务和嵌套 savepoint 保留原拥有者，不恢复局部 commit/rollback。存储失败、锁忙及内容冲突分别映射固定 HTTP 500/503/409，底层原因只保留在异常链。

## 兼容和迁移

显式 call_id 可从现有领域方法、HTTP 模型和支持的 CLI 创建命令传入；新操作使用新键，未知结果重试复用原键。普通人工文档/工单调用不传键时仍允许有意重复创建。dispatch_tool 无键按规范化完整输入生成 legacy-v1 键，需求创建/拆单继续原有无键幂等承诺。

旧拆单保留父单，子单按完整五字段规格和出现次数复用，不按标题丢弃不同验收或重复条目。不同显式计划键允许有意创建相同规格子单。迁移只增加回执表；首次无键读取完全相符历史树仅登记回执，不制造新的计划事件。无法还原身份的历史工具调用不伪造回执。完整契约见 [服务接口说明](../customizations/components/tianxuan/server/README.md)。

独立首轮审查复现祖先需求撤销 ACL 后的越权，以及普通无键写入遗漏检查。修订使用同一支持读/写权限的祖先链检查，新增 13 项回归；只读分享仍可读取评论，写入仍拒绝。原 12 个失败反例及首轮 changes_requested 报告保留，独立复验 40 项通过。
