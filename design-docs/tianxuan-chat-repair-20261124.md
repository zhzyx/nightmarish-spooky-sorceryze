# 天璇对话保存后没有模型回复

<!-- gonggong-request:tianxuan-chat-repair-20261124 -->

用户在已安装的原生天璇中报告“消息已保存，此轮未取得模型回复”，并要求修复；随后明确纠正：原生端应接入编辑器本机 CLI 或 API 返回，而非依赖线上模型。本轮由当前 Codex 会话负责诊断、修复、必要验证、源码交付与可用安装更新；工单 #2180，关联原生化交付 #2150。保留 Web 功能、现有账号权限、会话与草稿，不复制其他工作树的在途修改或凭据。

已确认消息通过线上服务保存，原生页面将所有非 answered/pending 状态显示为同一提示。当前主线的工作区对话由服务器的固定模型配置处理；编辑器本机模型配置没有参与这条链路。服务端保留数值失败码，但原生页面没有区分未配置、额度耗尽、上游失败和用户停止等待。另发现 Compose API 未传入文档要求的三个 TIANXUAN_CHAT_* 变量；此为已核实的部署输入缺口，尚不能据此宣称线上故障已确诊。

最新用户决定已排除服务端模型配置作为本次修复方向。修复原生调用路径：复用统一模型配置与现有宿主 Provider/CLI 适配器，在本机取得并呈现回复。凭据留在本机，模型调用由 Controller 持有，关闭视图不丢失会话。线上服务继续承载既有业务数据，任何不受现有服务支持的同步必须显式保留待同步状态，不能额外触发云端模型或伪报已同步。此前发现的 Compose 配置缺口不在本轮改动范围。

## 验收

- A1：原生普通对话使用编辑器当前选择的本机 CLI 或 API，已有历史消息和草稿保持完整。
- A2：复用已有模型配置、凭据及 Provider 协议，不要求线上模型，不把本机密钥上传到业务服务。
- A3：明确当前模型与实际错误，取消、身份切换及迟到回复不污染新会话；本机保存与远端同步分别回读。
- A4：相关服务端和编译后原生回归通过；源代码按实际门禁交付 main，并安装适用的新编辑器。
- A5：使用本机已有合法 CLI 或 API 实际验证回复恢复；Web 既有路径保持。必要服务协议升级和兼容限制如实留证。

## 验证与停止边界

使用隔离宿主验证 CLI/API 选择、回复与故障、取消和迟到结果、身份隔离与持久化，保持已有幂等行为；macOS 原生嵌入脚本改变后重建并在独立项目验证，必要时更新 Windows CI。实际本机模型仅作明确隔离的文本验证，不执行截图里的资产生产，不更换用户供应商、复制凭据或更改任务准入规则。

复用 editor-dependency-handoff 的适用原则：记录实际源码/安装消费者与回执，候选改变后只重验受影响链路。完整生产终态类经验不适用于本次只读诊断，不新增另一套调度或验收。
