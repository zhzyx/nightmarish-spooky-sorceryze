# 全仓 CI 按模块执行测试

<!-- gonggong-request:modular-ci-test-selection-20261120 -->

工单：[Issue #1668](https://github.com/zhzyx/nightmarish-spooky-sorceryze/issues/1668)。

## 目标与边界

普通 PR 和普通分支提交只验证实际变更模块及明确声明的公共检查；跨模块变更分别运行各模块测试，不因共享文件或未登记路径自动扩大为全仓回归。完整回归仅由人工显式触发。此次只调整测试选择、CI 编排、门禁和文档，不修改业务逻辑，不删减模块自身测试。

## 设计

1. 以集中模块注册表登记名称、负责路径、构建命令、测试命令、公共检查和状态检查名称。
2. 选择器从实际 base/head diff 计算变更集合；路径必须且只能归属一个模块，非法注册表和未登记路径失败关闭。
3. CI 按选择结果调用原有模块测试工作流或运行模块登记的命令；汇总检查只接受真实成功，未选中和跳过不等于测试通过。
4. 原模块工作流保留手动运行能力；统一工作流的 `workflow_dispatch` 显式执行完整回归。
5. 自动化测试覆盖单模块、多模块、共享文件、未登记路径、非法映射、空 diff、手动全量及真实命令失败传播。
6. 文档列出公共必需检查与各模块状态检查；远端分支保护按实际权限和回执核验，不以文档声明代替服务器配置。

## 验收证据

- 本地选择器、真实命令失败传播、汇总防伪及工作流契约共 30 项测试通过；单模块、多模块、共享文件、未登记路径、重命名、文档和显式全量场景均有自动化覆盖。
- 30,666 个已跟踪文件逐项通过归属检查，未登记数为 0；22 个工作流 YAML 均可解析，Web JavaScript 语法检查通过。
