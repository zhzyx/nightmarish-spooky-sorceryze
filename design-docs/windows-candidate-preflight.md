# Windows 引擎候选预检和推进失败回执

[修复工单 #535](https://github.com/zhzyx/nightmarish-spooky-sorceryze/issues/535) 关联 [原工单 #534](https://github.com/zhzyx/nightmarish-spooky-sorceryze/issues/534)。该工单已经建单、取得司南判断并开始推进。编辑器在生产模型请求之前把有效候选报为分支已改变。

## 路径核验

候选管理器保存 Python 解析得到的原生绝对路径；Godot 的 DirAccess 和 Git 可能用正斜线返回同一个 Windows 目录。核验时统一 Windows 路径分隔符，分别确认目录存在、引擎源码标志、精确 HEAD 分支、共同 Git 目录与基线祖先。保留原私有绑定、工单、需求和会话 owner 的逐字段匹配。原会话继续使用其已记录的需求工作区或已验证候选，遇到另一个工作区或不一致的 owner 要重新核对归属。

## 状态与恢复

天枢显式发起推进时，为该轮配发一次性回执标识。编辑器把真实结束状态送回同一工作区、账号、工单和来源修订。模型请求前的失败展示原因与手动重试入口。历史恢复只在用户查看相关工单时读取对应的已结束事件，并核对来源、操作者、会话、快照和该单的标准开工消息。不同修订、已处理的回执和其他工单不能更新当前失败状态。

验收使用原 #534 的既有候选执行只读核验，并以隔离项目复验旧失败记录、身份与修订隔离、回执的一次性消费和后续成功状态。工单图标制作和生产模型重试仍由原工单所有者明确发起。
