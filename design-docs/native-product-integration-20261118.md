# 合契同产品不可变贡献整合

需求 ID：native-product-integration-20261118，父 #1444；原用户授权持续有效。路径基准为仓库根。

目标是将多个 AI 对同一产品的贡献整合并验收，不要求生产者追赶任何 Git/main。固定输入、原始贡献和真实终态永久分离于产品选择；用户要求的全链路效率与模型实测仍由父项保留。

已独立验收的 #1451 候选源码和 #1456 定义/历史依赖源码按精确摘要交接到本隔离树（Git 留底仍在途）。工单 #1461 的工作者接入尚在开发，不作为已验收依赖；本项先独立实现以真实 NativeCandidates 输入的整合核心，待其完成后接入真实生产者链路验收。设计源为私有 heqi-integration-design.json，实际源码及当前边界优先于设计草图。

1. 新增既有 sinan-workorders 内的 host_tool，不新增框架角色。合契授权计划绑定 tenant、同一 product/channel、固定产品基线与预期发布、全部原任务/source/执行/候选/准则、原贡献receipt与当前权限、最终检查策略和独立review要求。原生产内容不得被覆盖为整合内容。
2. 短事务持久化计划/执行意图；实际文件、检查、模型/冲突处理在锁外。按原base与最终产品base做确定性对象级三方整合，删除、相同编辑、大小写/文件目录别名与依赖闭包均明确验证。未知读取允许构造候选，不表示语义独立，最终检查必须覆盖改变输入。
3. 真冲突只阻塞受影响整合，禁止last-writer-wins；已安装合契resolver可产生绑定原输入三元组的决议及新计划。依赖重绑必须显式授权，重新验证依赖消费者。无关head更新不重跑生产者。
4. contribution_checked 与 accepted 区分。合成同一最终candidate后检查联合准则和真实原需求覆盖，独立审查者排除全部原生产者及resolver；NativeRelease一次发布，原子推进所有已覆盖贡献任务/工单/进度/outbox。不能逐个旧complete造成部分关单；任何原需求换版/撤权/停止阻断全组合验收。
5. 进程/传输中断后按持久请求/历史release回读；幂等、CAS竞争、重复事件、撤销/过期/政策变更均验证。保留旧原件与未知占用，不伪造成功。当前组织与原私有需求权限保持。
6. 用同产品/同模块多贡献证明联合内容、全准则与一次发布；与不同产品分别发布区分。真实双生产者及认证HTTP/Sinan驱动在#1461精确验收接入后完成，不提前宣称跑通。最终效率对比和AA渲染保障仍属于父验收。

构建位置host_tool，新增文件须实际SCons零原生交集与缓存回归；不改#951/#1343/渲染/框架准入。证据首次写UTF-8 LF再绑定摘要；完整门禁、独立审查、Windows/Linux验证与main留底由父推进。不能以本设计登记当完成。
