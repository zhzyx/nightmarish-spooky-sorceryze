# 原生模型阶段观测与实际等待排障

需求 ID：native-model-latency-20261118；父 #1444，原始目标 #1382。用户要求完整 AI 链路效率优先，不能只把提交排队移到模型调用或验证环节。沿用司南路由、既有模型权限与实际调用账本。路径以实施仓库根解析。

事实：#1486 原始等任务样本 Git 路径18.016秒，原生路径121.735秒；不能据此推导普遍性能。修正输出字节后新生产122.625秒。独立单次诊断实际总121.812秒，其中 JS 协议120.849秒，Python owned-process返回只比首次完整输出晚约15毫秒；无模型握手另测1.953秒。这些结果排除了该样本的Python退出等待主因，尚不能区分模型推理、网络/服务排队、thread/start和终态通知。原回执保留，不重跑旧 intent，不把猜测当根因。

1. 在原生提案宿主增加有界、单调、来源明确的阶段耗时证据：启动完成、thread/start与turn/start请求/回复、首个实际响应事件、首个文本、最后文本、turn/completed、提案校验、可信宿主物理关闭。只记录方法/阶段、计时和有界计数，不记录完整提示词、文本、账号、凭据或环境。未知和缺失阶段保留 null；重复/错序/其他turn通知不能伪造本次阶段。阶段计时不作为模型用量、完成/批准或自动重放授权。
2. 优先通过现有原生提案端对公共Subscription接口观测，不改 #951 他人维护的 subscription_session.js，不修改冻结框架、不新增模型客户端。缺少可安全观测接口时报告具体限制，不绕过身份、安装摘要或实际终态。NativeModelHost 严格验证新的可选观测字段与界限，历史回执仍可读取；新安装摘要重算，旧评测/grant不能批准变更后的实现。
3. 用确定性实际协议替身分辨慢thread/start、慢首文本、慢终态、错误/取消/关闭，证明观察不会多发模型请求，不因首文本或超时提前报告完成，未知调用不重放。覆盖原有用量验证与原生提案/生产者兼容；先做窄测试，失败或证据不足才扩展。
4. 独立源码审查后，根责任者登记新的有限调用方案与当前安装，再做实际单次诊断。已完成的八次原始/回归/阶段诊断与新增样本分别记账。根据真实阶段证据修复可归于本平台的冗余；外部服务等待不能用假计时、截断终态、降质量或虚构token节约消除。后续对比先固定任务/质量/配置/样本规则，不能反复试到有利数据。
5. 若证据定位到网络/供应商或他人维护接口，按夸父与原责任者交接，继续不依赖该决定的工作。不存在平台内可验证修复时保留实际限制和原父项未完成；本子项的可交付观测不等于整体效率验收。
