# GUI 运行入口与自动隔离源码候选

稳定需求 ID：gui-runtime-node-20261107。真实 Issue：#390。

授权来源：2026-11-07 用户要求实际验证引擎内 Agent 从聊天到 main 的全流程，发现问题先打断再修复；后续明确要求宿主自动保持工单、仓库、源码工作副本、编译产物与运行入口一致，不能要求用户填写路径、选分支或手工同步。父执行者将入口与候选生命周期委派本任务；主线验收后的稳定启动入口由关联 #393 承接。

已复现故障：Finder 启动没有 PATH Node，Codex 桥虽使用有效 cli_node，需求整理却报告找不到 node；失效 Codex 路径被混为登录失败。生产模型把打开项目所在旧 checkout 当成引擎源码，build_engine 却固定编译运行二进制祖先源码，存在改 A 编译 B 的风险。原 #387 模型刷新需求已中断，等待本修复候选后继续。

## 设计定版确认

宿主在首次生产请求前回读真实工单，以仓库 common-dir、Issue、request 和持久会话身份建立私有 journal；自动从远端 main 创建或复用专用干净分支及隔离工作树。不得接管已有未知目录、分支、工作副本或其他人的未完成任务。需求文档和匹配谛听事件按持久计划迁移，迁移中断只恢复已证明的计划内容，未知修改明确拒绝。

候选归属在需求整理、文件写入、命令启动及编译之前检查；普通会话及子会话各自绑定工单。项目读写仍可用，旧源码仍可读；macOS 对其他已登记源码工作树实施宿主进程写保护，允许共享 Git 私有目录、打开项目和受管构建产物目录。命令默认目录、框架报告根、生产源码与编译根使用同一候选，模型不能靠自行传另一个源码路径绕过绑定。

编译记录实际源码文件的 SHA256、模式与删除项、宿主编译选项、候选归属及产物 SHA256。编译中源码变化则不发布 ready。切换前和后继启动应答前重新核对产物及源码，编译后只提交相同内容可以继续，编译后编辑源码必须重编。持久重启日志用于中断续跑与失败回滚。初始真实启动入口经私有凭据链跨候选沿用，供 #393 在 main 与工单验收完成后自动激活。

有效显式 GONGGONG_NODE 优先，否则复用有效 CLI Node；配置缺项明确提示，不误判登录。不保存认证信息，不替换用户正在运行的旧应用。

## 验收

1. 无 PATH Node 的真实宿主子进程复用配置 Node；无效 Codex/Node/bridge 路径分别诊断。
2. 同仓库工单在用户无需选路径或分支时自动取得独立候选；并发所有权、main 基准及中断迁移均有实际 Git 测试。
3. 原项目根与候选根不同：默认命令在候选；旧源码只读可用，误写及误 cwd 拒绝；项目自身写入可用。
4. 同 Issue 后续需求与不同父子会话的文档和工单分别绑定，切换会话不会被全局绑定覆盖；失去分支所有权时在需求整理写入前拦截。
5. 新候选可创建 bin 并编译，真实宿主配置保留 macOS arm64 等构建特性；构建 manifest 覆盖新源、删除、模式与实际产物，源码漂移拒绝切换。
6. 独立审查、必要回归及本地 macOS arm64 编译通过；提交、推送、精确候选 CI 和 main 权威回读分别留真实回执。#393 的入口激活及 #387 的真实模型端到端复验由父执行者接续验收。

不包含模型刷新按钮实现与命令式接口总清单，它们由其他已认领任务负责。用户另授权的统一持久配置（Node、工作流 Python、编译 Python、Codex，原子保存、迁移旧设置、临时环境覆盖不清持久值、不存认证）记录为主链完成后的关联实现；本次 Node 衔接不替代该完整验收。
