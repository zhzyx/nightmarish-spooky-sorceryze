# 并行工作者的真实验收来源

工单 [#785](https://github.com/zhzyx/nightmarish-spooky-sorceryze/issues/785)，父项 #776 / #773。方法召回 `editor-dependency-handoff / bind-consumer-release` revision 7，证据可用；适用于外部生产者向编辑器独立审查交接，CLI 退出或未绑定候选的 JSON 是已知反例。

现有 runner 的本地标签和退出码不足以证明生产身份或实际候选。启动前在真实 intake、框架和设计检查后，宿主以独占写入记录 execution_id、worker_id、工作副本、分支、基线、Issue/需求/设计和准备回执。`jobs[].workerId` 可绑定已授权台账中的实际 owner；未配置时使用宿主生成的独立执行身份，不虚构 CLI 模型会话。

实际进程结束并取得终态上报后，独立 sidecar 保存原登记引用、PID、退出码、取消状态与完整产物文件摘要。仅正常退出且观察、上报、候选登记有效时标记 transport_completed；business_accepted 始终为空。独立审查仍须核对候选当前性、来源与逐项证据。失败、未知和登记漂移保留原预留，不重复启动。

重放核对原始登记、终态文件原始字节、Issue/需求、工作序号与当前配置工作副本及明确 owner；旧版本没有新登记时仍保留原终态，不能因此补造新身份。新增文件、删除文件及未提交字节进入终态候选；链接与非普通文件拒绝。`.yuanheng/` 是现有台账自身输出，不作为生产文件。验收期新审计事件的限定处理由 #776 桥接负责，不能据此忽略源文件变化。

构建归属为既有宿主工具，无新增模块目录或原生输入。正常入口为 `tools/godot_parallel/runner.mjs`，输入来自编辑器已授权配置和实际派发请求。回退使用前一主线 runner；旧回执保留，缺少真实来源的新自动验收不得启用。实际测试使用临时 Git 工作副本、真实 Node 子进程、受控模型与门禁；不宣称供应商账号、原生消费者或业务验收已经完成。#783 负责实际编辑器消费组合验证。
