# Godot 编辑器内并行生产配置与工作副本准备

稳定需求 ID：`editor-production-setup-20261112`。父项 [#773](https://github.com/zhzyx/nightmarish-spooky-sorceryze/issues/773)，设计条款为父设计“连接账号、发现 CLI、选择可用模型及容量”。授权为用户要求 Godot 编辑器完整支持游戏生产及父项纠正评论。当前主责为 Codex 宿主派发的实现者，父项负责最终组合与真实账号验收。

## 范围与行为

当前并行入口需要用户手写私有 JSON 并逐项准备 Git worktree。提供编辑器内正常设置和准备入口，复用实际运行配置、已发现模型、原生授权开关和现有 runner。用户选择已连接的可用 CLI/模型及正整数容量后，宿主按定版设计准备独立工作副本并产生私有配置。不能让普通用户手工编写 JSON、登记表或样例脚本才能启动。保留显式自定义配置兼容路径；不复制凭据，不把配置存在当作登录或模型可用的证明。

不得抢占已有工作者、覆盖非本批次目录、删除未知占用或重复启动。设计依赖继续由已有独立验收机制核对。准备失败提供可操作的错误，重试回读原准备回执。长操作不阻塞编辑器线程。无可用并行 CLI 时明确现有串行能力与缺少条件。

## 独立验收

- 从正常编辑器入口选择已有连接、模型和容量，生成真实可回读的配置及独立 worktree；无需手写私有文件。
- 多个生产项映射唯一副本，重试幂等；当前工作区修改、已有未知执行、路径冲突、失效模型和无权限均不被覆盖或伪装通过。
- 配置容量不被描述为供应商额度或最佳吞吐；模型目录来自实际发现。
- 原手工配置和普通串行会话兼容；暂停、取消、重启不自动重派。
- 独立审查、适用单测与原生静默测试、严格编译、正式 main 交付；父项在最终安装上验证真实连接生产。

## 构建与交付

原生界面和调度接线属于 native，工具脚本属于 host_tool；沿现有 `tools/godot_parallel` 边界扩展，记录实际输入和宿主协议，不改框架定义。原生变更须验证构建失效；脚本从正常入口执行核验。回退保留旧自定义配置和全部回执，不迁移或释放未知执行。与成果接入子项无实现依赖，可隔离并行；共同文件由主责整合，禁止覆盖其他候选。

## 当前候选验证与父项边界

结合主线 `46697266403533f1038fd129956859597d4eda88` 的候选通过严格 Windows 原生重建、1,560 项原生测试及 435,575 个断言。正常 Codex/CodeBuddy 两条入口分别从模型选择、开启生产准备和容量设置开始，自动生成配置与两个独立副本，观察真实并发工作者和四份绑定回执。模型/GitHub 响应为受控测试传输，不作为已连接供应商业务验收。

准备 helper 的 25 项测试覆盖未提交设计/文件、真实 index/HEAD 保持、Windows 换行和长路径、幂等、配置漂移、未知占用、崩溃及竞争恢复。首次实现的七项回执保留原始字节；完整候选证据另存 `data-collection/editor-production-setup-810-final.json`，路径以仓库根解析。
