## 验收条件

- 一个带版本的本机 JSON 保存四个路径；原生 C++ 读取与操作系统文件锁不依赖先启动 Python。Python 标准库读取同一配置并使用相同锁协议。
- 每次操作启动读取当前有效配置，单次操作使用一致快照；其他窗口修改后下一次操作使用新值。环境覆盖只在本次启动有效，内部导出不能反向变成外部覆盖。
- UI 明确编辑只原子合并该字段；初始化、外部刷新、发送、登录及编译不把旧字段组回存。旧持久设置只补缺迁移，无凭据迁移；缺少编译 Python 不阻止聊天。
- `_sc_` 编辑器、离线夹具及子进程仅使用私有配置，不读取或写入用户全局配置。
- 原生 App 直接包含 Mach-O，无 shell 包装或 LSEnvironment 运行路径注入。先签最终 App，再计算产物摘要与外置 sidecar 并验收；安装只复制完整已签应用，不再修改包内字节。
- 入口来源 locator 仅定位现有候选 binding/manifest，核验后使用固定来源；不回退旧 cli_bridge，不产生新权限。没有显式项目、脚本或命令参数时才恢复已核验的绑定项目。
- 私有验收覆盖并发单字段修改、跨 C++/Python 锁、临时环境、旧设置迁移、隔离配置、跨窗口有效配置、模型自动刷新和真实原生 App 冷启动；实际用户安装与 GUI 最终验收由原宿主回执覆盖。
