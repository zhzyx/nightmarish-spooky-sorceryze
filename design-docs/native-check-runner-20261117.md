# 多宝原生实际检查执行与证据回执

需求 ID：native-check-runner-20261117。父目标 #1382 的 P0-D；依赖已验收 #1386、#1406、#1409、#1414，基线 main 04fcdb5f1f0e301f179e0581944accee382a2496。沿用当前用户开始执行与继续授权。

现有 EvidenceCache 只能接收受信运行者的结果，尚未提供把实际检查进程连接到精确内容快照的生产入口。本项连接 NativeWorkspace 与 EvidenceCache，产生可供 NativeRelease 独立审查使用的真实执行证据。保留司南派发、合契整合、阎罗交付；不新建调度器，不把检查通过等同于业务交付。

1. 可信宿主安装固定检查注册表：命令、参数、明确工具链/环境指纹、输入范围和超时/日志限额。调用者只能选择已安装检查ID、精确组合与稳定运行键，不能提交任意shell命令、工具链声明或outcome=passed。明确检查环境指纹依赖宿主真实安装核验，不把单个可执行文件摘要冒充整个环境的证明。
2. 从原生不可变组合物化受限普通目录，实际启动允许的进程并取得退出码和有界日志。未知读取采用完整组合检查。进程、模型、构建和日志等待均在SQLite写事务之外；相互独立的检查可并行。限制应覆盖超时、超量输出及子进程清理；优先复用仓库已验证的进程管理能力。不声称本地可信进程等同OS沙盒。
3. 原始输入在检查期间被修改、检查失败、超时、取消或终态不明不能形成通过证据。验证原始输入的实际内容；生成产物放明确分离的输出目录。检查结果写入已有EvidenceCache，绑定精确上下文和真实日志。缓存命中可直接复用既有有效证据；工具/规则/环境/输入漂移与撤回必须失效。
4. 持久记录稳定运行键及执行状态；同一运行键并发或重放不重复启动实际进程。不明终态保留待核对，不能仅凭超时抢占并重新执行。失败后按新的真实事件/运行键重试。崩溃窗口、缓存写回与回执缺失的恢复要有明确范围和实测，不声称自动恢复未实现的部分。
5. 使用真实子进程验证成功、非零退出、超时/子进程、输出超量、输入污染、幂等/竞争、重启、缓存复用/失效、其他候选提交期间检查仍在运行；演示实际执行证据进入 NativeRelease 的独立审查与通道选定。身份/授权沿用已有可信宿主端口，禁止默认放行授权器；测试身份/确定性检查与真实模型、生产部署清楚区分。Windows及现有服务器隔离实测、独立审查后交付。

placement=host_tool。输入为受信注册表、已认证宿主身份、明确绝对原生库和临时工作根、精确组合及运行键。输出为持久执行记录、EvidenceCache回执和日志摘要；实际输入、宿主进程接口、回退均记录。停用新入口并保留执行/证据库可回退，未知进程须先核实终态再清理；不切换生产服务、不触碰渲染或他人在途控制器。跨节点运输、线上身份/来源到发布接线、全链路真实模型和token对照仍属于父目标剩余范围。
