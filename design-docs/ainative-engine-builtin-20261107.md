# AINative 引擎内置编辑器入口

<!-- gonggong-request:ainative-engine-builtin-20261107 -->

用户最新决定：AINative 不应依赖工程插件，应内置于定制 Godot 引擎；此前用户在 GongGong Workbench 中找不到 Mesh 生成与骨骼绑定入口。本次 Codex 会话负责实现、验证和交付。

## 范围与验收

- 在引擎中注册原生 AINative 编辑器插件，任意工程均有明确入口，无需复制 addons、开启工程插件或打开示例工程。
- Mesh 生成和骨骼绑定具有直接可见的导航，复用已有管线及发布确认，不把离线 Copy 伪称为 AI 推理。
- 工作台及其本地 Python 工具随编辑器交付，不依赖源码仓库和样例工程的机器路径；模型服务仍需用户配置。
- 保留工程隔离的任务、来源和本机配置；发布的角色及运行时依赖仍可重新打开。
- 已有示例工程不出现双份 AINative 入口；第三方项目的 addons、project.godot 不因打开内置工具而被修改。
- 本轮目标为 macOS arm64 当前构建。必要检查：原生注册/构建、无 addons 临时工程无窗口启动及控件验证、真实离线执行与 Mesh 预览/角色绑定回归、内置资源部署和示例兼容。真实模型推理仅在已有可用配置下验证，不新增后端或购买服务。
- 完成条件包括必要审查、绑定精确候选的交付与远端回读；不修改其他工作树的在途工作。

关联工单：[Issue #374](https://github.com/zhzyx/nightmarish-spooky-sorceryze/issues/374)。

## 实现

原生 `AINativeEditorPlugin` 注册一个默认位于顶部工作区的 `EditorDock`，不依赖工程设置。首次进入该页面时，安装并加载编译时嵌入的脚本和 Python 工具；界面可直接切换 Mesh 生成、骨骼绑定、角色工作台、其他工具与本机设置。现有示例的源码仍与内置包共享，示例插件检测到原生类后不再注册底部副本。

工具部署到编辑器数据目录 `ainative/bundles/<内容摘要>`，逐文件核验 SHA256、原子安装。脚本引用改为同目录引用，Hair 的动态加载从自身脚本目录解析。状态部署到同一编辑器数据根下 `ainative/projects/<绝对工程路径摘要>`；仅打开页面不向工程复制 addons 或修改 project.godot。默认工具选择保存为语义标志而非某次版本的绝对路径，升级时跟随当前内置包，显式自定义工具路径仍可保存。

真实编辑器测试发现 `GLTFDocument.generate_scene` 在编辑器模式下保留 `ImporterMeshInstance3D`，旧样例只在独立运行模式下验收，因而漏掉空预览及绑定读不到几何的问题。共享 `runtime_mesh.gd` 现仅转换本管线生成的节点，保留变换、Skin、骨架路径、可见性、材质、元数据、子节点 owner 和动画路径；生成预览、绑定、互通、服装四个入口统一使用，不修改全局导入扩展。

普通 Mesh 与 Rig 场景不依赖脚本。集成角色的运行时脚本在发布时从可信内置清单核验并快照到产物旁的独占 `.ainative-*` 目录，场景引用改为相对路径；跨工程迁移须携带场景和该目录，不需要安装编辑器插件。来源摘要、stage 原件保持不变，依赖准备失败或主场景发布失败清理本次新建目录，既有场景和目录不覆盖。
