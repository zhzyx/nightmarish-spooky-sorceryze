# 多宝原生模块修订与组合候选

需求 ID：duobao-native-store-20261117。父需求：[全链路 AI 原生引擎 #1382](https://github.com/zhzyx/nightmarish-spooky-sorceryze/issues/1382)，设计条款 P0-A。

用户于 2026-11-17 明确取消新多宝的 Git 权威并“开始执行”。本子项实现 Git 无关的模块修订接收、读取、对象级并发、幂等与精确依赖组合；它是整体内核的一步，不能关闭父目标或宣称真实发布、模型收益及 AA 渲染已通过。

复用现有多宝宿主目录；新增 native_store.py 及正常 CLI 入口，Python 标准库即可执行。不修改既有 Git 服务及线上绑定，不新增 Agent。数据路径由调用方明确指定，不依据源码仓库或当前 Git 根解析。工具需可信宿主提供已认证 org/actor；核心不把字符串身份自证为认证。

验收：
1. 不调用 Git、网络、外部进程即可创建模块修订、读取二进制/文本、回溯历史、形成精确依赖组合候选。
2. 模块互不追赶全局 HEAD；同模块旧基线下不相交的读写对象可合成，已读对象变化、同对象竞争、删除/命名冲突与未知依赖在发生漂移时不能静默覆盖。
3. 一次请求支持跨模块原子变更；稳定请求键幂等，同键异内容拒绝；故障回滚及重启重放不丢版本/不重复接收。
4. 组织数据边界、修订归属、内容摘要和结构输入验证；路径只作逻辑对象标识，禁止任意宿主路径读写。
5. 组合候选固定模块修订并核对依赖闭包；接受内容不等于独立验收，不提供未经授权的“通过/已发布”状态。
6. 单模块/多模块、独立连接并发、250 个在途提交、持续无关更新及竞争反例留证；测得时延不外推生产服务容量或 token 收益。

平台：Windows Python 3.11+ 首验，Linux 标准库兼容由 CI 验证。placement=host_tool，输入为显式请求、字节与数据库路径；不进入原生引擎链接。回退停用新 CLI/适配并保留数据库；不删除既有数据。数据存储首版用短 SQLite 事务验证语义，不在事务内执行模型/编译/外部校验；大文件流式对象存储与多副本为后续整体任务，不将首版标为全目标完成。

范围不包含产品发布授权、在线 API、UI、完整协作文档、运行时装载与 GPU 验收。主责为当前 Codex 会话；实现完成后独立核查，Git 仅留底实现代码与证据。

## 首批验收证据

`native_cli.py` 是实际正常调用入口；`verify_native_processes.py` 在无 Git 工作目录、空 PATH 下启动精确 Python 进程，验证 250 次旧基线变更（最多 16 个同时执行）、历史读取、重启回执重放、固定依赖与陈旧读取拒绝。结果在 `data-collection/duobao-native-processes-1386.json`，绑定受测源码 SHA256。独立审查回执 `data-collection/duobao-native-review-fixed-1386.json` 覆盖 18 项单元测试及完整性缺陷修复，原审查保留在 `data-collection/duobao-native-review-original-1386.json`。所有路径以仓库根为基准。

接收成功没有上线或批准含义。读集合当前为可信宿主声明，尚无自动捕获；SQLite 并发及清单大小仍需服务器规模实测。后续缓存、执行、发布和服务接线继续由父项推进。本批正常入口测试仅为 host_behavior，不影响原生引擎二进制，也不声称 AA 验收。

测试临时数据库按 TemporaryDirectory 生命周期清理；首次单元测试中测试代码未显式关闭 SQLite，造成 5 个自有临时目录残留。测试连接已改为显式关闭并复验。宿主自动审批拒绝对这些遗留目录的清理操作，错误为 blocked by policy，因此保留并在交付证据中列为未清理；未改用其他工具绕过。工作分支和隔离副本保留至实际交付及后续在途工作结束。
