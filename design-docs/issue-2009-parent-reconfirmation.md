## 故障与修复

首次运行保存生产者 A、B 的回执，C 等待依赖；冷启动保留这些历史。pc-2、pc-4 和 pc-6 依次检验错误生产者、未开始生产者和过期参数。实际失败发生在切回原父会话、模拟丢失本机定版记录、点击「继续落地」之后。

工作台的共享输入框在手工切换会话后回到「仅咨询」。原夹具直接发起生产动作，界面按当前模式拒绝。复验在同一签发编辑器中回读到父 ID 匹配、工具开启、队列为空、继续按钮可用且仅咨询已勾选。夹具增加两次公开操作，先在仅咨询时点击验证拒绝，再由原操作者退出仅咨询以申请恢复。重新确认期间，切换到另一个父会话后也必须拒绝，并在返回时重新选择执行模式。

同一编辑器完成重新确认后，父会话明确继续生产，独立复审会临时选中其只读子会话。原实现将宿主在同一批次内调度的切换也看作手工换人，回到父会话后原批次收到仅咨询拒绝，C 无法启动。

调度入口现在传递拥有该次切换的父 ID。只有来源与目标有相同的父 ID，存在活跃批次，且父会话的 conversation、snapshot、Issue、需求和工作区与该批次匹配时，界面才保留操作者当前选择的模式。主动选中仅咨询仍有效。手工换页、冷恢复及无关会话使用原恢复逻辑。每次会话恢复仍撤销原生任务授权，每个审查回合仍根据子会话角色强制只读。保存设计定版与派发生产仍是两次独立操作。
