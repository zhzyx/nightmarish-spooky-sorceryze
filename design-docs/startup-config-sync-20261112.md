# Godot 启动时检查 Git 与 AI 配置

用户于 2026-11-12 要求每次打开 Godot 引擎校验当前 Git 和 AI API 配置，并拉取所需内容；随后明确 Git 策略为“获取远端，满足条件时快进更新”。当前 Codex 会话负责实现、验证及 main 交付。

启动编辑器后后台执行一次，可从统一设置查看分项结果并手动重试。检查当前打开项目所属 Git 工作树、分支、上游和本地状态，获取其已配置远端；只有工作区干净、无合并等在途操作且可快进时更新当前分支。无仓库、无上游、本地修改、分叉、离线或身份失败分别说明；不自动提交、stash、reset、切分支或处理冲突。操作设期限，关闭编辑器取消在途进程。

AI 检查复用项目通用配置、现有连接探针和天枢模型发现/个人模型库接口。已具备工作区身份与运行环境时后台刷新可用模型信息，缺项给出进入配置的入口；不自动切换当前模型，不把枚举成功当作连接成功，绿点仍由当前配置实际响应决定。启动刷新不抢占当前页面，不在日志或项目中保存密钥，不自动安装软件或下载模型权重。正常 GUI 编辑器启动触发；headless、命令行、恢复模式默认不发生远端操作，测试从显式入口运行隔离桩。

验收：1. 每次普通编辑器启动恰好触发一次，后台运行且状态可查看/重试；2. Git 远端获取及干净快进成功，脏工作区/分叉/无上游等分支不破坏内容；3. 超时、取消、离线和重复操作有确定结果；4. AI 缺配置和真实成功/失败分别显示，复用天枢拉取，失效回执不覆盖新配置；5. 无页面跳转、凭据落盘或未经请求的模型安装；6. 本地候选原生静默检查、相关回归、独立审查及精确候选 CI 通过并回读 main。
