# 天枢在真实工作区加载与切换工单

需求 `tianshu-real-issue-load` 对应 [工单 #533](https://github.com/zhzyx/nightmarish-spooky-sorceryze/issues/533)。用户在 Windows 安装版从详情返回总览或切换工单时感觉卡顿，实际入口包含已挂载的工单推进对话。

## 导航与保存

切换时立即在内存中保留当前正式工单的图、答案与个人布局；完整私有快照沿用已有合并保存计时器及退出时的同步写入。个人新需求继续立即保存，保留需求正文检查点。先显示选中工单的本地快照，再在后续帧启动最新流程读取。启动读取前和收到回执后都核对选择代次、账号、仓库与 URL。恢复既有详情时直接挂载所保存的工单，不先绘制隐藏总览。

## 推进对话

将会话内容与定时会话提示挂到已验证的工单宿主。设置、定时器、会话导航、计时器与后台请求保持原有归属。定时器页面刷新时按当前宿主决定普通会话内容的位置；定时会话仍由定时器页管理。切单与恢复独立 AI Chat 时继续沿用原生权限检查及会话标识。

## 验收

以安装版、真实工作区缓存与对话的隔离副本，在 Windows OpenGL 图形编辑器中打开 #534 的失败对话，返回原工单、切至实际带 12 个节点的 #56、返回总览，分别测量调用耗时与连续帧间隔。验证显示已保存的本地需求、列表及依赖图，快速改选不发起过期读取，异步读取期间能继续交互。数字、测试入口与边界见 [实测记录](../data-collection/issue533-real-navigation.json)。

既有受支持工作区的只读增量适配扩大到另一份经核对的官方脚本摘要，保留现有现代脚本和未知自定义脚本的原入口。Windows 集成测试使用独立编辑器与独立设置目录。用户原工作区、草稿和运行中的编辑器不参与自动测试写入。
