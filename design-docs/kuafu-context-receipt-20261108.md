## 已复现事实

在来源提交 `a144411fb39d6470ed2b70a9f6ea6ad8220695ac`，本机真实 Node v24.22.1 用同一框架快照与正常只读委托执行 Kuafu context CLI：正典入口退出 0，输出 5930 字节并含真实职责及委托；目录链接入口、macOS `/tmp` 到 `/private/tmp` 别名入口均退出 0，却没有 stdout 或 stderr。

`agent-context.mjs` 的 CLI 保护比较词法 `path.resolve(argv[1])` 与实际模块路径。接单器从未经正典化的临时目录构造脚本入口，可能完全未进入职责装配逻辑。`bind_context` 又把空 stdout 的 SHA256 作为接收回执，未拒绝空内容。

#542 的原始 receive 输出为空，原 received 回执的 context SHA256 为 `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855`；后续文件事件的 recorded_file 仅证明落库，不证明职责加载已完成。原 received 文件摘要 `b5a8121b4c50c08eebbc54f026c511fe33757dfaa30e1ba70dc693567de516ac`、原事件摘要 `d9aafed3598c6b6da77597eb8578b6de6c883fe3d29929b78603da642fd17f41` 保持不变。独立临时 CLI 复现报告摘要为 `98d7e3424da999e7d3c5ccfbc231f25e99af19a4f34fd0f890e5e5960af784e0`。

## 最小修复与边界

1. 对可信 main 框架解包路径及实际 context 脚本入口做正典化，使现有 CLI 保护正常执行。
2. 在职责 stdout 为空或仅空白时准确失败，不创建或改写成功接收回执。
3. 保留现有仓库、操作者、Issue、需求、准入与上下文变更拒绝规则。不修改框架 CLI 保护、Agent 定义或冻结纲领，不增加工具权限。
4. 原错误回执与落库事件保持原件；新增纠正证据明确旧记录的证明范围，不将历史空正文补写为已读职责。

## 验收

- 正常可信框架快照经非正典临时目录取得的接单根为正典路径，真实 CLI 输出非空职责与同一委托。
- `bind_context` 对链接路径入口仍真实执行当前 Kuafu 职责；未改变 CLI 导入保护。
- 空及纯空白输出均拒绝，新接收文件不产生，旧接收文件不改写；子进程失败继续失败。
- 正常非空接收、重试幂等和已有不同上下文拒绝保持；测试使用私有目录和模拟 GitHub，不执行生产接单或模型。
