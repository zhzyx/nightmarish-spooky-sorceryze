# 原生任务定义换版与固定验收依赖

需求 ID：native-workflow-revisions-20261118。父 #1444（原生需求到交付链路），本子项不缩减原父项验收。路径以仓库根解析。

用户要求固定输入制作不因无关发布前进反复重做，并允许真实需求变化后继续自动推进。PR #1452 已交付首批原生链路，但当前 issue UNIQUE 绑定无法显式换版，依赖验证还错误要求发布频道保持同一指针。已独立实测：上游相同 candidate、同一有效 approval 再次发布，仅产生新选择事件，就使下游 reserve 报 Dependency release no longer current。

## 行为与边界

1. 为同一原生工单保存多份不可变任务合同及显式 active 绑定。换版必须带 expected 原 active 标识，当前认证身份有权授权，输入来自已安装计划；不接受客户端任意命令/actor/来源。并发换版仅一个成功，同操作稳定重放。
2. 原合同、已产出内容、审查与历史验收保留。已被替换的任务不能开始新生产、结束新定义或产生依赖放行；已在运行或结果未知的旧工作保持实际物理占用，直到可信终态到达。晚到终态只能结清旧工作，不覆盖新工单进度。不按超时自动抢占或重启。
3. 固定依赖引用精确验收记录和内容。发布频道的无关变化或同内容新选择不使旧依赖失效；仍核对当前读取权限、原 approval 撤销/过期、检查政策、内容完整性及真实发布事件。被新定义替换的原任务不能作为新定义完成证明；旧验收作为固定内容版本的适用性由合同明确，不混淆当前业务完成。
4. 原领域数据库在一笔短事务内迁移任务表、active 映射和定义历史，不改变真实 worker 状态。迁移失败全回滚；旧 schema 真实持久 fixture 验证、重启幂等、关闭新入口后的数据回读验证。旧程序不能悄悄按已移除唯一约束误处理多版本数据，回退要求已验证兼容读或显式拒绝。
5. 从真实 Python 和认证 HTTP 入口验证换版，取消/撤权/并发/未知旧工作/重复请求/跨组织反例。用真实 producer/check/review/acceptance 验证频道前进后固定依赖仍可继续；真实撤回必须拒绝。
