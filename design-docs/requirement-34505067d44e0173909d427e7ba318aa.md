# 中文显示与 UTF-8 读写验收

[工单 #115](https://github.com/zhzyx/nightmarish-spooky-sorceryze/issues/115) 要求修复中文乱码，统一开发文件的编码，并验证编辑器与运行时可以正确读取、显示和保存中文。路径相对仓库根。

## 文件编码

在主线 c096647f 的 24,836 个 Git 跟踪文件中，按前 8 KiB 含 NUL 区分出 124 个二进制资源或包，其余 24,712 个文件逐一严格解码。唯一失败的是 thirdparty/linuxbsd_headers/X11/extensions/Xge.h 第 2 行版权符号。将单字节 A9 转为 UTF-8 C2 A9 后，全量复查通过。头文件的字符、换行与接口均保持原样。仓库根的 .editorconfig 已指定 UTF-8。

## 编辑器与运行时

此前的提交 5bc53846 修复了 AI Chat 中传给 Godot String 的中文标签。当前源码以 UTF-32 字面量构造“会话”“定时器”“共工”和初始的“会话 1”。#113、#114、#117 的人工验收记录可在各自工单查阅。

本次在 Windows 隔离项目中使用已有的 Godot 4.8.beta 自定义构建 d492e0b4a，以 headless 编辑器读取真实标签控件，随后写出“存档.txt”。独立运行时进程读回“会话与共工：中文读写。”并赋值给 Label；宿主另行逐字节核对 UTF-8 内容。两次进程退出码均为 0。测试核对控件字符串及文件字节，未做桌面截图。此次头文件修改只涉及 Linux/BSD 第三方头文件中的版权注释。

## Windows 中文传输

共工桥接命令和环境点火器此前按进程代码页输出 JSON。缺失请求文件的名称含“中文”时，CP936 产生了无法按 UTF-8 解码的字节，CP1252 未输出可解析 JSON。两处入口现显式输出 UTF-8。在两种旧代码页下分别验证桥接错误包含完整中文文件名，环境检查成功输出包含中文的组件路径。桥接测试 43 项及点火器测试 15 项通过。

Windows PowerShell 5.1 的配置代理在调用子进程期间指定 UTF-8 来解码工具输出，并在结束时恢复原控制台编码。以 CP936 启动，探针验证日志保留“中文”，结束后编码恢复到 936。本地工作台启动脚本显式以 UTF-8 读取配置；用无 BOM、含中文的 JSON 验证读取结果。

历史采集原件保留。当前 headless 编辑器的初始化日志可正确解码并读出中文。独立核查的派发与终态回执关联到本需求的谛听事件。
