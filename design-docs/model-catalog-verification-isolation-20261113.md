# 模型验证隔离与凭据版本

<!-- gonggong-request:model-catalog-verification-isolation-20261113 -->

关联 Issue #979，父需求 #978。路径以仓库根为基准。

## 问题与验收

显式选择 Codex 后验证失败，旧逻辑继续调用 CodeBuddy；同一 API 配置更换凭据时，旧 live 证明仍可被司南采用。本单修复验证范围和凭据替换状态，保留已有本地目录发现、手动注册和 synthetic 评测。

1. 显式选择的连接失败或未配置时，返回该连接原因，不验证另一个供应商；无选择的自动发现保留原有行为。
2. 明确保存凭据时，原 live 证明立即失效；synthetic 结果保留。发现已有配置不覆盖用户存储的凭据。
3. 跨进程保存与在途验证发生交错时，旧回执不能让新凭据获得准入；首次导入不互相覆盖。
4. 外部凭据存储写入失败、部分写入或数据库提交失败时，配置保持不可验证状态；用户明确重新保存可恢复。
5. 使用隔离数据库、内存凭据替身和模型替身完成回归，不调用真实付费模型或真实密钥。

## 实现

`model_catalog.py` 将来源发现与明确验证范围分开。未知的显式 backend 在发现之前拒绝；缺少所选 API 配置返回可操作说明。保留无 backend 时原自动模式。

新增 `credential_revisions` 表记录随机版本及 pending/ready 状态。保存第一事务撤销 live 证明、持久化 pending；第二事务核对版本，在写锁内更新外部凭据、注册配置及 ready。失败不会把 pending 回滚为旧的有效状态。并发显式保存中被后一次取代的保存不触及凭据存储；自动发现遇到 pending 不覆盖，已存在配置保持幂等。

验证开始时捕获 ready 版本，写回 live 回执时在同一事务中核对版本。旧请求、无版本调用以及未完成保存均不能写回证明。历史数据库按需增加版本表，旧配置初始版本为空；首次明确保存推进到新版本并撤销旧证明。CLI 仍按已有精确运行配置标识，账号变更及目录生命周期由父需求另行处理。

## Review 与验证

首次独立 review 发现仅提前删除证明仍有两处竞态：旧验证在删除后恢复证明、内层事务提前提交破坏首次导入互斥。两项均已复现并按版本机制修复。定向复核确认两项修复，同时覆盖旧 schema 迁移、阶段之间第二次导入、并发显式保存。

回归命令：`PYTHONPATH=customizations/components/godot-host/daqian:tests/editor python3 -m unittest test_daqian_models test_daqian_local_models -v`。20 项通过，包含失败来源隔离、缺失 API 不回退、存储失败失效、迟到验证、pending 恢复、双线程首次导入及已有运行路径转换。

这是 Python 个人目录行为验收，不代替原生编辑器、多平台系统凭据库或真实供应商验收；本次没有修改有效安装或框架定义。公开证据在 `data-collection/model-catalog-verification-979.json`。
