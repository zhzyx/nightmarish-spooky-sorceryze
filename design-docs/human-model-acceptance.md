# 人形模型验收规范

<!-- gonggong-request:maliang-priest-head-proportion-20261112 -->

版本：2026-11-12。适用对象：人形角色及其头部替换、比例调整、材质调整和 GLB 交付。本文是项目验收清单，不是某个生成服务的宣传指标，也不是永久不变的审美模板。

## 一、验收原则

1. **先证明文件正确，再评价外观。** GLB 结构、索引、坐标、材质和引用不正确时，不能用好看的预览掩盖。
2. **全身与局部同时验收。** 近景只能证明局部细节，不能证明头身比例、肩颈衔接、姿态或整体轮廓。
3. **数值与视觉互相印证。** 比例、顶点数和文件大小是辅助证据，不能代替真实渲染和人工判断。
4. **保留原始资产与未知项。** 新结果必须另存，原文件不覆盖。未测试的项目标为“未知”，不能自动写成通过。
5. **实际渲染高于服务预览。** 服务返回的图片可用于参考，但最终验收必须包含目标引擎中的真实 GLB 渲染、加载和保存重开。

## 二、状态约定

- `passed`：有实际证据且满足该项要求。
- `failed`：有实际证据证明该项不满足要求，必须修复或保留问题。
- `unknown`：尚未验证、证据不足或不适用于当前范围。不得把 `unknown` 写成 `passed`。
- `not_applicable`：明确说明为什么该项不属于本次范围，例如未要求绑骨。

## 三、验收清单

| 维度 | 检查内容 | 通过依据 | 常见误判 |
| --- | --- | --- | --- |
| 来源与版本 | 原图、原模型、操作任务、输入模式、源／目标 SHA-256 | 来源可追溯；新文件独立；原文件未覆盖 | 用旧模型冒充新结果、覆盖输入、丢失上游任务 ID |
| GLB 结构 | 文件头、JSON／BIN 块、缓冲区、索引、材质和依赖 | 可独立解析；索引不越界；引用完整；无意外外部依赖 | 重复块头、长度错误、索引分组错误、材质索引错位 |
| 坐标与原点 | 单位、朝向、节点平移／旋转／缩放、世界与本地坐标 | 修改后姿态、位置和比例符合目标；变换链明确 | 用世界坐标的切割高度直接缩放本地顶点 |
| 几何有效性 | 有限顶点、有效三角形、法线、严格零面积检查 | 无非法索引、无非有限值、严格零面积三角形为 0 或已解释 | 把大量微小三角形直接称为破洞；只检查法线存在便宣称无缺陷 |
| 头部大小 | 头高、头宽、头身比、头发体积、肩颈比例 | 全身轮廓协调；头高／头宽与角色风格一致；没有头重脚轻 | 只看正脸近景，不看全身；只按固定比例数值验收 |
| 脸型与五官 | 脸型轮廓、脸颊、眼睛、鼻子、嘴、下巴和耳朵 | 与参考的特征差异可解释；无明显凹坑、错位、异常折痕或破损 | 把生成服务的“相似”当作身份保真；忽略脸颊和下颌 |
| 头颈衔接 | 颈部位置、接缝、穿插、双下巴、材质过渡 | 颈部位置稳定，无明显裂缝、重叠、第二颈部或突变 | 头部缩小后颈部位移、接缝穿插、身体皮肤覆盖到脸部 |
| 材质与纹理 | 材质索引、纹理索引、采样器、皮肤、布料、金属和头发 | 资源对应正确；无错贴图、异常黑块、明显拉伸或服装纹理覆盖皮肤 | 头部使用身体材质、纹理来源错误、采样器不匹配 |
| 表面与 shading | 表面连续性、法线表现、折痕、闪烁和背面表现 | 受检角度无明显异常凹凸、闪烁、非预期黑面或严重锯齿 | 把纹理或光照问题误判为几何破洞，或反之 |
| 姿态与轮廓 | T Pose、肩宽、手臂、手指、腿部、脚部、法袍和肩甲 | 姿态清楚、结构完整、无缺肢或严重穿插；轮廓与需求一致 | 只看正面忽略背面、手臂和衣物结构 |
| 多视角 | 全身正面、斜侧面、背面、正脸和斜侧脸 | 每个要求视角均有真实截图或明确未验证标记 | 用服务单张预览代替所有角度，漏掉后脑和颈部 |
| 文件与性能 | 顶点数、三角形数、文件大小、资源数量 | 满足当前工具预算；减面后仍有足够面部细节 | 把减面目标当硬上限；为了数量牺牲脸型或材质 |
| 原生加载 | 目标引擎导入、预览、材质、坐标和姿态 | 实际 GLB 能加载并正确显示 | 只验证下载成功或服务预览，不验证引擎资源 |
| 发布与重开 | 原生资源保存、重新打开、几何和材质保持 | 重开后边界、顶点、材质和姿态保持一致 | 只看首次加载，未验证保存后的真实资源 |
| 调整与修改 | 文字／图片上下文、材质修改、比例修改、独立输出 | 实际参数生效；原模型不覆盖；修改类型与能力一致 | 用 `texture_3d_model` 承诺任意几何编辑或精确局部遮罩 |
| 证据与隐私 | 任务 ID、日志、摘要、截图、验证 JSON、限制项 | 证据与具体候选对应；无凭据、签名 URL、原始响应和隐私素材进入公开记录 | 公开原始人脸、密钥、签名 URL、私有路径或大文件，除非明确授权 |
| 未声明能力 | 绑骨、动画、生产拓扑、身份保真、无缝拼接 | 只有实测后才能声明；未测标为 `unknown` | 因单张图片好看便宣称生产级角色、无缝拓扑或可动画 |

## 四、头身比例的检查方法

1. 先记录颈部基准线，例如 `neck_y`，并说明它是世界坐标还是节点本地坐标。
2. 计算：`head_height = head_top_y - neck_y`，`full_height = max_y - min_y`，`ratio = head_height / full_height`。
3. 同时检查头宽、头发体积、肩宽、颈部位置和手臂姿态，不能只看一个比例值。
4. 若需要缩放，必须将世界坐标中的基准点正确转换为节点本地坐标。减面服务可能重置头部原点，不能直接沿用合并前的本地切割高度。
5. 数值范围只作为辅助。当前人物的 10% 缩小试验是局部纠偏，不是所有角色的固定标准。

**本角色修正结果：** `neck_y = 0.34`，头部整体缩放 `0.90`，修正后比例约 **14.5%**。该值与全身、正脸、斜侧面和背面共同验收，不单独构成通过理由。

## 五、推荐执行顺序

1. 固定原图、原模型、任务 ID、源摘要和验收范围。
2. 检查 GLB 结构、缓冲区、索引、依赖、坐标和材质引用。
3. 验证有限顶点、三角形、法线和严格零面积；保留微三角形分布，避免把密度误判为破洞。
4. 渲染全身正面、斜侧面和背面，先看比例、姿态、轮廓和颈部，再看脸。
5. 渲染正脸与斜侧脸，检查脸颊、眼睛、鼻子、嘴、下巴、耳朵、头发和材质。
6. 检查纹理与采样器、表面 shading、穿插、闪烁和隐藏面。
7. 核对顶点数、三角形数、文件大小与目标平台预算。
8. 在目标引擎中加载、发布、重新打开，确认几何、材质、坐标和资源身份未异常变化。
9. 如执行调整，另存新文件，记录参数和源／目标摘要；不得覆盖原模型。
10. 最后列出通过、失败、未知和不适用项，不写超出证据的结论。

## 七、禁止的“假通过”方式

- 用近景掩盖头部过大、颈部穿插或身体比例失衡。
- 用服务预览图代替目标引擎中的真实模型验收。
- 把大量微小三角形直接写成大量破洞，或把法线存在直接写成表面无缺陷。
- 用错误的坐标基准、索引或材质映射生成“看起来已完成”的文件。
- 把未测试的背面、绑骨、动画、生产拓扑、相似度或通用能力写成通过。
- 用旧模型覆盖原文件、用重复任务冒充新模型、用没有证据的“自然”或“完美”收尾。
