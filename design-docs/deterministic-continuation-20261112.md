# 确定性任务连续执行

稳定需求 ID：deterministic-continuation-20261112。路径以仓库根为基准。

工单：[#953](https://github.com/zhzyx/nightmarish-spooky-sorceryze/issues/953)。

用户报告相同任务 Astra 能连续完成，6.1 Sol、Kimi 在多个入口出现反复确认、猜测和问答。本次授权：调查原因、寻找并落实可验证的改进。执行责任为当前 Codex 会话；不接管 #951、#773 的在途生产。尚无同任务、同工具、同推理强度的配对记录，不能认定根因是推理强度，也不能声称某模型必然完成。

当前证据：根 AGENTS.md 和 execution-policy 已要求持续交付，但原生派发的独立上下文 handoff 只有范围和验收提示，未携带执行/提问/结束的简明判定；Godot 共享上下文的 host mandate 主要携带权限、工单与交付要求。本次将同一套模型无关的执行约定放在这两个实际提示词入口及仓库入口，并明确宿主限制继续有效。提示词改善是待实测的干预，不等同于宿主强制续跑。

范围：接入层提示词和仓库执行约定、针对实际上下文组装与派发的回归，以及可复用的对照实验方案。不更换用户模型，不修改全局个人配置、冻结框架或 Agent/Skill 定义，不新增后台服务，不绕过工具审批、独立验收或人工保留决定。目标平台为现有 Python/Node 宿主，未修改原生引擎；不需编译 Godot。

验收：
- 确定性判定基于明确目标、已有授权、可用工具、可验收结果；先读事实再行动，常规可逆实现自主决定。
- 澄清仅限无法通过现有来源获得且影响正确性/授权的必要输入；保留只读、暂停、预算、权限与真正人工决定。局部阻塞不停止独立项。
- 执行者区分工作者终态、产物、验证和业务验收；阶段成功后继续下一已授权步骤，未知发布结果先回读，不盲目重试，不以自报完成替代验收。
- Godot 共享上下文和 Codex 独立 handoff 实际携带约定；策略变化使长期会话上下文失效，普通续聊仍复用未变治理上下文；原有工具/只读限制保持。
- 相关回归、独立审查、正式门禁、精确候选 CI/main 回读及本单收尾。模型对照效果明确记为未测，不能用提示词字符串测试冒充行为成功率。

方法召回：editor-dependency-handoff 的 await-terminal-observers、bind-consumer-release 适用：模型/进程结束不是业务验收。只读咨询为反例，不触发生产或交付。当前不修改已有方法记录。

进一步的宿主控制方案：复用原任务账本，在真实工具结果或回合结束事件中回读完整验收、权限和在途状态；有可执行步骤则推进既有执行入口，需要外部结果则等待原完成事件，需要必要决定则一次汇总。任务完成仅由权威验收决定。没有进展时保留失败回执并转排障，取消、权限撤销、预算耗尽立即停受影响操作。不可用的宿主继续能力必须如实标未接通，不能用定时发送“继续”、关键词识别“完成”或放宽审批代替。Codex 桌面回合调度属于产品宿主，本仓库不能通过 AGENTS.md 强制拦截其结束。

对照实验：固定任务、仓库修订、工具权限、输入和验收，分别比较原指令/本约定，以及模型支持的相同 effort；记录实际型号和生效 effort，不能把 API 默认值当桌面值。样本包含确定性修复、工具可查信息、失败复验、缺少必要产品决定、只读任务、工具拒绝、丢失发布回执、用户取消。比较无需人工接力完成率、无必要询问数、验收通过率、错误越权/虚报次数，以及实际时延和用量；没有实测保留未知。Kimi 的型号、凭据与推理参数由实际宿主提供，不假设与 OpenAI 参数同名或语义相同。
