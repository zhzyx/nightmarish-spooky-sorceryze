# 天枢路由进度和澄清输入窗口

关联工单 #520，需求 ID 为 tianshu-routing-stage。来源为 #511 修复后的实际桌面验收。用户通过当前 Windows 编辑器创建 #518，司南及偃师先后正常返回；打开澄清后模态窗口高度为 2772 像素，上沿与底部按钮越过工作区，造成无法退出的体验。已通过只关闭该对话框恢复操作。

验收要求为同一工作台中显示已核验的当前路由阶段、保留最后澄清请求，长问题可滚动，输入、提交、取消、标题关闭和 Esc 可达，取消不提交、同问题重开保留回答。使用实际 #518 问题、长和多问题测试不同工作区尺寸；不产生新的模型调用，不提高自动远端读取频次。

用户追加流程图验收：偃师提出的问题、待确认状态和可填写答复入口需要醒目显示。按真实输入关系连接偃师、问题和答复节点；相同一轮多个问题共用一次答复。在正式回执核实后保留已答复节点，再分支连接并列的预计任务、验收和后续流程。不得把未收到回执或尚未执行的计划显示为已完成。
用户最新现场反馈为点击“填写答复”后的二次输入窗口仍产生明显卡顿。正常填写改为直接定位或展开展示在画布高亮输入节点内的 TextEdit，直接输入和提交，无须新原生窗口。图不可呈现时才沿已修复尺寸的澄清窗处理。验证真实鼠标点击、焦点、键入退格、Esc 离开、草稿保留和准确绑定；不重复提交。
用户实机反馈鼠标在弹窗上时出现底层画板的交互光标。分别验证弹窗真实命中、空白区/编辑区/按钮的悬停光标以及点击、滚轮、拖动是否影响画板。修复确认存在的输入层级问题，验证关闭后的画板恢复，避免对整个编辑器或弹窗输入做全局拦截。
画板文字清晰度也纳入本次验收。以当前编辑器字体及 Windows 图形渲染，比较总览和工单图的 85%、100%、120% 缩放；图卡标题、正文、状态和输入文字随实际显示比例栅格化，保留个人缩放、字体偏好及运行时性能。
