# R09 重开编辑器时收回无主的本机占用

工作台登录业务项目后调用认证服务的 `POST /api/v1/native/workflow/recover-occupancy`。本机预约与实际启动分别登记宿主、系统启动标识、进程身份、工作目录、原账号与任务运行号。macOS 和 Linux 的本机组进程启动后另记组号。恢复时在同一写事务核对活动契约、原项目、账号、当前执行权以及拥有者的物理状态。两个窗口同时重开时，首个成功者将原票据的占用转给本机服务，后一个读到已存活的拥有者。

原监督进程已退出而工作者组仍然存活时，预约保持原状。已确认整组消失但缺少输出回执时，服务释放槽位并保留 `closed-unresolved`。后续产物对账使用原运行号。远程适配器、宿主无法核实，以及旧任务缺少可信进程记录时，沿用原有恢复流程。[R09 工单](https://github.com/zhzyx/nightmarish-spooky-sorceryze/issues/1778) · [原有恢复清单](gonggong-ai-workbench-r05.md) · [原有预约](gonggong-ai-workbench-s08.md)

macOS 定向验证由独立协调进程预约两个任务并启动其中一个生产者。强制终止协调进程后，两份独立安装目录内的候选编辑器用同一账号的不同会话同时进入工程。服务只对未启动的运行发出一份续领回执，另一运行保留实际进程组。等该组退出后，服务只收回一次占用。服务端另验未认证、其他账号与其他项目。[候选、两个编辑器 PID 及逐单回执](../data-collection/gonggong-ai-workbench-plan1-r09.json)
