# 内部只读子验收与自动回父

稳定需求 ID：internal-readonly-review-20261108

## 来源与授权

原业务验收 Issue #483 暴露：模型可读父上下文，却没有创建内部只读子验收的工具。生产工单自动子会话明确以开发模式运行，正文“只读”不是宿主权限限制。

用户在 Codex 聊天要求验证编辑器内 Agent 从聊天、拆解、实现、自编译、子验收到 Git main 的流程，发现问题即打断并修复，并要求编辑器体验与 Codex 一致。本次由该验收责任者委派隔离修复；不是新造 GitHub 用户请求或扩大凭据权限。

## 设计定版确认

提供可发现的 `delegate_review` 模型工具。已授权生产父可以排队一个内部只读审查，父本轮正常结束后执行。宿主强制只读，子会话不能通过篡改消息模式提升为生产；仅读取文件、目录、日志、编辑器状态与父上下文，禁止写入、执行、构建、工单操作、再委派及交付。

复用当前真实子工单批次的身份检查、受界限回执及自动回父。返回审查是数据，不是自动业务验收，`business_accepted` 保持未知。保留原父会话身份和绑定候选；正常回传启动后续父轮会产生新的正常快照。停止、失败、权限变化或身份漂移不得假报完成。原生产工单子会话行为保持兼容。

## 验收

1. API 与 Codex 原生工具清单可发现 `delegate_review`；顶层已授权父可排队，递归/仅咨询/未绑定/冲突批次被拒绝。
2. 内部子会话真正以宿主只读模式运行，篡改 consultation_only=false 仍不能写/执行/构建/交付/再委派，不启动生产 intake 或新候选。
3. 子可读取父上下文和真实源码/回执，真实读取结果与终态保存；失败或停止如实保留。
4. 子结束自动回原父，身份及候选来源守护不变，结果不自动判业务通过；现有生产 design children 不回归。
5. 适用验证、独立审查、正式门禁、精确签名 CI 与 main 回读分别留证。

## 边界

不支持仅咨询尚未实现的 CodeBuddy 原生通道；明确拒绝而不降级权限。不编辑当前 #483 源、会话历史、运行 App 或全局配置。真实业务中的端到端子验收由原父在合入并重编译之后实测。
