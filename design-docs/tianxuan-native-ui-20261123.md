## 原始需求与已确认目标

原始需求：“当前godot编辑器内的天璇界面还是基于web的，期望能够在编辑器内搭建原生的UI进行显示和处理。web端功能保持。向我提问明确所有目标后开始”。

用户逐项确认：

1. 全部功能原生化，按模块实施，最终在编辑器内完整使用。
2. 主工作区与可停靠侧栏都需要，共享业务身份、会话和任务状态。
3. 必须支持并验收 Windows 与 macOS。
4. 共用现有后端、账号、权限和数据；断网保留草稿，重连后同步。
5. 视觉与框架要求原文：“迭代godot原生引擎框架。实现目标表现结果”。实现可扩展原生控件与编辑器框架，不能以现有控件能力为由缩减交互目标。
6. 四项编辑器联动全部纳入：项目绑定、文件或脚本跳转、资源导入、选中节点或资源作为对话上下文。

用户同日追加：“当前天璇界面内的呈现也不是很高级，需要优化一下表现效果”。因此原生化同时进行视觉与交互升级，设计重点为清晰文字层级、统一色彩与间距、克制强调色、对话／文档可读性、任务状态和进度反馈、主工作区分栏、紧凑侧栏、深浅主题与高 DPI。现有 Web 作为功能对照，原生界面承担本次视觉优化的首要交付；仍保留 Web 功能兼容和回归。

文档保留 Markdown 编辑、预览、实时协作、冲突处理、版本比较与恢复。原生界面正常操作不依赖 WebView。独立 Web 端仍能使用同一数据及原有能力，纳入回归。

## 实现边界

- 使用 Godot 原生 Control、容器、文本、树／列表、菜单及弹窗；必要的框架迭代以可复用、可验证的编辑器组件承载。
- Model／Controller 持有权威业务状态、认证、异步传输与迟到回执判断；View 仅收集意图和显示快照。主工作区与侧栏切换不创建第二份状态，不中断请求，不丢失草稿、焦点和选择。
- 复用现有后端语义，原有版本、身份、审批和幂等规则持续生效。仅为原生客户端确有缺口时扩展兼容接口，并同时验证 Web 调用方。
- 凭据不进入项目文件、日志或版本库。原生端执行同源约束及 HTTPS／本机回环策略；身份切换隔离缓存和草稿，拒绝旧身份迟到响应。
- 断线保留修改及服务器基线；重连先回读再合并，有冲突保留双方内容。不自动重放未知结果的写操作。
- 服务端已有任务不因收起视图取消；本机工作者沿其既有任务生命周期与关闭策略管理，不以本次 UI 迁移改写 #1709 的检查点和退出约定。
- Web 页面及原有部署保持兼容，不开展与本次原生 UI 无关的生产迁移、历史工单执行或权限重构。
