首要目标是同等质量与验收下最大化 AI 有效产出，降低用户 token、总耗时和介入次数；避免主线持续变化导致反复校对、重做与合入饥饿。产品功能跑通与视觉为次级优先级，仍保留完整范围。

- 天璇为统一平台，文曲管理文档，多宝管理版本与资产，偃师设计，司南协调派发及按任务能力/复杂度选择模型，合契整合，阎罗交付，谛听留证，夸父排障；复用现有职责，不另建协调 Agent。

- 首轮每组织 250 个在途任务。此为测试负载，不是 250 个模型/构建同时运行的承诺。
- 仅现有服务器；复用本机和已有执行节点、多 CLI/API。日常自主执行与审查责任沿用已有规则。
- 原生多宝不依赖 Git 程序、仓库、GitHub、Gitea。Git 可作为本次实现代码及历史记录留底、迁移来源和可选导出；不得作为新内核运行时接收/验证/发布成功的前置条件。

- 代码、大文件、图片、音频、模型、子模块迁移、构建产物、发布包、网页代码编辑与远程执行环境均保留在整体范围。
- 并行文档编辑、表格与可视化重要；文档/工单/代码统一关联；偃师需求保存、拆单和自动进度回写。
- 同步现有 Git 设计、Issue/PR、飞书和 Confluence 等实际可访问来源；保留来源身份、修订、历史及失败，不能把缺连接计为完成。

2026-11-17 后续用户决定：完整目标包括 AI 友好的引擎本体和多 Agent、多内容工作流；已有架构均可按目标重构，不把现有代码组织视为不可改变的边界。渲染与 3D 至少支持 AA 级游戏制作是硬约束，不能通过削减画质、游戏能力或性能达成 AI 效率。画面参考《血源诅咒》的写实方向与沉浸感，首验 Windows PC，其他平台保留扩展；最低显卡、分辨率和帧率尚未确定，先测量基线再共同确定。本机只读设备枚举显示 RTX 5080 与 Intel Graphics；这不是游戏最低硬件承诺。

### 渲染与 3D 不降级验收

当前来源 version.py 为 Godot 4.8 beta；源树包含 RenderingDevice、Forward+、Mobile 及 Jolt 等，存在源码不等于当前安装二进制已启用、可用或达到 AA 质量。

先在固定资产、镜头、配置、可执行文件和驱动上建立真实 GPU 基线：室内/室外写实材质与光照、阴影和雾、角色动画与接触反馈、特效、场景加载及空间音频。测量 CPU/GPU 帧时间分布、帧尖峰、内存/显存、加载停顿与实际画面；具体场景规模与阈值由基线和用户目标确定。禁止用 headless/dummy renderer、接口存在、截图或单一平均帧率代替全体验收。浏览器工作台兼容不降低桌面渲染基线。

必须比较后台多 Agent 工作时前台编辑器与游戏的表现，避免 AI 任务争用 CPU/IO/GPU 造成交互或游戏帧时间退化。渲染器/资源管线替换前保留旧版本并通过相同场景功能、画面、性能及恢复试验。

## 目标架构

1. 诉求与上下文：保存原话、决定与验收的修订，提供带来源的任务上下文及变化；允许主动展开，不以摘要代替原始证据。确定性检索、比较、对账不默认调用模型。
2. 内容存储：不可变内容摘要与模块修订；Git 无关的组织/对象身份、操作 ID 和幂等回执。只生成改变对象的新版本，不复制整个工程作为业务协作单位。
3. 模块修订：模块 ID、父修订、内容摘要、导出接口、精确依赖修订、构建类别、候选证据引用。模块内对象版本条件更新；无关模块推进不产生冲突。同模块不相交对象允许合成，读取对象变化则拒绝静默重用。
4. 接收与验收分离：接收持久化不等于通过；候选、已验收、可消费、已发布分别留证。先支持原子候选接收及确定性依赖校验，独立审查由现有责任链签发，不让提交者自证批准。
5. 产品组合：发布清单是模块 ID 到精确修订/产物的映射，显式固定依赖闭包。兼容升级可独立消费；跨模块接口变更作为一组候选整体验证并原子切换。不建立供每个 Agent 追赶的全局 main。
6. 验证：输入摘要、精确依赖、工具链/规则/环境决定证据缓存；未知依赖不视为独立。最终可运行组合验证不省略。真实冲突由合契局部处理。
7. 执行：既有节点按需物化普通文件快照以支持 CLI、编译器及 Godot；缓存可复用。物化目录无 Git 管理元数据，不作为版本权威，不要求模型维护分支/同步。
8. 调度：司南按真实容量、依赖、能力和等待时长派发；幂等、真实终态与事件恢复。资源耗尽可明确背压，不以隐藏队列或持续模型轮询伪装无等待。
9. 协作文档：稳定块/行列身份与并行编辑；结构化编辑模型、Markdown AI 表示及导出。CRDT 仅承担适用的数据合流，不承诺程序语义自动正确。完整格式契约在接入文曲前固定。
10. 部署：先模块化单体与本地持久存储验证，不提前引入微服务集群。短原子存储操作仍需一致性；不能用长期全局锁包住模型、检查或构建。

## 可独立交付的子项与先后关系

- P0-A：原生模块候选与内容存储；对象级读写集、幂等、并发、跨模块原子组合、精确依赖、重启恢复。无 Git 环境验收。
- P0-B：既有模块边界审计与依赖提取；区分原生、嵌入、运行包、宿主工具；不能按后缀整体豁免。

- P0-C：证据缓存、独立验收与发布清单；接收不等于验收。依赖 A/B。
- P0-D：已有 CLI/API/司南/合契/阎罗/谛听接线、上下文增量与执行快照；依赖 A/C。
- P0-E：当前实现与新内核同任务 A/B；250 在途任务、持续无关更新、冲突、失败和公平性；真实 token/耗时留证。依赖 A–D。
- P1：文曲并行编辑、表格/可视化、工单与模型能力整合、资产及开发环境、迁移、Godot/浏览器 UI、服务器部署与恢复。复用 P0，完整范围不因优先级下降而删除。

## 验收与停止条件

- 无 Git 程序或网络依赖时创建模块、编辑/读取、版本回溯、候选接收、依赖组合及最终交付成立。
- 无关模块持续更新时，已固定任务不会被要求重新生产，未受影响证据不重复生成。
- 同模块独立修改保留双方；已读对象改变、接口不兼容、同对象冲突不静默覆盖；依赖未知必须显式处理。
- 跨模块原子提交、重启恢复、幂等重放和失败恢复不丢数据、不重复执行或伪报通过。
- 同等质量下记录 token、总耗时、等待分位数、重复读取/验证、有效成果与人工介入；不估算未知模型用量，不凭合成速度宣称生产收益。
- 250 在途任务及当前服务器容量实测；无关候选不因全局版本漂移饥饿。高冲突/过载时保留实际限制。
- 最终在 Godot/浏览器真实运行完整范围，接入来源逐项对账，备份/恢复及兼容回退验证；子项通过不能关闭整体目标。

本文件是实施与验收基线，不是已完成报告。原生框架冻结定义不修改；新增平台接入承担 Git 无关映射。
