# Engine Next 输入窗口背压修复

稳定需求 ID 为 `engine-next-input-window-backpressure-20261117`，来源为 M4 联机可视验收及父工单 #1343。

## 已复现问题

交互客户端允许保留 256 个未确认输入，服务端只接受领先已处理序号最多 32 个输入。持续丢弃第一个输入时，客户端在第 512 毫秒发送序号 33，服务端按现有协议以原因 7 拒绝。私有确定性夹具已经复现该边界。镜面联机验收同时观察到原因 7，实际会话中造成序号缺口的具体网络事件尚未记录。

## 修复范围

在共享协议中明确现有的 32 个输入窗口。交互客户端达到窗口时暂停生成新输入，继续接收确认和重传已有输入。释放窗口后恢复生成，保留待消费的短按方向与连续序号。服务端继续使用同一窗口校验。

## 验收

- 第一个输入持续丢失超过 600 毫秒时，客户端发送的最高序号保持在服务端窗口内。
- 丢失结束后，旧输入重传、确认和新输入连续推进，待消费的短按只消费一次。
- 正常预测、非法输入、缺失确认、远端实体限制、重连与排空继续通过。
- 运行受影响的 C++17 无异常测试及完整独立运行时验收，保留原始失败和最终通过证据。

本修复在独立工作树完成。反射分片的冻结生产源码保留原候选身份。
