# Godot 生产任务的原生编辑操作持续授权

稳定需求 ID：`editor-task-authorization-20261112`。父项 [#773](https://github.com/zhzyx/nightmarish-spooky-sorceryze/issues/773)，授权为用户要求 Godot 编辑器连接账号后持续自主生产、验证和修复。当前根宿主承担交付与父级验收，实际实现通过司南派发。

## 问题与范围

场景、资源、运行接口已经存在，但原生写操作始终要求逐次真人确认；现有自动文件/命令开关不代表这些操作的授权。新增由真实用户入口开启、范围清晰、随时可撤销的当前任务授权，使一次确认后的编辑→运行→诊断→修复→再运行能够连续推进。

授权由宿主持有，绑定当前项目、当前 Issue/稳定需求、当前会话与代际。第一版覆盖游戏生产所需场景编辑、资源导入、运行/停止和有界验证输入；模型参数、文本、工具返回或任意 JSON 不能生成、恢复或扩大授权。导出到任意外部目录、编辑器退出和其他敏感动作维持原确认。保留对象/状态快照、未保存冲突、只读咨询和取消边界。

## 验收

- 正常编辑器入口显示任务、项目和授权动作，用户开启后连续场景修改→运行→读出预置错误→修复→再运行，无逐动作弹窗。
- 默认关闭；仅开启自动文件/命令不获得原生编辑授权，模型请求不能修改授权。
- 撤销、停止、切换项目/工单/会话或重启后不复用旧授权；已排队的旧代际操作被拒绝。
- 咨询模式、只读审查、对象/资源状态漂移、未保存冲突继续拒绝；未知/未声明动作保留逐次确认。
- 独立审查、适用单测与原生静默正负例、严格编译、正式 main 交付；最终已连接供应商的组合业务验收归 #773。

本项不接管 #559 原责任者的八类特殊操作，不改变其已交付十五类接口覆盖结论。使用现有 native 编辑操作模块和授权控件边界；回退为关闭本开关并恢复逐次确认，保留会话与回执。

## 原生验收补齐与首次导入修复

补测明确区分首次导入与启动时已扫描的资源。启动后才创建 PNG 的原候选返回 import_failed_or_pending；确认及漂移核对后先注册该文件，再沿同步导入入口执行，严格构建及实际正常工具首次导入通过。另以真实 BoxMesh 内容变化验证 scene_changed_since_confirmation，以真实 CodeEdit 未保存缓冲区验证原生写入拒绝且磁盘/缓冲区不变；输入采样核对强度、时长和释放，冷启动伪造写入仍拒绝。证据及独立审查见 `data-collection/editor-task-authorization-820-first-import.json`，路径基准为仓库根。其来源摘要属于当次验证，之后 run_ai_chat_semantic.py 仅 Ruff 折行规范化，最终组合另行记录。诊断文件测试不代表真实调试器链路，后者由 #845 交付；真实供应商和最终安装仍归 #773。
