# 提交后自动选择渲染编译范围

承接 #739。由现有 push、PR 等仓库事件处理变更集，开发者提交时无需指定模块。修改渲染服务或图形驱动的独立实现文件时，从当前平台真实的 SCons 构建图选择对应对象及其依赖；同一次提交可与已有模块目标组合。覆盖平台独有的后端，纯文档继续跳过引擎。公共接口、生成输入和无法证明局部覆盖的范围回退到平台编辑器构建。发布标签触发完整验证。

验收覆盖真实渲染代码改动、普通模块、混合提交、无关提交、未知输入和编译失败。通过CI事件直接验证自动选择；保留完整产物及其链接/运行验收入口。

## 触发与验收

GitHub [工单 #743](https://github.com/zhzyx/nightmarish-spooky-sorceryze/issues/743) 跟踪本次接入。仅认可当前构建图中存在的对象与模块；缺少对象、探测失败或不完整的基线保守回退到相关平台的编辑器构建。main、PR、普通分支和合并队列均按差异处理。发布标签自动运行完整 Windows 与 macOS 验证；手动完整构建入口仍可用。独立目标自身编译失败会使 CI 失败。

本地在隔离检出依次提交文档、通用渲染实现、BMP、Metal 驱动以及 MetalFX 的混合改动，按真实 Git 提交范围运行生产选择器。macOS arm64 实编确认通用分片选中 instance_uniforms 对象和 BMP 模块，Metal 分片选中后端对象并编译其图中声明的第三方依赖。共享源码内的 Metal 宏和直接引用按变更前后两侧识别，例如 MetalFX 与渲染服务的条件分支。文档提交两侧均跳过 SCons。路由器或相关工作流发生变更时，GitHub 的 Windows 和 macOS 检查会在临时检出重跑该提交序列。
