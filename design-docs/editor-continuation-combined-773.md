# Godot 编辑器生产接续修复

原需求 #773 / `game-production-goal-20261111` 要求编辑器自身支持完整游戏生产。此次交付关联 #896、#899、#903；样例和受控测试只验证对应机制，不代表父项完备。

## 行为与边界

- #896：在实际依赖现状核验时保存请求、响应与 nonce，将原始字节摘要关联至串行启动或并行登记。缓存以编辑器缓存目录为解析基准，每批最多 256 个文件、256 MiB；单条核验最多 32 MiB、派发最多 64 MiB。模型只接收紧凑引用。磁盘材料用于审计，冷启动不能凭它恢复实时授权；缺失、改变或写入失败会阻止下游。
- #899：普通游戏只读审查可以回传未验证诊断，由原父会话接续修复。成功读取的来源字节、HEAD、父委托、权限仍须匹配；回传不授予业务验收。另保留有界的首个来源读取失败，避免先有其他失败、随后窗口滚动时丢失原因。
- #903：只忽略安装器拥有的 `/project/godot/.editor-install-*/`。实际 Restart Manager 观察为多路径瞬时记录，不证明持续占用；原子替换、锁拒绝与回滚逻辑未改变。正式主线规则安装后再删除本次局部 exclude 恢复块。

## 构建与验证

此次扩展已有原生实现、宿主执行器及仓库配置，没有新增模块。Windows MSVC 严格构建实际重编译 `ai_chat_sub_agents.cpp` 并链接编辑器；宿主接口仍为既有派发 JSON 与 Node 入口。回退使用上一已验证二进制及对应执行器，保留原审计文件和用户项目；不将旧磁盘回执当作授权。

完整证据见 [组合验证](../data-collection/editor-continuation-combined-773.json)，分别保留三个工作者的原始输入与结果。最终原生测试 1567 项、435685 条断言通过；并行执行器 66 项通过。并行、串行、存储失败、冷启动整合场景通过。独立审查发现诊断滚动丢失后，旧二进制实际失败，新二进制在 39 条回执后仍保存序号 3 的来源错误，父回传一次、冷启动新增请求为零；撤权仍拒绝回传。

模型和 GitHub 传输在这些机制测试中由受控 fixture 提供。真实提供商、正式安装、原游戏交付分别验收。测试入口参数和批量上限的失败均保留，不以重跑覆盖原记录。
