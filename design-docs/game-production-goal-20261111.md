## 历史局部验收行为

独立生产工单按实际配置容量并发执行，每项使用自己的工作副本和真实执行登记。生产结束触发独立只读审查，宿主核对完整标准、实际读取证据、原生产者终态及当前候选，验收回读一致后由真实事件补位依赖任务。明确失败的外部生产修复使用新执行身份并保留原回执；取消、权限不足、未知或漂移证据不释放依赖。关闭后冷启动保留记录，不使用旧 token 自动重派。

真实 Codex 试运行中，A/B 同时生成 Player/Beacon；三次独立审查完成后，C 自动整合为 BeaconRun，C 启动和父完成通知各一次。独立核查重执行只读审计断言，确认 A/B 重叠 178.625 秒、C 在最后一项上游决策落盘后 9.898 秒启动、三份台账均为 done、九份最终资源和上游四份资源字节一致。真实模型证据绑定 build21；之后三处局部变量改名经独立逆替换检查，不改变逻辑。后续上游 GDScript 修复另经完整套件和正式安装复验，不混用二进制摘要。

## 使用当前入口

使用编辑器中已登录且核验能力的模型/CLI；并行文件生产沿用 [CLI 配置](../tools/godot_parallel/README.md)，设置 `ai_chat/parallel_work_orders_config` 为本机私有配置的绝对路径，按实际账号和机器资源填写容量。配置及凭据留在宿主。

在原父会话给出游戏目标、关联工单和可验证标准，定版工单逐项包含 `验收: ID | 可验证要求`，然后执行“按工单落地”。完成、独立验收、依赖补位和明确失败修复由实际事件接续；需要人决定的内容仍保留给有权人。

演示项目以安装工作区根解析：`project/games/BeaconRun-773-final/project.godot`。方向键移动至 Beacon，获胜后 Enter 重新开始。工程是实际模型链路的原始整合产物，安装版本通过相同实际输入验证。
