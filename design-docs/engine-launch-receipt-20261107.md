# main 验收后自动保持引擎启动版本一致

<!-- gonggong-request:engine-launch-receipt-20261107 -->

来源：用户在当前 Codex 主任务及旁支明确要求自动绑定工单、仓库、隔离候选、编译产物与运行版本，main 交付后后续启动不能默默回到旧源码副本；无需用户填写路径、挑选分支或手工同步。

关联：#390 负责自动候选、运行时、构建清单和重启同源核对；本项负责已验证 main 回执后的稳定启动入口及持久回执。原业务需求 #387 不在本项实现范围。

## 验收

- 使用候选 sidecar 自动取得仓库、工单、候选、可执行文件和项目，核对实际产物 SHA256、已提交的源码输入、真实远端 main 包含关系。
- 未提交、候选未进入 main、产物或源码输入变化时不激活；保留当前有效入口并返回准确 pending/failed 状态。
- 只有同一任务的完整业务验收及真实 main 回执齐备时，原子更新用户级稳定启动入口，指向已验证的产物与项目；不依赖用户指定路径或分支。
- 幂等调用及中断恢复不重复覆盖有效入口；保留上一入口可回退，恢复先重新校验产物和 main。
- 由交付回读事件自动调用，不新增定时扫描，不把 PR 创建、排队或模型口头完成当作已交付。
- 使用隔离 Git 仓库和伪远端验证成功、未合入、未提交源码、产物漂移、源码不匹配、幂等与恢复边界；与 #390 联合做真实候选验收。

## 边界

启动版本固定为“本次已验收并已进入 main 的精确候选”，不是自动追踪 main 的所有后续并发提交。回执分别记录 source_commit、main_commit、main_advanced 和 activation_mode=accepted_candidate；不把两者不同的产物称为最新 main 全树构建。

不改变授权开关、认证或审批。不自动批准 PR，不绕过门禁、CI 或分支保护。不使用模型传入的“已通过”布尔值代替真实验收回执。私有路径与本机回执不进入公共采集事件；公开证据使用摘要。
