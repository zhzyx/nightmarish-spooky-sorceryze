# 与共享模块版本解耦的原生候选接收

需求 ID：native-candidate-intake-20261118。承接 #1444，完整目标 #1382；独立子 Issue #1451 已回读关联父 #1444。路径均相对仓库根。

在 #1444 的真实双生产者试验中，两者完成了普通文件生产，第二个却因 `NativeStore.submit` 的模块 head 漂移被拒收，且没有原生终态。原来的保守读取检查是即时整合入口的保护，不能通过把 reads=None 改成空列表来绕过。

本项新增独立可验收的候选接收能力：把每份变更基于其固定原始输入持久保存为不可变版本和可回读回执，不要求当前模块 head 相同，也不改变任何模块 head、产品发布频道或业务完成状态。现有 submit 的即时合入及未知读取保护保持原义。合契随后整合这些候选，仍需真实检查和独立发布；本项不冒充合契完整集成或 #1444 完成。

## 接口和约束

- 复用 NativeStore 内容对象、模块修订与 compose，新增明确的候选入口和幂等操作命名空间。可抽取共享的纯校验逻辑，避免复制后出现不同路径/完整性约束；原 submit 行为不得悄然改变。
- 可信宿主绑定 tenant、actor、来源/工作者引用和授权；授权回调严格 True、本地短操作，不接受模型自证身份、完整 reads 或批准。新入口暂为可信 Python/CLI 宿主库，HTTP 和 NativeWorker 接线在 #1444 继续。
- 输入保留精确 base、reads（未知仍为 null）、写入对象和依赖；候选的父版本是该固定 base，而非接受时的可变 head。不存在的/跨租户 base、坏摘要、非法路径、对象前缀冲突、未知依赖、循环及越界必须拒绝。
- 多模块批次原子保存，支持有界内部依赖解析；同一输入和操作键重放同一回执，不重复写入；不同输入不能复用键。失败不得残留半个候选或移动共享指针。
- 同模块同基准的不同产物和完全相同产物都可并行接收；每位生产者保留真实独立回执，内容可去重。候选身份及贡献来源不能由文件名、线程数量或文本声称推导。
- 接收不是验收；未知读取候选标明后续必须在最终组合上验证，不给“不冲突”“可发布”或“已交付”虚假证明。必要集成不自动触发生产者重跑。

## 验收

1. 实际多进程和重启：固定旧 base，同时接收同模块不同/相同输出，独立回执可读，重复请求稳定，无关/同模块 head 持续更新不丢候选。
2. head 与发布表在接收前后保持一致；从接收结果 compose/read/物化实际内容成立。失败原子回滚，跨组织、授权拒绝、坏对象/依赖、路径与资源边界反例通过。
3. 现有 NativeStore、EvidenceCache、NativeRelease、NativeWorkspace/检查器回归通过；未知 reads 的原 submit 漂移拒绝继续有效。
4. 真实无 Git CLI/进程入口验证，Windows/Linux 对应范围、输入摘要、独立审查与源码交付。零模型调用仅表明确定性存储验收，不声称 token 或完整生产性能收益。

placement=host_tool，输入为可信宿主参数、原生内容数据库及已验证存储/物化接口；不进入渲染逐帧路径或生成头。回退停用新增候选入口，保留全部既有版本、未整合产物和回执。新增表采用兼容的创建方式，原接口仍可读取既有存储；未经核验不切换有效服务。
