# 归因与修改边界

本模块只提供数据依据。分类基准为实际 Agent 快照（ID、版本、定义指纹、来源），不能仅写“通用 Agent”而丢失目标；生成中 Agent 也使用当时快照，快照登记不代表准入通过。

| 层级 | 允许产物 | 采纳责任 |
| --- | --- | --- |
| feature/project/module/agent | reference 或 proposed optimization，绑定实际子 Agent 与相关工作 | 有效任务授权内由既有责任方实施，沿用奥林匹斯审查、宙斯评价和独立验证 |
| framework/zeus | 仅 proposed reference；可写观察、假设、证据和待验证方向 | 仅用户另行明确指令可以启动相应调整；引用该指令、范围与版本进入原治理链 |
| unknown | 待补证 reference | 不靠分类推断授权 |

冻结 FOUNDATION.md 始终不变。框架／宙斯参考不得绕道标成子 Agent 优化；target 明确 scope、agent_ref，涉及共同治理或框架文件须归 reference。没有用户单独指令，不自动开框架修改任务、不修改宙斯准则、不将参考注入共同指令。单独指令也不由赫尔墨斯代为签发。

优先在目标 Agent、项目配置、工具及模块内解释症状。仅有跨 Agent 关联、交接或通讯证据时，才可能涉及框架；跨 Agent 数据本身不能证明框架根因。多个用户反馈同一 Agent，不自动变成框架问题。保留关联为“已确认／可能／未知”，未证实的关联可检索但不作为因果事实。

子 Agent 候选写清目标快照、需求和步骤、独立事件去重、错误／纠正与质量返工链、消耗及覆盖、反例和替代解释、最小改动、对照指标、验证责任与回退。不得只减少轮次或 token 而损害理解、必要确认或质量。框架／宙斯参考可以保留相同证据，但没有执行动作和自动采纳状态。

历史记录保存原快照，版本升级用映射查询，不能反写旧归因。改进成效依实际结果回链既有主记录，采纳与验证状态仍取自原责任系统。

共工可按框架根 sync/POLICY.md 只读使用赫尔墨斯数据优化；用户已持续授权有效共工更新的完整同步。此前“单独指令”要求仍适用于自行提出和实施框架修改，不阻断已批准上游同步。数据读取工具为 sync/read_hermes.py，历史快照不改写。

用户明确豁免：无数据库时使用独立 extensions/hermes-files 模块，在目标 Git 仓库的 olympus-hermes-data 记录需求产出并随需求合入。该模块和数据不受共工同步覆盖；赫尔墨斯与共工使用同一文件分析入口。尚无目标仓库时只交付规则与工具，不创建生产数据。文件状态不冒充 SQLite 回执。
