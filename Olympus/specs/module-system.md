# 奥林匹斯模块系统规范

版本：0.2。性质：专项规范草案。加载条件：评估、开发或组合生产模块时。

按需参考依赖：GOVERNANCE.md。仅加载与当前职责有关的部分；不要求每个执行任务读取全部依赖。

## 模块划分与产品组合

模块表达可复用能力；工作流表达能力如何组合；Agent 表达当前由谁执行。三者独立配置。设计、生产、质量是工作主线，不是必须常驻的部门，也不要求每个任务走完所有环节。

设计主线将意图转为可执行规格，并记录假设、候选与取舍。

| 模块 | 核心范围 | 主要交付 |
| --- | --- | --- |
| 产品与体验定义 | 目标玩家、核心幻想、体验目标、范围 | 项目纲领、目标与验收方向 |
| 玩法与系统设计 | 核心循环、战斗、成长、经济、行为规则 | 系统规格、状态关系、参数和边界 |
| 关卡与世界设计 | 空间、路径、遭遇、引导、节奏 | 关卡意图、布局约束、事件要求 |
| 美术设计 | 风格、形体、色彩、材质、角色与环境语言 | 风格规范、参考、资产规格 |
| 叙事设计 | 世界观、角色、任务、对白和分支 | 叙事结构、任务状态、文本规格 |
| 电影化设计 | 调度、分镜、镜头、剪辑及玩法衔接 | 分镜、镜头规则、演出规格 |
| 操控与交互设计 | 输入、移动、反馈、镜头和可读性 | 操作规格、交互原型、反馈要求 |
| UI 与无障碍设计 | 信息架构、HUD、流程、适配 | 组件规范、界面状态与可用性要求 |
| 音频设计 | 音乐、音效、语音、空间声和混音 | 声音规范、事件与优先级 |
| 技术设计 | 组件、接口、数据、性能、平台、联网边界 | 实现约束、接口契约和运行预算 |

生产主线把规格转为可编辑内容，并完成加工、装配和集成。

| 模块 | 核心范围 | 进入项目的完成条件 |
| --- | --- | --- |
| 2D 资产生产 | 图像、贴图、图集、精灵和图标 | 源文件与运行资源完整，尺寸及引用正确 |
| 3D 资产生产 | 网格、UV、材质、LOD、碰撞与绑定 | 尺度、拓扑、骨架、性能及导入符合规格 |
| 动画生产 | 动作、重定向、混合、IK、表情 | 状态切换、事件和玩法时序正确 |
| 特效与技术美术 | 粒子、Shader、轨迹、天气和破坏 | 挂点、时序、可读性及预算通过 |
| 关卡与场景生产 | 灰盒、地形、拼装、布景、光照与导航 | 空间可用，路径、事件与玩法衔接正确 |
| 导演与演出生产 | 镜头、时间线、表演、口型与过场 | 触发、跳过、中断与恢复符合要求 |
| 代码生产 | 模块、接口、工具、读写与工程集成 | 通过适用检查和测试，形成可审阅变更 |
| 玩法逻辑生产 | 技能、任务、状态机、行为树和事件 | 规则、状态转换及边界符合设计 |
| UI 生产 | 组件、布局、动效、数据和输入绑定 | 状态、操作、分辨率及本地化适配正确 |
| 音频生产 | 音乐、音效、语音及运行事件绑定 | 触发、循环、混音及资源预算正确 |
| 数据与平衡生产 | 配置、掉落、成长、经济和难度 | 数据合法，影响可追踪并通过仿真或试玩 |
| 构建与交付 | 本地化、平台配置、打包和交付清单 | 对应版本可运行，资源和证据完整 |

质量主线包括规格检查、生产过程检查、资产检查、工程检查、玩法回归、场景验证、体验评估及交付验收。它既提供独立模块，也可以接入客户现有验证服务。

平台底座包括企业与项目配置、知识与实体关系、能力注册、任务调度、资产与配方、版本协同、模型工具路由、质量证据、成本资源、权限隔离和能力评测。客户可以不启用某个专业模块，但平台必须保留相应的输入与验收责任。例如，客户可自己提供资产规格和质量报告。

支持三种交付方式：在引擎内完整使用；将独立能力接入客户现有管线；与客户工具混合编排。引擎适配器是执行游戏工程操作时的依赖，纯资产加工或独立文档任务不必启动引擎。

## 模块契约与配置边界

模块内的生产、skill 与 Agent 创建及变更须执行 specs/governance-review.md 的强制回查。新入口保持精简，外部 Agent 合入分别取得框架审查与宙斯评价结论；缺少证据或纳管状态不完整不得启用。

每个现有及未来子业务模块必须继承宙斯统一纳管约束与冻结纲领 1.0。模块契约须声明其 Agent 的登记与派生规则、治理关系、授权来源和撤销方式；外部 Agent 也必须通过纳管后接入。客户裁剪、替换工具、私有化部署或引擎迁移不得关闭该约束。缺少纳管声明、试图脱管或要求改写纲领的模块，不得通过准入。后续业务能力进入新模块或专项规范，不修改基础纲领。

每个模块注册时声明：标识与版本、输入输出结构、必需依赖、可选增强、可替代外部能力、读写对象、权限、预算、运行环境、取消与恢复方式、验收规则、兼容范围和负责人。依赖约束与商业套餐分别管理。

模块输出包括产物本体、源文件或可编辑参数、生产配方、版本来源、依赖、证据和待处理问题。生成失败可以改用模板、程序化工具、已有资产或人工制作，替换路径必须保持交付要求。

模块组合规则区分五类：必需依赖缺失则不能执行；可选增强缺失则按声明降级；外部能力可以通过契约替代；互斥能力不能同时生效；版本不兼容需转换或调整。降级行为需可见，不能暗中降低客户的质量承诺。

配置按平台、企业、项目、工作流和任务分层继承。下层可以在授权内细化约束，不能覆盖上层的权限和根本边界。配置记录来源、生效版本、兼容检查及恢复点；在途任务固定所用版本，变更后明确继续、重验或取消策略。
