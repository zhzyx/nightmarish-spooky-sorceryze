# 数据与反馈模块

赫尔墨斯 hermes 为独立数据 Agent，当前版本以 framework-manifest.json 及 agents/hermes/agent.json 为准，五项 skill 按需加载。采集对象含授权外部反馈和需求执行事件，以实际 Agent／版本快照及关联工作分类。每个需求记录发起时间、对话消息／轮次、方向错误／纠正、质量问题／返工、步骤与 token／等价用量；缺失明确标注，不能补零。

入口 agents/hermes/AGENT.md；记录契约 references/data-contract.md，采集及统计口径 references/telemetry.md，边界 references/optimization.md，接入与迁移 references/storage.md，均相对 Agent 目录。

奥林匹斯和宙斯内容只保留 reference。必须用户另行明确指令才进入原治理变更流程，赫尔墨斯无框架和宙斯修改权，冻结纲领不变。其他子 Agent 的优化候选按既有授权与审查执行，数据不产生权限。只有跨 Agent／关联通讯才可能涉及框架，不因一般反馈自动升级。

客户配置复用来源、权威数据服务、Agent 清单、分类、权限与保留策略。宿主按租户及来源分区，事务成功再确认游标，失败入待处理队列，重试幂等。源端账单／事件计数与落库结果对账；记录采集完整度，不承诺无数据丢失的虚假完整。

赫尔墨斯拥有记录与分析，雅典娜拥有设计，业务方拥有实现，验证者拥有质量结论，忒弥斯拥有升级监察，宿主拥有身份和状态。问题／返工只引用原质量主记录，不建第二套质量关卡。

本地 SQLite 验证可用，企业连接器、身份隔离、删除／保留、备份恢复和容量仍需部署验收。主键、外键、字段约束、结构化索引、版本化标签、证据溯源及可重算统计是交付要求；“永远可用”落实为受权限和保留政策约束的可追溯性及恢复验证，不以文档承诺无限留存。

共工可按框架根 sync/POLICY.md 只读使用赫尔墨斯数据优化；用户已持续授权有效共工更新的完整同步。此前“单独指令”要求仍适用于自行提出和实施框架修改，不阻断已批准上游同步。数据读取工具为 sync/read_hermes.py，历史快照不改写。

用户明确豁免：无数据库时使用独立 extensions/hermes-files 模块，在目标 Git 仓库的 olympus-hermes-data 记录需求产出并随需求合入。该模块和数据不受共工同步覆盖；赫尔墨斯与共工使用同一文件分析入口。尚无目标仓库时只交付规则与工具，不创建生产数据。文件状态不冒充 SQLite 回执。
