# 奥林匹斯项目状态与记录规范

版本：0.2。性质：专项规范草案。加载条件：实现状态、工单、证据和上下文恢复时。

按需参考依赖：GOVERNANCE.md。仅加载与当前职责有关的部分；不要求每个执行任务读取全部依赖。

## 项目共同状态与生产记录

项目以稳定实体 ID 组织角色、技能、任务、场景、镜头、界面、资产和接口。引擎对象路径只是映射，不能成为唯一身份。

| 记录 | 保存的关键内容 |
| --- | --- |
| 意图与规格 | 用户原话、解释、假设、确认状态、版本和验收条件 |
| 方案与配置 | 启用能力、工具、权限、预算和适用规则 |
| Feature 主工单 | 目标、唯一主要负责人、协作职责、状态及整体验收 |
| 执行任务 | 输入、依赖、读写范围、委托、产物与证据 |
| 变更集 | 基准版本、修改、依赖版本、验证与合入结果 |
| 资产履历 | 源文件、配方、模型工具版本、来源和衍生关系 |
| 验证证据 | 目标版本、环境、测试方法、结果和适用范围 |
| 方法与决策 | 取舍依据、适用范围、生效版本和恢复方式 |

奥林匹斯以事件账本和版本化产物保存生产事实。外部版本库仍负责代码与资产版本；奥林匹斯记录提交、对象和工单之间的映射。文档内工单进度、仪表盘和外部工单是同一事实的视图，通过连接器同步，不各自维护互相矛盾的完成状态。

同步采用来源标识、事件 ID 和版本检查防止循环与重复。外部系统更新时先确定该字段的权威来源，再更新对应记录。断网允许暂存待同步事件；恢复后检查顺序和冲突，不能把本地暂存宣称为远端已完成。

Feature 为用户可理解的工作单元，阶段任务作为子项。进度展示已验收项、阻碍、负责人和下一步；没有可靠工作量估算时，子项比例不显示为工时完成率。已有雅典娜可以作为 Feature 设计与追踪能力的候选接入，通过契约验证后使用，不在本版默认为已经完成运行集成。

上下文按任务加载相关意图、实体、依赖和最近变化。长任务保存结构化检查点，保留授权、基准版本、未决问题和证据引用；恢复时重新检查有效性。压缩摘要不能替代原始记录，也不能把暂时偏好沉淀为永久用户属性。
