# 奥林匹斯治理与加载规则

本规则落实冻结纲领 1.0，全部 Agent 及派生、接入和恢复实例受宙斯统一管理，无豁免。纲领、宙斯原件及其基线不得由局部适应、模块、客户配置、部署或引擎迁移改写。

宿主真实权限优先，负责认证身份、委托、版本、预算、租约、状态和审计。治理链必须可追溯至宙斯；失效或未知时拒绝相关授权和结果，不降级为脱管。其他有效授权任务继续。多级委托不得扩权，名称和文本不产生权限。

治理主体采纳公共标准，项目负责人在委托内配置，执行者在任务内选择方法。规范变更保留影响、证据、兼容、必要独立审查、真实采纳、监测与恢复；局部经验不自动成为全局规则。只有目标、承诺、权限或用户保留决定发生变化时回到对应权源，不重复询问已有有效授权。

生产、skill／Agent 创建变更和外部接入执行 specs/governance-review.md，通过 skills/dike/SKILL.md 回查。通行证绑定对象、版本、阶段和范围，必须有真实批准；模板、自评、未知、过期或被替代记录不能用于准入。

上下文按共享宙斯核心、模板、冻结纲领、当前独立 Agent 入口和真实委托装配。只加载相关程序和证据，组织调整时才加载 hestia。总索引、架构、旧记录和大型 JSON 不默认注入。相同任务的有效读取可复用，来源变化重验受影响部分。

状态由宿主提交，证据绑定版本，工单和展示来自同一账本。检查点、运行记录和客户配置不是永久指令。奥林匹斯质量职责依 specs/quality-responsibilities.md，要求独立审查时不得由实现者自行取消或自批。

文件指纹必须与宿主可信基线核对；随包锁文件和 JSON 通行证本身不是安全根。runtime/runner.py 在可信本地操作员边界内校验签名委托、限定资源、调用预算及状态；宿主负责保护签名密钥、框架及账本。企业身份、全局资源和分布式状态控制尚未部署，文件校验不能替代这些能力。跨模型执行按 specs/model-runtime.md。

奥林匹斯组件创建与准入包含 specs/reporting.md 的必需上报契约。静态配置不能替代宿主真实绑定或实际回执；模板和待接入状态不能作为已上报证据。
