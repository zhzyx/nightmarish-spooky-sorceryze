# 宙斯 · Zeus

**宙斯智能体体系 · v0.4.1**

> 守其本，因事变，成其用。

元，是生成的根本；衡，是处境中的判断。

## 六项原则

因人定目的，理解可修正。循证察实效，未知仍为未知。复用已有能力，组织服务整体。权责相称，解释不生授权。因实践而变，随实效而存废。方法可变，承诺与根本约束不得暗改。

这里把“表意”作为设计方向：表达目的、关系和判断尺度，避免枚举岗位与动作。“表象”未作为严格语言学分类；不据此断言某种自然语言先天更优。抽象原则仍需在具体任务中落实为结果和证据。

## 使用

项目标识为 `zeus`；Agent定义为 `agents/zeus.md`；按需技能为 `hestia`。本次为命名更新，消息协议仍为0.2，与包版本独立。

运行 `python tools/context.py` 获得默认指令。确需调整分工或沉淀方法时使用 `python tools/context.py --organize`。没有固定部门名单。一个Agent模板可以实例化多个承担不同任务的Agent，实例化仍遵守宿主的派生权限。

临时职能按问题产生，明确结果、权限、交接及负责人；协作可以扩大，完成后可以撤销。需要独立审查的工作保留职责分离，不能因为采用一个模板就自行验收。公共标准仍由真正获得委托的治理职能负责，局部不自行创造通信制度。

用户适应发生在任务理解、表达方式和做事方法上。暂时偏好保持暂时性；有实际效果证据的方法才沉淀为可复用能力，并保留适用范围。核心约束不允许Agent靠一次反馈自行重写。

内部指令采用英语，内部消息固定JSON，用户交流遵循用户语言。可选的contracts/message.schema.json及tools/check_message.py沿用已有严格消息校验，仅在程序侧使用；依赖见requirements-optional.txt。它们不默认进入模型上下文。

实际身份、授权、费用和状态控制由宿主提供。该包没有实现自训练模型、持久用户画像或自动扩权。当前验证覆盖指令装配与格式，尚未证明开放任务上的自适应效果。

## 与v0.3相比

将固定的四类角色替换为一个可实例化模板；将常驻岗位规定收束为六项原则；保留一个按需组织方法。旧版的权责、独立审查和公共标准责任仍然保留。实验与多编码方案不进入本生产包。
