# 共工上游同步与赫尔墨斯数据共享

## 当前主线内已登记模块

当前司南 0.4.0 已包含在共工主线，奥林匹斯名称为阿里阿德涅 Ariadne。全量复制已登记的模块契约、skill、实现和运行空配置；不从历史 archive 复活定时调度、旧授权或旧注册源。历史双来源的 0.2/0.3 分发不再是当前重建来源。来源批准仍只证明原对象，不充当名称映射后候选的批准。

每次更新核验读取当前主线及模块的绑定文件、原批准与独立证据。框架内引用相对 framework 根，../work 下的审查原件限定在同一 Gonggong 工作区根内，索引用 source-package 命名空间保留相对路径与原始摘要。批准中已声明的能力限制仍保留在原件，不将局部定义批准解释为全局监听或宿主授权。

## 用户新增的独立豁免（优先适用）

`extensions/hermes-files/` 为奥林匹斯独立文件数据模块，目标 Git 仓库根 `olympus-hermes-data/` 为专用需求产出目录。模块和数据均不得被共工同步覆盖。文件模式不需要数据库，共工和赫尔墨斯直接使用该模块的同一分析入口读取。此项是用户对“不得偏差”的明确局部豁免，其余共同框架仍全量同步。

同步重建必须逐字节携带现有豁免模块；上游占用其路径则拒绝重建，不能替换。本地数据始终在框架包之外，不纳入源框架复制、清理或重命名。豁免模块独立版本化，文件格式、事件摘要、Git 合入检查仍须验证。待合入确定的目标 Git 仓库后再初始化数据目录；当前只交付规则与工具。详见 [文件数据源规则](../extensions/hermes-files/README.md)。

本规则依据用户明确要求：赫尔墨斯数据可由共工读取用于优化；共工优化后，奥林匹斯必须同步所有框架更改并全量核验，不得存在框架偏差。

## 单一上游

共工是框架行为、治理、Agent、skill、契约及工具的唯一上游。奥林匹斯保留西方神话名称，仅允许确定性的名称映射、此目录中的同步/数据读取接入、重新计算的指纹及真实的待审记录。不得选择性挑取更新、遗漏新增或删除文件、保留本地业务分叉，或将名称以外的功能差异解释为品牌差异。版本号相同也必须按全部文件内容核验。

共工调整仍由共工原治理链决定；本指令持续授权奥林匹斯跟随有效上游的完整同步，并不授予赫尔墨斯自行修改共工或宙斯的权限。同步共工已批准的纲领更新属于用户授权的上游同步，不属于奥林匹斯自行修改纲领。历史身份、证据和批准不改写；原批准不能充当副本新指纹的批准。

## 同步流程与阻断

1. 跟踪共工 `CURRENT_FRAMEWORK.json`，也可显式指定已批准的上游根目录。全量读取文件，包括审查来源；拒绝链接目录与无法读取的文件。仅忽略 `.git`、`__pycache__`、`.pyc` 运行缓存。
2. 在全新目录重建完整副本；新增、修改、删除通过重新生成全部文件集合同步。根据名称映射重新生成依赖指纹、冻结指纹及候选摘要。不将共工整包纳入交付；源审查原件保留在真实上游，分发包记录原始逐文件摘要索引，不伪造副本批准。
3. 执行 `check` 逐文件核对确定性转换结果、完整文件集合及源指纹，执行框架候选校验、代码语法检查与质量归属检查。适用的行为验证及新依赖迁移仍需按上游变更安排；这些静态检查不能替代生产验收。
4. 核验或独立准入未通过，不启用新版本。部署宿主在全量核验和准入后切换，保存旧包及数据恢复点。数据库/队列在框架目录之外保存，不随重建覆盖或自动迁移。
5. 运行校验与更新核验分离：验证工具及 Agent 上下文入口校验包内 runtime-lock.json 的完整文件集合，再核对候选指纹、准入及宿主权限；不读取外部共工位置。上游发布事件触发新目录完整重建和独立准入，不直接使已安装版本失效。离线启动不声称核对了上游最新状态。

```powershell
python sync/gonggong_sync.py build --source PATH/TO/CURRENT_FRAMEWORK.json --out PATH/TO/NEW-OLYMPUS
python sync/gonggong_sync.py check --root PATH/TO/OLYMPUS
python tools/verify_framework.py --candidate
```

`sync/binding.json` 保存相对框架根的源位置（`path_base: olympus_framework_root`）；执行更新核验时使用 `GONGGONG_FRAMEWORK_SOURCE` 指定实际源指针。Node 上下文入口可通过 `OLYMPUS_PYTHON` 指定 Python。源位置是接入配置，不是同步证据。更新时源不可用则阻断更新；本地完整包运行不依赖源位置。当前交付包含同步命令和入口检查，没有常驻监听器或远程发布服务；宿主必须将上游发布事件接入 build→全量验证→准入→切换流程。

## 共工读取赫尔墨斯

共工可通过 `read_hermes.py` 以 SQLite 只读连接读取已获访问权限的赫尔墨斯 v2 台账，用于优化分析。必须指定租户；保留原始文档、来源、历史版本、证据关系、Agent ID、定义指纹及记录摘要。名称对应关系仅供查询解释，不反写历史归属，不把源系统不同的记录按裸 ID 合并。原始敏感数据仍受实际租户/来源访问、保留和删除权限约束，命令行租户过滤不等于身份认证。

```powershell
python sync/read_hermes.py --db PATH/TO/HERMES.sqlite --tenant TENANT --out PATH/TO/NEW-EXPORT.json
```

读取失败、数据缺失、覆盖未知须保留事实，不能补零或宣称完整。导出保留同一事务快照及全部该租户记录和证据关系，供共工读取，不能直接当作共工自身运行事件导入或覆盖。优化建议进入共工原治理链；有效上游采纳之后，奥林匹斯完整跟随。当前没有指定真实数据源，因此不声称已读取生产数据。

## 2026-11-02 用户明确的交付范围与可移植路径

本仓库交付 Olympus 和 Godot，不交付整套 Gonggong。source-evidence.json 是确定性来源摘要索引，不是批准原件、签名或离线快照；它纳入候选指纹。原件不改写，保留在实际共工来源，更新核验时重新检查有效源批准、完整文件集合与摘要，缺源、变更、撤销均拒绝更新。旧源 ZIP 从当前交付树移除，既有 Git 历史不重写。

交付文件使用相对路径且声明解析基准。历史出处以相对来源标识保留，未随包分发的历史参考明确标注为非运行依赖。运行时解析的绝对位置不写入 Git。源司南宿主配置、旧调度授权和旧写入范围不迁移；分发调度配置默认禁用，必须由当前宿主重新绑定。路径与证据存储适配不得被解释为批准新 Agent。

## 待审来源的隔离候选准备

`prepare --source ... --out ...` 仅在新目录准备未启用候选，要求源候选完整性及当前模块已批准范围的文件/证据验证。结果明确记录 `source_admission_verified: false`；原始来源验证错误不变成通过。此命令用于当前上游的路径迁移尚待 Agent 新准入时完成可审查的 Olympus 交付，不批准生产。

`verify_framework.py --candidate` 检查本地完整性；正式验证及上下文入口继续检查本地候选准入。`build`、`check` 保留正式上游核验，`prepare` 只生成未批准候选。runtime-lock.json 由完整重建确定性生成并纳入每个 Agent 候选指纹；它不是签名或批准。生产必须满足 Olympus 精确候选独立准入、真实宿主授权和事件回执。

本地正式 Agent 准入采用受限覆盖：只有清单指定的 admission_pass 和其明确引用的 reviews/local-admission/ 证据允许区别于生成的待审记录；运行准入及更新核验仍调用共享 admission.mjs 验证主体、完整候选摘要、基线、独立审查、真实批准引用、有效期和撤销状态。其他文件在运行时按本地清单核对、更新时按源确定性逐字核对，证据目录的未引用额外文件也拒绝。该机制不自动批准、不改写待审记录，也不能绕过更新时正式源准入。
